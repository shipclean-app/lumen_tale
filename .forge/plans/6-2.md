## 1. Résumé de la slice

`6-2` ajoute à `browse-catalogue.md` le **mode résultats** : un champ de requête, une liste
qui remplace le catalogue, et une pagination qui répète les mêmes mots avec l'offset du site.

La slice est petite, et sa petite taille est le point : **presque toute sa conception est déjà
faite**. `browse-catalogue.md` § 1.1 dit *« one route, two modes »* ; § 5 dit ce que le champ
envoie ; § 4 dit ce qui se passe quand la recherche ne rend rien. Ce qui reste à faire est
d'en **écrire le code** — et de décider, d'abord, s'il y a quelque chose à écrire.

Une règle domine toutes les autres, et elle n'est pas une règle d'interface :

> **B41** — *« Searching inside a site searches whatever that site searches. The app does not
> split a query into title, author and description, nor decide which of those a site matches;
> it passes the reader's words to the site. »*

Le mot qui compte est *« whatever that site searches »*. Un lecteur qui écrit `mother of
learning zorian` doit voir **exactement** ce que le site verrait de ces mots. Ni découpage, ni
normalisation, ni ré-écriture, ni tri de pertinence côté app. Et la **pagination** d'une
recherche est *« More results from Royal Road »*, pas *« Page 2 »*, parce qu'un jeu de résultats
n'a pas de pages dont le lecteur a raisonné.

**User stories couvertes** : US-02 (recherche dans un site — conditionnelle), US-01
**Règles métier couvertes** : B41, B50
**Edge cases couverts** : E5, E8, E19

## 2. Contrats de données (code)

> **Aucun changement de schéma.** Une recherche ne lit rien en base et n'y écrit rien. Les
> résultats vivent le temps de l'écran.

### 2.1 Schémas de validation

**Aucun.** Ni table, ni colonne, ni migration, ni `shared_preferences`. Une recherche est un
**paramètre d'URL** et un appel réseau — la seule forme de donnée qu'elle manipule est le
`String` que le lecteur a tapé.

### 2.2 Types et interfaces

```dart
// lib/features/browse/domain/search_query.dart
import 'package:lumen_tale/domain/sources/browse_outcome.dart';

/// Ce que l'écran envoie, et **rien de plus**.
///
/// B41 est une règle sur **ce qui ne se passe pas** : cette classe n'a aucune
/// méthode de normalisation, de découpage, de mise en minuscules ni de
/// nettoyage. Un `trim()` ici serait déjà une violation, parce qu'il change
/// les mots que le lecteur a tapés. Le seul traitement est l'**encodage
/// d'URL**, fait par dio, et le `String` lui-même est transmis **byte pour
/// byte**.
///
/// ⚠️ La conséquence mesurable : `query == screenText` est une assertion, et
/// elle est testable sans réseau.
final class SearchQuery {
  const SearchQuery({required this.sourceId, required this.words});

  final String sourceId;

  /// Les mots du lecteur, **inchangés**. Jamais coupé en champs, jamais
  /// re-casé, jamais joint à un genre.
  final String words;

  bool get isBlank => words.trim().isEmpty;
}

/// Les trois issues d'une recherche, dans le type.
///
/// Le troisième est la contrepartie obligatoire de `BrowseEmpty` : B50 dit
/// qu'une source qui **déclare** la recherche et ne rend rien est **un site
/// cassé**, jamais « aucun résultat ». Sans ce troisième état, l'écran
/// devrait choisir entre deux mensonges, et il en choisirait un.
sealed class SearchResults {
  const SearchResults();
}

/// La page a été lue et porte des lignes.
final class SearchResultsFound extends SearchResults {
  const SearchResultsFound({
    required this.novels,
    required this.hasNextPage,
    required this.page,
  });

  final List<Novel> novels;
  final bool hasNextPage;

  /// Le n° que le lecteur **ne voit pas**. `browse-catalogue.md` § 5 : le
  /// lecteur voit *More results from Royal Road*, jamais *Page 2*.
  final int page;
}

/// La recherche est bien formée, le site a répondu, et **le site dit** qu'il
/// n'y a rien.
final class SearchResultsNothing extends SearchResults {
  const SearchResultsNothing({required this.siteSignal});

  final String siteSignal;
}

/// ⚠️ **La source déclarait `supportsSearch == true` et n'a rien rendu
/// d'exploitable.** C'est `BrowseFailed` de la source, présentée par
/// l'interface comme une **source cassée** avec un réessai — jamais comme
/// « aucun résultat ».
final class SearchResultsUnusable extends SearchResults {
  const SearchResultsUnusable(this.reason);

  final SourceFailure reason;
}
```

```dart
// lib/features/browse/providers/search_controller.dart
import 'package:lumen_tale/domain/sources/source.dart';

/// Traduit une recherche en appel de source, **et rien d'autre**.
///
/// Cette classe existe pour que la règle B41 soit vérifiable en un seul
/// endroit : il n'y a **qu'un seul** appel à `searchNovels` dans toute la base
/// de code, et il est ici, avec `query.words` passé tel quel.
abstract interface class SearchController {
  Future<SearchResults> run(SearchQuery query);
}

/// L'implémentation. ⚠️ `filters` est **toujours vide**.
class SourceSearchController implements SearchController {
  const SourceSearchController({required this.resolveSource});

  /// `SourceManager` résout par id. Une source inconnue est un
  /// `SourceUnavailable`, pas une liste vide.
  final Source Function(String id) resolveSource;

  @override
  Future<SearchResults> run(SearchQuery query) async {
    final source = resolveSource(query.sourceId);

    // ⚠️ B41 : aucun filtre n'est attaché à une recherche. Le genre est un
    // filtre du **catalogue** ; l'ajouter ici ferait dire à l'app ce que la
    // requête signifie, ce qu'elle n'a pas le droit de décider.
    final BrowseOutcome<NovelsPage> outcome =
        await source.searchNovels(1, query.words, const FilterList([]));

    return switch (outcome) {
      // ── 1. Le site a rendu des lignes ────────────────────────────────────
      BrowseSucceeded(:final value) when value.novels.isNotEmpty =>
        SearchResultsFound(
          novels: value.novels,
          hasNextPage: value.hasNextPage,
          page: 1,
        ),

      // ── 2. 200, zéro ligne, ET le signal du site ────────────────────────
      BrowseSucceeded() =>
        // ⚠️ **Impossible** à ce niveau, et c'est le but. Une source ne doit
        // JAMAIS produire `BrowseSucceeded` avec zéro novel : elle produirait
        // alors un « aucun résultat » pour une page cassée — exactement le
        // bug que B22 interdit (6-1 § 7).
        //
        // Ce n'est donc pas un garde-fou défensif, c'est un **défaut de
        // source**, et il se lève comme tel. `13-error-handling.md` règle 1
        // interdit `Exception`, `Error` et `StateError` nus : c'est un
        // `SourceException`, avec le nom de la source dedans.
        throw SourceException(
          'searchNovels on a source with supportsSearch == true returned '
          'BrowseSucceeded with no novels — it must use BrowseEmpty or '
          'BrowseFailed instead',
        ),

      // ── 3. Le site dit qu'il n'y a rien ─────────────────────────────────
      BrowseEmpty(:final siteSuppliedSignal) =>
        SearchResultsNothing(siteSignal: siteSuppliedSignal ?? ''),

      // ── 4. La source a déclaré la recherche et n'a rien rendu ───────────
      BrowseFailed(:final reason) => SearchResultsUnusable(reason),
    };
  }
}
```

```dart
// lib/features/browse/widgets/search_field_row.dart
import 'package:flutter/material.dart';
import 'package:lumen_tale/app/router/app_routes.dart';

/// Le champ, et **seulement** le champ.
///
/// Il est posé **au-dessus de la liste**, collant au défilement
/// (`browse-catalogue.md` § 1.1 : *« rendered at the top of the content area,
/// above the list, sticky while the list scrolls »*), et il est **utilisable
/// pendant que la liste charge** : la requête est l'entrée du lecteur, et la
/// bloquer derrière le réseau serait à l'envers.
class SearchFieldRow extends StatefulWidget {
  const SearchFieldRow({
    required this.sourceId,
    required this.initialWords,
    required this.enabled,
    super.key,
  });

  final String sourceId;

  /// Les mots de la requête courante, re-posés après une erreur. **Jamais
  /// effacés** : un lecteur qui retape mot à mot une requête de 40
  /// caractères pour une erreur réseau est un lecteur qu'on a puni.
  final String initialWords;

  /// `false` hors ligne. Le champ reste **présent et lisible** ; c'est le
  /// rendu du résultat qui change.
  final bool enabled;

  @override
  State<SearchFieldRow> createState() => _SearchFieldRowState();
}

class _SearchFieldRowState extends State<SearchFieldRow> {
  late final TextEditingController _controller =
      TextEditingController(text: widget.initialWords);

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  void _submit() {
    // B41 : `_controller.text` est transmis tel quel. Pas de `trim()`,
    // pas de `toLowerCase()`, pas de découpe sur des espaces.
    context.go(AppRoutes.searchResults(widget.sourceId, _controller.text));
  }

  @override
  Widget build(BuildContext context) {
    return TextField(
      controller: _controller,
      // design-system.md § 2.4 : placeholder jamais vide, un vrai exemple.
      enabled: widget.enabled,
      textInputAction: TextInputAction.search,
      onSubmitted: (_) => _submit(),
      // 56dp de haut, `--color-border-field`, 2dp `--color-border-focus`
      // à l'état `focused`. Jamais d'état `error` — voir § 3.3.
    );
  }
}
```

## 3. Algorithmes critiques

### 3.1 Le rendu du champ, qui est une décision et pas un `if` (couvre **B50**)

```
build(sourceId):
  if (source.supportsSearch == false):
      # ⚠️ Le champ N'EST PAS RENDU. Pas « rendu et désactivé ».
      # Une zone de texte désactivée est une promesse à propos d'une version
      # qui n'existe pas, et elle occupe une ligne sur l'écran le plus
      # comparative de l'app.
      #
      # C'est `browse-genre.md` qui porte la phrase qui explique pourquoi :
      # `EmptyState` « search-unsupported » (design-system.md § 2.7),
      # qui explique que ce site n'a pas de recherche et propose les genres.
      render(genreGrid)          # le mode catalogue, tel quel
      return

  render(
    SearchFieldRow(sourceId: sourceId, initialWords: q ?? '', enabled: hasConnection),
    NovelList(results),
  )
```

**Les deux issues :**

| Situation | Ce qui est rendu |
|---|---|
| `supportsSearch == false` | **aucun champ**, la grille de genres. `browse-genre.md` porte l'explication |
| `supportsSearch == true` | champ collant en haut + liste |

**Le test qui le prouve** est un `find` sur le widget, pas un `if` à lire : avec FanMTL
(`supportsSearch == false`), `find.byType(SearchFieldRow)` renvoie **zéro**. C'est
l'assertion la moins ambiguë de la slice.

### 3.2 Soumettre — B41 rendu mécanique (couvre **B41**)

```
onSubmitted(text):
  # ⚠️ Le texte du lecteur, byte pour byte.
  go('/browse/<sourceId>/genre/search?q=<texte encodé>')

  # Ce qui n'est PAS fait, et qui est toute la règle :
  #   ✗ text.trim()                 — « mother  of » ≠ « mother of »
  #   ✗ text.toLowerCase()          — le site peut être sensible à la casse
  #   ✗ text.split(' ')             — B41 interdit le découpage en champs
  #   ✗ ajouter le genre au scope   — ce serait l'app qui décide du sens
  #   ✗ composer une requête de pertinence
  #   ✗ mettre en cache les résultats
  #   ✗ afficher un Toast « 12 résultats » — le lecteur les a sous les yeux
```

**La page suivante** est la seule autre chose qui se passe :

```
scrollToEnd():
  # « More results from Royal Road », jamais « Page 2 ».
  # La requête est **ré-envoyée** avec l'offset du site : c'est la
  # pagination d'une recherche, pas un défilement infini
  # (`15-performance.md` §Lists : « no unbounded scroll auto-loading »).
  run(SearchQuery(sourceId, same words), page: current + 1)
```

### 3.3 Quatre échecs, quatre rendus qui ne se ressemblent pas (couvre **B50**, **E5**, **E8**, **E19**, **B22**)

| Issue | Type produit | Rendu | Pourquoi distinct |
|---|---|---|---|
| **La recherche est bien formée, et le site dit qu'il n'y a rien** | `SearchResultsNothing` | `SearchNoResultsState` — **centré, silencieux, sans icône**, *No results for « mother of learning »*, et une suggestion de requête différente. **Aucun réessai** : rien n'a échoué | **E19** : c'est le seul des quatre qui est un **résultat**. « Visibly distinct from a failure message » est la contrainte entière — d'où l'absence d'icône, de couleur d'erreur et de bouton |
| **La source déclare la recherche et ne rend rien d'exploitable** | `SearchResultsUnusable` | **`ErrorState`**, ancré en haut, icône `--color-error`, *Lumen Tale could not read Royal Road*, `secondary` **Check again**, ligne de rapport **C12** | **B50** : *« A source that declares search and then returns nothing is treated as a **broken source** and reported per B22 — never as a source that simply has no results »* |
| **Pas de connexion** | `SearchResultsUnusable(NoConnection)` | `ErrorState` *No connection. Nothing is wrong with Royal Road* + **Check again** + `ghost` **Open your library** | **E5** : la bibliothèque marche hors ligne, et l'écran le dit |
| **La source déclare la recherche et renvoie `BrowseSucceeded` vide** | *aucun rendu* — la clause 2 **lève** | — | **E8** : une page vide ne peut pas devenir « aucun résultat ». LLevée est un **défaut de source**, pas un état d'écran ; l'afficher serait le mentir |

> ⚠️ **E19 ne peut pas être satisfaite par une liste vide.** `SearchResultsNothing` n'est
> produit que depuis `BrowseEmpty`, et `BrowseEmpty` n'est produit que si le **site** a
> fourni son propre signal — *There is nothing here :(* sur Royal Road. Une recherche qui
> ne trouve rien et que le site ne signale pas est donc un **`SearchResultsUnusable`**, pas
> un `SearchResultsNothing`. C'est ce que la clause 2 du `switch` garantit
> structurellement (§ 2.2) : il n'existe aucun chemin de code qui transforme une page
> muette en « aucun résultat ».

**Le champ ne passe jamais en erreur dans aucun des trois cas.** `browse-catalogue.md` § 4
(*Submit error (a)*) : *« The field **never turns red**. The query was well-formed and accepted;
what failed is the site's answer. Marking the input as errored tells the reader they typed
something wrong, which is the one thing that is not true. »* Le champ garde la requête
**verbatim et éditable**, et le réessai est à une seule tape.

### 3.4 Le cas où la slice n'a rien à construire (couvre **B50**)

Si `6-11` conclut qu'aucun site n'implémente de recherche utilisable :

| Ce qui se passe | Ce qui ne se passe pas |
|---|---|
| `supportsSearch` reste `false` sur les trois sources | Aucun champ de recherche n'est rendu nulle part |
| `browse-genre.md` affiche l'`EmptyState` `search-unsupported` — qui explique que la recherche par genre **est** le chemin | Aucun `TextField`, aucun état de résultats, aucun test de pagination de recherche |
| `SC-1` est satisfait : *« A source with no genuine site search is met by genre browsing alone; that is a passing v1, not a gap »* | Aucune ligne du registre, aucun libellé « bientôt » |
| La slice est **clôturée sans être exécutée** | Aucun travail jetable n'est laissé dans le dépôt |

**C'est un résultat, pas un échec.** Le PRD le dit en toutes lettres et
`benchmarks.md` § 4b le chiffre comme le coût assumé.

elle retient des `Novel` inutilement.

component-parity` le dirait si on en créait un.

### 4.3 États par écran

`browse-catalogue.md` déclare **neuf** états. Cette slice en implementle **quatre** en propre,
et **modifie** un état existant :

| État | Ce que cette slice ajoute |
|---|---|
| *Loading* — mode résultats | Le squelette est **identique** à celui du catalogue ; le champ est **présent et utilisable** pendant le chargement |
| *Filled* — résultats | `NovelRow` variante `result`, **l'ordre du site**, aucun tri appliqué par l'app |
| *Empty — no data* — résultats | `SearchNoResultsState`, qui est **une autre instance** que `EmptyCatalogueState` : *« distinct copy »* |
| *Load error* — résultats | `ErrorState` ancré en haut, **une ligne** *Lumen Tale could not read Royal Road*, ligne de rapport C12 |
| *Submit error* (a) | **Modifié** : le champ ne rougit jamais ; `ErrorState` remplace la liste, le champ garde la requête |
| *Success* (b) — la requête | **Aucun Toast.** *« A toast that says "12 results" is a statement about something that is on the screen »* |
| *Offline* | `ErrorState` *No connection. Nothing is wrong with Royal Road* + **Open your library** |

**Trois choses que le mode résultats n'a pas**, et qu'il ne faut pas lui ajouter parce qu'elles
seraient faites ailleurs :

| Absent | Pourquoi |
|---|---|
| Un filtre par genre **dans** la recherche | B41 : ce serait l'app qui décide du sens des mots |
| Un tri ou un score de pertinence | *« a relevance score would be the app ranking on fields it does not hold »* |
| Une mise en cache des résultats | *« a cached row is a promise that tapping it opens that novel »* |

### 4.4 Formulaires

**Un seul, et c'est le champ de recherche.** `09-widgets-ui.md` §Deferred : les règles de
formulaire *parked* (« form focus navigation », « inline mutation forms ») **s'activent**
quand des forms texte arrivent — et celui-ci en est un. **Lire ces règles avant d'écrire ce
champ**, mais **ne pas les étendre** : ce champ est une soumission unique, pas un formulaire
multi-champs, et il n'y a ni `Next`/`Done` à chaîner ni état de sauvegarde en ligne.

**Aucune validation de champ.** Une requête vide est simplement *ignorée* : le lecteur n'a rien
demandé, et B5 interdit d'aller chercher quelque chose qu'il n'a pas demandé.

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| La requête courante | écran, **`autoDispose`** | état du notifier + le paramètre `q` de la route | au montage, depuis `q` | `submit` |
| Les résultats de la page N | écran | mémoire | au `run()` | `nextPage` |
| Les mots tapés | widget | `TextEditingController` | `initialWords` | à la frappe |
| Les résultats d'une recherche **précédente** | **rien** | — | — | **jamais conservés** |

**La ligne vide est la plus importante du tableau.** Il n'y a **aucun cache de résultats**,
parce qu'un résultat de recherche en cache est une promesse que l'app ouvrira ce roman — et
elle pourrit sur un roman renommé, déplacé ou retiré (**E9**). Le **seul** élément mis en
cache est l'image de couverture, ce que le design system nomme *« the only reason a second
visit costs nothing »*.

**La requête n'est pas persistée au-delà de la route.** C'est un paramètre d'URL
`?q=…`, donc elle **survit à un retour arrière** — ce qui est exactement ce qu'un lecteur
veut après avoir ouvert un roman et être revenu — et **rien d'autre**. Elle n'est jamais
écrite en base et **jamais journalisée** (B29 : une requête est une préférence de lecture).

## 6. Traçabilité des règles

### 6.1 Règles métier (B*)

| ID | Règle (PRD, texte intégral) | Implémentée où | Approche |
|---|---|---|---|
| **B41** | *« Searching inside a site searches whatever that site searches. The app does not split a query into title, author and description, nor decide which of those a site matches; it passes the reader's words to the site. »* | § 3.2, `SourceSearchController.run` | Un **seul** appel à `searchNovels` dans tout le code, avec `query.words` tel quel. `SearchQuery` n'a **aucune** méthode de normalisation. `filters` est **toujours** vide, donc aucune portée de genre n'est attachée. Le pied de page dit *More results from &lt;site&gt;* et non *Page 2*, parce qu'un jeu de résultats n'a pas de pages dont le lecteur a raisonné. Aucune mise en cache |
| **B50** | *« **Search is an opt-in capability of a source, not a promise of the app.** The app offers search for a site **only when that site genuinely implements one** — meaning its own search returns results a reader would call useful, rather than an empty page or an error. Where it does not, the app offers that source's **genre and tag browsing** instead, and says so, rather than showing a search box that would return nothing. A source that declares search and then returns nothing is treated as a **broken source** and reported per B22 — never as a source that simply has no results. »* | § 3.1, § 3.3, § 3.4 | **Trois** dispositions, toutes nécessaires. (a) `supportsSearch == false` → **aucun champ rendu**, et `browse-genre.md` porte l'explication + les genres. (b) `supportsSearch == true` mais la source ne rend rien → **`ErrorState`**, pas « aucun résultat » ; c'est la troisième classe de `SearchResults`, `SearchResultsUnusable`, sans quoi l'écran devrait choisir entre deux mensonges. (c) `supportsSearch == false` pour **tous** les sites → la slice n'est pas exécutée, et c'est un v1 qui passe |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| **E5** | *« No connection while browsing or searching — the user is offline and opens a catalogue or runs a search. A clear "no connection" message with a retry; the library and every stored chapter remain fully usable (B23, C14) »* | `SearchResultsUnusable(NoConnection)` → `ErrorState` *No connection. Nothing is wrong with Royal Road*, **Check again**, et `ghost` **Open your library**. Le champ reste **présent et lisible** avec les mots du lecteur — c'est le résultat qui change, pas la saisie. La bibliothèque et les chapitres stockés ne sont pas touchés (B23, C14) | § 3.3, `browse-catalogue.md` § 4 *Offline* |
| **E8** | *« A site returns nothing where content is expected — a site's page loads but contains none of the expected items. Treated as a suspected break, not as "no results", and reported as a failure (B22) »* | **La clause 2 du `switch` de § 2.2.** Une source ne doit **jamais** renvoyer `BrowseSucceeded` avec zéro novel ; si elle le fait, c'est un bug de source et le contrôleur **lève** au lieu de fabriquer un « aucun résultat ». La troisième issue est donc structurellement inatteignable depuis cette slice : elle ne peut pas transformer une page vide en « rien trouvé » | § 2.2 `SourceSearchController.run` |
| **E19** | *« A search genuinely matches nothing — the search is well-formed and the site has no match. An explicit "no results" message, visibly distinct from a failure message (B22, US-02). »* | **La clause 3 du `switch`, et elle exige le signal du site.** `BrowseEmpty(siteSuppliedSignal)` → `SearchResultsNothing` → `SearchNoResultsState` : **centré, silencieux, sans icône, sans réessai**, avec la requête citée et une suggestion différente. « Visibly distinct » est une exigence de rendu, pas de libellé : l'absence d'icône et de couleur d'erreur **est** la distinction. Une recherche sans correspondance **dont le site ne dit rien** n'atteint pas cette issue — elle tombe en `SearchResultsUnusable`, parce qu'un site qui ne sait pas dire qu'il n'a rien n'est pas distinguable d'un site cassé (**B22**) | § 3.3, § 2.2 `SourceSearchController.run` |

### 6.3 Contraintes (C*)

| ID | Contrainte (PRD) | Comment elle est respectée |
|---|---|---|
| **C2** | *« Privacy — no account, no server, no telemetry of any kind. Reading data never leaves the phone (B4, B29). »* | La requête est **la seule** donnée de cette slice, elle ne quitte l'appareil que dans la requête que le lecteur a demandée, elle n'est **jamais** journalisée et **jamais** persistée au-delà du paramètre d'URL. Aucune analytique, aucun rapport de crash |
| **C7** | *« Source reliability — sites change their pages without warning and can stop working overnight. The app silently returning nothing is the main failure mode to avoid (B22, E4). »* | La clause 2 du `switch` est la construction qui empêche le mode d'échec principal : une page vide **ne peut pas** devenir « aucun résultat ». Un rapport d'échec nomme la source et la requête en toutes lettres (C12) |
| **C12** | *« The app must make its own failure state obvious enough for that reader to describe it to the owner **in words** — a message that can be read aloud and reported back — and actionable, not merely present. »* | `ErrorState` porte la ligne *If you report this, say: "Royal Road's search could not be read."* — lisible à voix haute, et le lecteur n'a rien à traduire. L'action **Check again** est là. Un état d'échec qui n'admet aucune action est un état qui échoue à C12 |
| **C11** | *« Reading happens one-handed, on a phone, at night or in transit »* | Le champ fait 56dp, chaque action 48dp, la liste défile verticalement. **Aucun** pull-to-refresh : B5 interdit de récupérer ce que le lecteur n'a pas demandé, et l'action est **Check again** |

## 7. Pièges à éviter

- **⚠️ Ne pas commencer cette slice avant le verdict de `6-11`.** Le comportement correct
  (**B50**, ADR-015) est : lire `.opencode/rules/18-external-contracts.md`, et si aucun site
  n'y a de verdict mesuré `supportsSearch: true`, **ne rien écrire**. Une recherche construite
  pour être activée plus tard est une promesse à une version qui n'existe pas.
- **⚠️ Ne pas rendre le champ « présent et désactivé » quand `supportsSearch == false`.** Le
  comportement correct (**B50**) est : **absent**. Une zone de texte désactivée occupe une
  ligne, promet quelque chose, et laisse le lecteur chercher pourquoi elle est morte.
- **⚠️ Ne pas écrire `query.trim()`.** Le comportement correct (**B41**) est : les mots
  **byte pour byte**. Une espace en trop change ce que le lecteur a demandé, et « mother  of »
  n'est pas « mother of » pour un site.
- **⚠️ Ne pas découper la requête en champs, ni lui attacher le genre.** Le comportement
  correct (**B41**) est : `searchNovels(1, words, FilterList([]))`, `filters` **toujours**
  vide. Ajouter le genre ferait dire à l'app ce que la requête signifie.
- **⚠️ Ne pas faire de `SearchResultsUnusable` un « aucun résultat ».** Le comportement
  correct (**B50** + **B22**) est : une source qui **déclare** la recherche et ne rend rien
  est un **site cassé**, avec `ErrorState` et **Check again**. C'est la phrase entière de B50,
  et c'est la troisième classe du `sealed` qui la rend impossible à confondre.
- **⚠️ Ne pas faire passer le champ en état d'erreur.** Le comportement correct
  (`browse-catalogue.md` § 4) est : le champ **ne rougit jamais**. La requête était bien
  formée ; c'est la réponse du site qui a échoué. Marquer le champ en erreur dit au lecteur
  qu'il a mal tapé, ce qui est la seule chose qui n'est pas vraie.
- **⚠️ Ne pas faire de Toast sur le résultat d'une requête.** Le comportement correct est :
  **aucun**. *« A toast that says "12 results" is a statement about something that is on the
  screen »*.
- **⚠️ Ne pas écrire *Page 2* en pied de liste.** Le comportement correct (**B41**) est :
  *More results from Royal Road*. Le jeu de résultats n'a pas de pages dont le lecteur a
  raisonné.
- **⚠️ Ne pas mettre en cache les résultats d'une recherche.** Le comportement correct
  (**E9**, `browse-catalogue.md` § 8) est : rien n'est mis en cache, sauf la couverture. Une
  ligne en cache est une promesse que l'app ouvrira ce roman.
- **⚠️ Ne pas ajouter de filtre, de tri ou de score de pertinence.** Le comportement correct
  (**B41**) est : l'ordre est celui du site, et `NovelRow` n'a pas de slot pour un score.
- **⚠️ Ne pas automatiser le chargement de toutes les pages.** Le comportement correct
  (`15-performance.md` §Lists) est : la pagination est explicite via `hasNextPage`, et il n'y
  a pas de défilement auto-chargeur sans borne.
- **⚠️ Ne pas journaliser la requête.** Le comportement correct (**B29**, **C2**,
  `browse-catalogue.md` § 8) est : un rapport d'échec nomme la **source**, jamais les mots
  tapés. Un titre que le lecteur a tapé est une préférence de lecture, et un journal est un
  appel réseau.

### 7.4 Une contradiction dans les documents sources, signalée et non corrigée

`architecture.md` § 5.1 présente le contrat `Source` dans un bloc de code où
`getPopularNovels`, `getLatestNovels` et `searchNovels` sont déclarés
`Future<NovelsPage>` — c'est-à-dire **sans** `BrowseOutcome` — tandis que **la prose juste
au-dessous** du même paragraphe écrit *« **Every one of these returns `BrowseOutcome<T>`** (§
2.2), not a bare list »*. Le même bloc déclare aussi `Future<Novel> getNovelDetails` et
`Future<List<Chapter>> getChapterList`, et `03-source-system.md` §Contract reproduit les
mêmes signatures nues.

Les trois lectures possibles — `Future<NovelsPage>` ou `Future<BrowseOutcome<NovelsPage>>` —
donnent deux comportements différents, dont un seul satisfait B22 : sans le troisième état,
une recherche qui ne rend rien **peut** être rendue comme une liste vide.

**Ce plan suit la prose de `architecture.md` § 5.1** — `Future<BrowseOutcome<NovelsPage>>` —
parce que B22 et SC-6 sont des règles du PRD et qu'une règle approuvée ne se réinterprète
pas dans un document d'architecture. **La correction appartient à `architecture.md` et à
`03-source-system.md`, pas à ce plan, et ce plan ne les modifie pas.** Signalé au
propriétaire.
