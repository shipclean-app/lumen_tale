## 1. Résumé de la slice

`6-11` répond à **une** question, avec une méthode et un livrable :

> **Est-ce que Royal Road implémente une recherche utilisable ? Et Novel Fire ?**

| Élément | Contenu |
|---|---|
| **Méthode** | Un fetch réel, sous le **`User-Agent` honnête** du projet, de l'URL de recherche de chaque site, avec une requête **qui doit matcher**, en suivant la chaîne de redirections |
| **Critère** | ADR-015, mot pour mot : *« its own search returns results a reader would call useful, rather than an empty page or an error »*. **Un `200` ne suffit pas. Une liste non vide ne suffit pas** — il faut des résultats **pertinents** pour la requête choisie |
| **Livrable** | Une section par site dans `.opencode/rules/18-external-contracts.md`, avec la carte d'URL, la date, le `User-Agent`, le statut HTTP, le nombre de lignes, et **un exemple de requête qui matche et un qui ne matche pas** |
| **Effet** | La ligne du tableau « Open items » de `18-external-contracts.md` passe de *unknown — not yet checked* à `true` ou `false`, avec sa base. `6-2` devient alors exécutable **ou** clôturée |

**La méthode est déjà appliquée une fois, et c'est le précédent à copier.** `0-2` a fait
exactement cela pour le signal de résultat vide de FanMTL, et sa conclusion tient dans une
cellule : *« Measured 2026-10-02. GET and POST both 404 with a meta-refresh, including for a
query that should match, session or no session. »*. **Note la formulation** : *« including
for a query that should match »* — c'est le contrôle qui empêche de conclure « pas de
résultats » d'une recherche qui n'a jamais rien cherché.

**Trois choses que cette slice ne fera pas**, chacune pour une raison écrite :

| Ne pas | Pourquoi |
|---|---|
| Écrire une classe `Source`, un adaptateur, ou un `source_registry` | Le résultat est un **verdict**, pas une implémentation. `6-1` et, si elle existe, l'adaptateur Novel Fire s'en chargent |
| Écrire un test qui atteint le réseau | `10-testing.md` règle 7 : *« No test may reach the public internet »*. Un « test de recherche » réseau est un test qui échoue la semaine où le site change |
| Proposer une recherche **partielle** | ADR-015 a rejeté l'idée de passer les tags du roman dans la barre du site : *« ain't satisfying at all »*. Un demi-verdict est un verdict `false` avec de la paperasse |

**User stories couvertes** : US-02 (conditionnelle), US-16 (être prévenu quand un site ne
marche pas)

**Edge cases couverts** : E4, E8, E21

### 2.2 Le harnais de mesure

Un script Dart jetable, parce que la mesure doit employer **le User-Agent et la
politique réseau du projet** — un `curl` avec un UA de navigateur ne mesurerait pas ce que
l'app vit. Il est **hors de `lib/`** : il n'est pas du code de production.

```dart
// tool/search_reachability.dart
// Mesure la REACHABILITÉ et l'UTILISABILITÉ de la recherche d'un site.
//
// Lancement, depuis la racine du projet :
//   dart run tool/search_reachability.dart --site=royalroad
//   dart run tool/search_reachability.dart --site=novelfire
//
// Sortie : un rapport sur stdout, à transcrire dans
// `.opencode/rules/18-external-contracts.md`. Ce script n'écrit rien.
//
// ⚠️ Il utilise `core/network` — donc l'UA honnête, la limitation de débit et
// `Retry-After` sont ceux de l'application. C'est le point : une mesure faite
// avec un autre client ne décrit pas ce que l'app verra.
import 'dart:async';
import 'dart:io';

import 'package:lumen_tale/core/network/http_source_client.dart';

/// Un mot-clé qui **doit** matcher sur le site mesuré. Sans lui, une page vide
/// ne distingue pas « pas de recherche » de « pas de résultats ».
const Map<String, String> _probes = {
  'royalroad': 'mother of learning',
  'novelfire': 'omake',
};

/// Une requête qui **ne doit pas** matcher. Sans elle, une liste pleine ne
/// prouve rien : n'importe quoi ressemble à une recherche qui marche.
const Map<String, String> _negativeProbes = {
  'royalroad': 'zzzzqqqxxnomatch',
  'novelfire': 'zzzzqqqxxnomatch',
};

Future<void> main(List<String> args) async {
  final site = _argValue(args, '--site');
  final baseUrl = _argValue(args, '--base');
  final path = _argValue(args, '--path');
  final param = _argValue(args, '--param');

  if (site == null || baseUrl == null || path == null || param == null) {
    stderr.writeln(
      'usage: dart run tool/search_reachability.dart '
      '--site=<id> --base=<baseUrl> --path=<search path> --param=<query param>',
    );
    exit(64); // code d'usage : 64, pas 0 — « ça n'a pas tourné » ≠ « ça a marché »
  }

  // ⚠️ Le client de l'application. Pas un Dio() nu : on mesure ce que l'app voit.
  final client = HttpSourceClient(userAgent: honestUserAgent());

  stdout.writeln('=== $site ===');
  stdout.writeln('user-agent: ${honestUserAgent()}');
  stdout.writeln('date: ${DateTime.now().toUtc().toIso8601String()}');

  for (final (label, query) in {
    'positive': _probes[site]!,
    'negative': _negativeProbes[site]!,
  }.entries) {
    final result = await probe(client, baseUrl, path, param, query.value);
    stdout.writeln('--- $label: "${query.value}"');
    stdout.writeln('status          : ${result.status}');
    stdout.writeln('final url       : ${result.finalUri}');
    stdout.writeln('redirects       : ${result.redirectCount}');
    stdout.writeln('content-type    : ${result.contentType}');
    stdout.writeln('result nodes    : ${result.resultNodes}');
    stdout.writeln('first title     : ${result.firstResultTitle ?? "(none)"}');
    stdout.writeln('site empty text : ${result.siteEmptySignal ?? "(none)"}');
    stdout.writeln('meta-refresh    : ${result.metaRefresh ?? "(none)"}');
  }
}
```

```dart
// tool/search_reachability.dart — la mesure elle-même
/// Le résultat brut d'une sonde. **Aucune interprétation ici** : interpréter
/// est la décision de la section § 2.3, écrite par un humain, pas par le
/// script. Un script qui conclut est un script dont on ne peut pas discuter
/// le verdict.
final class ProbeResult {
  const ProbeResult({
    required this.status,
    required this.finalUri,
    required this.redirectCount,
    required this.contentType,
    required this.resultNodes,
    required this.firstResultTitle,
    required this.siteEmptySignal,
    required this.metaRefresh,
  });

  final int status;

  /// L'URL **après** redirections. Une recherche qui redirige vers la page
  /// d'accueil est une recherche qui ne cherche pas.
  final Uri finalUri;
  final int redirectCount;
  final String contentType;

  /// Le nombre d'éléments correspondant au sélecteur de résultat du site.
  /// **Zéro sur la sonde positive est le signal d'alarme principal.**
  final int resultNodes;

  /// Le titre du premier résultat : c'est ce qui décide si les résultats sont
  /// « ceux qu'un lecteur qualifierait d'utile ».
  final String? firstResultTitle;

  /// Un texte d'absence **fourni par le site** — la troisième voie de B22.
  final String? siteEmptySignal;

  /// Un `<meta http-equiv="refresh">`. C'est ce que FanMTL fait, et c'est
  /// un 404 déguisé : le statut est 404 et le navigateur va ailleurs.
  final String? metaRefresh;
}
```

## 3. Algorithmes critiques

### 3.1 La sonde, et ses cinq issues

```
probe(site, query):
  # ── 1. La requête telle quelle ─────────────────────────────────────────
  # ⚠️ AUCUNE normalisation : pas de trim, pas de minuscules, pas de
  # découpage. On mesure ce que le site ferait des mots choisis, parce que
  # c'est ce que B41 promet au lecteur.
  uri = Uri.parse(baseUrl + path).replace(queryParameters: {param: query})

  # ── branche 1 : réseau / DNS / timeout ─────────────────────────────────
  #   → statut `unreachable`. Ce n'est PAS un verdict sur la recherche : le
  #     site est peut-être perfectly capable et éteint. ⚠️ REPRENDRE plus
  #     tard, et le dire dans la fiche.
  #
  # ── branche 2 : statut non-succès (403, 404, 429, 5xx) ─────────────────
  #   → statut `blocked` ou `not-found`. Un 403 sous UA honnête est aussi un
  #     signal fort : cela rappellerait la mesure de Novel Fire (honête → 200,
  #     navigateur → 403). On le consigne dans les deux colonnes.
  #
  # ── branche 3 : redirection ────────────────────────────────────────────
  #   Si l'URL finale n'est plus une page de recherche — si elle revient à
  #   l'accueil, par exemple — alors le formulaire de recherche est un
  #   mensonge : il mène ailleurs. → statut `redirects-elsewhere`.
  #   ⚠️ C'est une forme de « recherche non implémentée » qui NE se voit pas
  #   sur un simple code HTTP. C'est pourquoi on suit les redirections.
  #
  # ── branche 4 : 200 + <meta http-equiv="refresh"> ──────────────────────
  #   → statut `meta-refresh`. C'est exactement ce que FanMTL fait : un 404
  #     qui ressemble à un chargement. À consigner tel quel, sans l'adoucir.
  #
  # ── branche 5 : 200, page de recherche, aucun de ce qui précède ─────────
  #   → la sonde est lisible. C'est là que commence la vraie question :
  #     ⚠️ le SCRIPT NE CONCLUT PAS. Il imprime le nombre de lignes et le
  #     premier titre. La décision est humaine, et elle est écrite en § 2.3.

  return ProbeResult(...)      # des faits, jamais un verdict
```

### 3.2 Le verdict — la décision, avec les six issues

C'est ici, et **seulement ici**, qu'une conclusion est écrite. Les six issues, parce que
« ça marche » n'a pas une seule forme :

| Issue de la sonde positive | Verdict | Raison |
|---|---|---|
| **≥ 1 résultat, et le premier est le livre cherché** | **`true`** | ADR-015 : *« results a reader would call useful »*. Le test est l'**utilité**, pas le `200` |
| ≥ 1 résultat, mais **aucun ne correspond** à la requête | **`false`** | Le site a une liste, pas une recherche. C'est le piège que ADR-015 a nommé : passer les tags dans la barre du site |
| **0 résultat**, statut 200, aucun texte du site | **`false`** | **E8** : une page qui ne contient rien de ce qu'on attend est une **rupture**, pas « pas de résultats ». Le dire autrement rendrait la mesure inutilisable |
| 0 résultat, statut 200, **avec** un texte du site d'absence | **`false`**, et **la découverte est consignée** | Le site distingue le vide — c'est la troisième voie de B22 — mais il ne sait pas chercher. Les deux faits sont notés séparément |
| Le site renvoie vers l'**accueil** | **`false`** | La réponse à une recherche n'est pas une recherche |
| Son propre **formulaire** ne part pas (bouton absent, `action` mort) | **`false`** | *« its own search returns results »* — un formulaire qui ne part pas n'est pas une recherche |

**Et la symétrie obligatoire :**

| Issue de la sonde **négative** | Ce qu'elle prouve |
|---|---|
| 0 résultat, avec le texte du site | Le site **sait** dire qu'il n'y a rien. C'est B22 rendu par le site — une découverte à consigner, avec son signal exact |
| 0 résultat, **sans** texte du site | Le site ne distingue pas « rien » de « cassé ». **C'est un défaut de B22 chez ce site**, et cela doit être écrit dans sa fiche |
| ≥ 1 résultat | **La recherche ne filtre pas.** Un verdict `false`, et c'est le motif le plusimportant de tous |

### 3.4 Les six issues de **politesse** (non négociables)

`17-security.md` règles 5-7 et `10-testing.md` règle 7 s'appliquent à cette mesure comme à
tout le reste, et une mesure est un ensemble de requêtes contre un site qui ne nous doit
rien.

| Règle | Ce qu'elle impose ici |
|---|---|
| Règle 5 — UA honnête | Le script utilise **le client de l'application**. Pas de chaîne de navigateur, pas de `WebView`, pas de `cf_clearance` (ADR-014). Si un site défie cet UA, on **consigne et on arrête**, et on ne contourne rien |
| Règle 6 — limitation de débit | **Six requêtes au total** pour cette slice : deux par site (positive, négative). Pas de boucle, pas de « vérifions une troisième fois ». Le délai entre requêtes est celui de `core/network` |
| Règle 7 — TLS seul | Aucune exception, aucun certificat désactivé |
| Règle 16 — n'aspirer que les sites qui le permettent | Le `robots.txt` de chaque site est lu **avant** la sonde, et le verdict est consigné avec. Si `robots.txt` interdisait la recherche, le verdict serait **`false`**, et la fiche le dirait |
| `10-testing.md` 7 — aucun test n'atteint le réseau | Le script est **hors de `test/`**. Il n'est ni un test ni un test unitaire déguisé |
| `18-external-contracts.md` règle 1 — la confirmation | Date, User-Agent, statut, chaîne de redirections. Une mesure sans provenance est une devinette avec un ton confiant |

### 3.5 Ce qui n'est **pas** mesuré, et pourquoi

| Ce qui n'est pas mesuré | Pourquoi |
|---|---|
| La **navigation par tags** de Royal Road (`?tagsAdd=`) | ADR-015 : *« passing a novel's own tags back into a site's search bar »* — *« isn't satisfying at all »*. C'est une **décision de conception déjà prise**, pas une mesure à faire |
| La recherche de **Novel Fire** quand Q-004 n'est pas résolu | On peut la mesurer — c'est une requête HTTP — mais le verdict **ne conditionne rien** tant que C10 n'est pas levé. La mesure est une information, pas une autorisation |
| La **qualité** de la recherche au-delà d'un exemple | ADR-015 demande *« useful »*, pas *« excellent »*. Un exemple qui matche et un qui ne matche pas suffisent ; évaluer la pertinence sur vingt requêtes est une autre slice, et elle n'existe pas |
| Le comportement de la recherche **hors ligne** | C14 : la recherche est une lecture réseau par nature. Elle ne fonctionne pas hors ligne et n'a pas à le dire autrement |

|---|---|---|---|
| Le résultat d'une sonde | **processus du script** | stdout | le temps de l'exécution |
| Le verdict | **le fichier de règles** | `.forge/../.opencode/rules/18-external-contracts.md` | jusqu'à la prochaine vérification |
| `supportsSearch` d'une source | **code** | `sources/implementations/<site>_source.dart` | jusqu'à ce qu'une URL casse |
| Un rapport d'erreur brut d'une sonde | **rien** | **nulle part** | — |

**Le rapport brut ne survit pas.** Il est transcrit dans la fiche du site — sous forme de
lignes de comportement, **jamais** de HTML brut, **jamais** de corps de réponse intégral.
`17-security.md` règle 9 interdit le HTML brut dans ce qui est persisté, et une fiche de
règles n'a pas besoin de 40 Ko de réponse pour dire *« 200, zéro ligne »*.

**Ce qui n'est délibérément pas de l'état** : la liste des requêtes déjà essayées. Une mesure
ne se met pas en cache : si elle doit être refaite, elle se refait, et le fichier conserve la
**date**, qui est la vraie information.

## 6. Traçabilité des règles

### 6.1 Règles métier (B*)

| ID | Règle (PRD, texte intégral) | Implémentée où | Approche |
|---|---|---|---|
| **B50** | *« **Search is an opt-in capability of a source, not a promise of the app.** The app offers search for a site **only when that site genuinely implements one** — meaning its own search returns results a reader would call useful, rather than an empty page or an error. Where it does not, the app offers that source's **genre and tag browsing** instead, and says so, rather than showing a search box that would return nothing. A source that declares search and then returns nothing is treated as a **broken source** and reported per B22 — never as a source that simply has no results. »* | § 3.1 (la sonde), § 3.2 (le verdict, **six issues**), § 3.3 (les conséquences), § 2.3 (le livrable) | Le critère est **« utile »**, pas « joignable » : la sonde positive doit **matcher**, et le verdict se décide sur le titre du premier résultat, pas sur un code HTTP. Six issues de verdict, parce que « ça marche » a six formes et une seule donne `true`. Le livrable est une **ligne de tableau et une fiche datée**, dans le format que `0-2` a fixé — donc `6-2` a, après cette slice, **une base écrite** au lieu d'une opinion |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| **E4** | *« Site layout changed between releases — a site reorganises its pages; the app can no longer read it. The app detects this and reports "this site could not be read"; it never shows an empty catalogue or an empty chapter list as if the novel had none (B22). »* | **Une mesure est une photographie, et une photographie périme.** C'est le sens qu'E4 prend ici : il n'y a pas d'application à corriger, il y a une **valeur datée** à expire. Le format de § 2.3 impose `Last verified` et la date dans le tableau « Open items », donc une mesure vieille se voit au lieu de mentir. Et une sonde **positive vide** n'est jamais conclue « pas de résultats » — c'est une **rupture** (§ 3.2, ligne 3, et **E8**) : une mise en page qui a changé se présente exactement comme ça | § 2.3, § 3.2 |
| **E8** | *« A site returns nothing where content is expected — a site's page loads but contains none of the expected items. Treated as a suspected break, not as "no results", and reported as a failure (B22) »* | **Appliqué au mesureur lui-même.** Une sonde positive qui rend **zéro** élément dans une page 200 bien formée est traitée comme une **suspicion de rupture**, pas comme « pas de résultats ». Concrètement : `verdict = false` **et** la fiche dit *« 200, zero result nodes, no site signal »* — ce qui est une observation sur le site, distincte d'une recherche qui a cherché et n'a rien trouvé | § 3.2 ligne 3, § 3.2 symétrique |
| **E21** | *« Novel Fire's terms are not confirmed — the decision in C10 arrives negative. Novel Fire does not ship, is not advertised anywhere in the app, and v1's success is judged without it (B1) »* | **Une mesure n'est pas une autorisation.** Cette slice sonde Novel Fire et rend un verdict, et le verdict **n'ouvre aucune porte** : tant que Q-004 n'est pas levé, aucune ligne du registre, aucun `NovelFireSource`, aucun libellé, aucun écran n'existe — et aucun n'est préparé « pour plus tard ». Le verdict est **consigné** dans `18-external-contracts.md` comme une observation datée, ce qui est l'inverse d'une annonce. § 3.3 : un verdict mesuré sur un site qui ne sera peut-être jamais implémenté reste une mesure | § 3.3, § 2.3 |

### 6.3 Contraintes (C*)

| ID | Contrainte (PRD) | Comment elle est respectée |
|---|---|---|
| **C1** | *« Legal — reading is for personal use only, from sites whose rules permit automated reading. Verified for FanMTL and Royal Road; unconfirmed for Novel Fire (B1). No redistribution of any content. »* | `robots.txt` de chaque site est lu **avant** la sonde. Un site qui interdisait la recherche dans son `robots.txt` donnerait `false`, et la fiche l'écrirait. Le contenu lu est **six réponses HTTP**, rien n'est redistribué, rien n'est conservé (**B30**) |
| **C5** | *« User skill — the only technical user cannot write code »* | Aucun réglage, aucun fichier de configuration écrit par le lecteur, aucune étape manuelle sur son téléphone. Le script est une étape de développement, pas une étape d'usage |
| **C7** | *« Source reliability — sites change their pages without warning and can stop working overnight. The app silently returning nothing is the main failure mode to avoid (B22, E4). »* | **C'est la règle qui justifie le « Last verified » du magasin.** Une mesure datée vaut six mois ; une mesure sans date ne vaut rien. Et le format de § 2.3 impose de relire le `robots.txt` à chaque vérification, comme le fait déjà la fiche FanMTL |
| **C6** | *« No server, no support, no telemetry means the app has no way to learn why it failed. Failures must therefore be recognisable on the device and reported there (B24, B22) »* | Le livrable **nomme la cause** de chaque verdict : `404`, `meta-refresh`, `redirige vers l'accueil`, `formulaire mort`, `aucune correspondance`. Un verdict « non » sans raison ne permet pas au propriétaire de le comprendre ni de le réexaminer |

## 7. Pièges à éviter

- **⚠️ Ne pas conclure « pas de résultats » d'une requête qui n'a rien cherché.** Le
  comportement correct (`0-2`, le précédent) est : la sonde positive utilise **un mot qui doit
  matcher**, et la fiche l'écrit tel quel. *« Measured … including for a query that should
  match »* est la formule de `0-2`, et c'est elle qui rend le verdict opposable.
- **⚠️ Ne pas conclure « ça marche » d'un `200`.** Le comportement correct (**B50**,
  ADR-015) est : il faut des résultats **pertinents** — c'est-à-dire que le premier titre
  est le livre cherché. Un `200` avec une liste non pertinente est un **verdict `false`**,
  et c'est le piège exact qu'ADR-015 a nommé chez les concurrents.
- **⚠️ Ne pas suivre la recherche par tags.** Le comportement correct (ADR-015) est :
  les liens `?tagsAdd=` existent sur le site et **ne prouvent rien** sur une recherche par
  mots. La décision de ne pas les utiliser comme chemin de découverte est **déjà prise** et
  argumentée ; la mesurer serait la refaire.
- **⚠️ Ne pas laisser le script conclure.** Le comportement correct est : `ProbeResult` ne
  contient que des **faits**, et le verdict est écrit à la main dans la fiche, avec la date.
  Un script qui conclut produit un verdict qu'on ne peut pas discuter, et B50 est une décision
  qu'il faut pouvoir réexaminer.
- **⚠️ Ne pas mesurer avec un `curl` ni avec un UA de navigateur.** Le comportement correct
  (`17-security.md` règle 5, ADR-014) est : le client de l'application, UA
  `LumenTale/<version> (personal reader)`. C'est exactement ce qui a été mesuré sur Novel
  Fire — honnête → 200, navigateur → 403 — et c'est la mesure qui justifie toute la posture.
  Une mesure avec un autre client décrit un autre programme.
- **⚠️ Ne pas mettre le script dans `test/`.** Le comportement correct
  (`10-testing.md` règle 7) est : *« No test may reach the public internet »*. Un test qui
  échoue le jour où le site change est pire qu'aucun test : il fait échouer la suite pour une
  raison qui n'a rien à voir avec le code.
- **⚠️ Ne pas mettre le script dans `lib/`.** Le comportement correct est : `tool/`, hors de
  l'APK. Un script de mesure compilé dans l'application est du code mort qui pèse sur le
  binaire.
- **⚠️ Ne pas faire plus de six requêtes.** Le comportement correct
  (`17-security.md` règle 6) est : deux sondes par site, et c'est tout. Une mesure qui
  recommence est une mesure qui devient du martèlement, et C7 est explicite.
- **⚠️ Ne pas persister le HTML brut ni le corps d'une réponse.** Le comportement correct
  (`17-security.md` règle 9) est : la fiche consigne des **lignes de comportement** —
  *statut, nombre de nœuds, premier titre* — pas 40 Ko de page.
- **⚠️ Ne pas écrire `supportsSearch = true` « pour rendre la fonctionnalité plus visible ».** Le
  comportement correct (**B50**, ADR-015) est : la valeur ne change que sur le verdict écrit
  dans `18-external-contracts.md`, et `6-1` ne change **que** si ce verdict existe. Un `true`
  non mesuré est exactement la promesse qu'ADR-015 a été écrit pour interdire.
- **⚠️ Ne pas mesurer Novel Fire et en déduire qu'il ships.** Le comportement correct
  (**B1**, **E21**, C10) est : un verdict mesuré est une **information** ; il n'autorise rien
  tant que Q-004 n'est pas levé. « Absent », pas « désactivé ».
- **⚠️ Ne pas laisser le verdict sans date.** Le comportement correct
  (`18-external-contracts.md` règle 1) est : *« An entry with no provenance is a guess with a
  confident tone »*. `Last verified` et la date dans le tableau sont **obligatoires**.
- **⚠️ Ne pas consigner « le site a une page de recherche » comme une découverte.** Le
  comportement correct (`18-external-contracts.md` règle 3) est : *« Known-and-always-true
  behaviour is not a finding »*. Seule la **réponse mesurée** est consignée.

### 7.5 Où mettre le script — signalé, pas tranché

`architecture.md` § 1.2 ne déclare ni `tool/` ni `bin/`. L'implémentateur choisit `tool/`,
qui est la convention Dart et qu'aucun document du projet ne contredit. **Si ce choix est
contesté, ce n'est pas à cette slice de modifier `architecture.md`** : le livrable de la slice
est la section de `18-external-contracts.md`, et le script est un moyen. **Ce qui est
absolument interdit** est de l'écrire dans `lib/` ou dans `test/`.
