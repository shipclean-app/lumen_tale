## 1. Résumé de la slice

`3-5` construit **l'écran « À propos »**, et la règle qu'il porte est la plus
petite du PRD : **B43**, *the app shows which version is installed, on a dedicated
about screen*.

L'écran fait bien plus que cela, et il faut dire pourquoi avant de dire quoi.
`benchmarks.md` § 2 enregistre que **le défaut le plus signalé chez les
concurrents est la perte de données lors d'une réinstallation** — *« will not
restore after a reinstall »*. **B31** rend cette panne structurellement
impossible : il n'y a ni compte, ni serveur, ni export (**ADR-010**), donc une
réinstallation n'a rien à restaurer et rien à perdre. Cette garantie, seule,
vaut le paragraphe — **et une garantie que personne ne peut vérifier n'est qu'une
affirmation.** L'écran existe pour la rendre **vérifiable**, et il le fait en
plaçant **trois chiffres** juste sous le numéro de version : ce qu'il y a dans la
bibliothèque, ce qui est téléchargé, et combien de positions de lecture sont
enregistrées. Le lecteur les note avant d'installer une mise à jour, et les
compare après.

**La deuxième moitié de l'écran est une déclaration d'absence, et c'est
délibéré.** Sept choses ne quittent jamais l'appareil — bibliothèque, positions,
historique, journaux d'erreur, rapports de plantage, suivi d'audience,
identifiant d'appareil — et chacune a une coche à côté d'elle, **pas** un
écusson de bouclier. Un bouclier signifierait « vos données sont en sécurité »
et demanderait au lecteur de nous croire ; une liste de sept choses qu'il peut
compter demande moins, et dit davantage. Elle se termine par une **vérification
que le lecteur peut faire lui-même en trente secondes** : mode avion, ouvrir
l'application, tout est là. La promesse de confidentialité et la promesse
hors-ligne sont **la même mesure**, donc le lecteur ne la croit pas sur parole.

**User stories couvertes** : US-17 (Une nouvelle version comme fichier),
et US-13 par inversion — chaque chaîne existe en français et en anglais (B28)
**Règles métier couvertes** : B43
**Edge cases couverts** : aucun attribué par `state.json` ; E11 est traité ici
parce que l'écran le déclare (§ 6.2)

## 2. Contrats de données (code)

### 2.1 Schémas de validation

**Aucun nouveau schéma.** Cette slice ne lit et n'écrit **aucune** colonne
existante. Elle compte trois tables et affiche une constante de compilation.

Les trois chiffres qu'elle affiche sont les seules données locales de l'écran, et
chacune est un `COUNT(*)` brut — jamais une somme, jamais une valeur mémorisée :

| Chiffre | Requête | Table |
|---|---|---|
| `libraryCount` | `SELECT COUNT(*) FROM novels WHERE in_library = 1` | `novels` |
| `downloadedChapterCount` | `SELECT COUNT(*) FROM chapters WHERE downloaded_at IS NOT NULL` | `chapters` |
| `readingPositionCount` | `SELECT COUNT(*) FROM reading_positions` | `reading_positions` |

Les trois requêtes sont écrites ici **et nulle part ailleurs**. `3-5` est le seul
lecteur de ces trois compteurs dans tout le projet : ni `library.md`, ni
`updates.md`, ni `novel-details.md` ne les displayent, et `6-3` ne les possède
pas — il produit des comptes **par roman**, pas des totaux de l'installation.

### 2.2 Types et interfaces

```dart
// lib/core/app/app_version.dart
/// The installed version, resolved from build-time constants.
///
/// ADR-011: the version comes from `pubspec.yaml` and is injected at build
/// time. It is **not** read from the installed package — and that is why the
/// screen's Load-error state is a *real* failure mode rather than a defensive
/// branch: `--dart-define` is a flag on a build command, and a build command
/// can forget it.
library;

/// Injected by `apk-pipeline` from `pubspec.yaml`'s `version:` line.
///
/// **Two constants, both `String`.** `version: 1.0.0+1` in `pubspec.yaml`
/// splits into the two halves `1.0.0` and `1` that `settings-about.md` § 4.1
/// renders as *Version {buildName} · build {buildNumber}*.
///
/// ⚠️ These are EMPTY by default. That is not a placeholder; it is the state in
/// which the screen shows its Load-error line, which is the honest outcome and
/// is covered by a test. `apk-pipeline` supplies them:
///
///     flutter build apk --dart-define=LUMEN_BUILD_NAME=1.0.0 \
///                        --dart-define=LUMEN_BUILD_NUMBER=1
const String kBuildName = String.fromEnvironment('LUMEN_BUILD_NAME');
const String kBuildNumber = String.fromEnvironment('LUMEN_BUILD_NUMBER');

/// Resolved version, or the reason it could not be read.
///
/// A sealed type, because **a missing version and an epoch version are
/// different facts**, and because `settings-about.md` § 4 forbids `Version —`:
/// *an em dash looks like a version, and C9 requires the owner to be able to
/// determine which version is installed*.
sealed class AppVersion {
  const AppVersion();
}

final class VersionKnown extends AppVersion {
  const VersionKnown({required this.buildName, required this.buildNumber});

  final String buildName;
  final String buildNumber;

  /// `0.9.0 · build 41` — the exact shape of the two `about.version`
  /// placeholders in `settings-about.md` § 4.1.
  String get displayLine => '$buildName · build $buildNumber';

  /// `0.9.0 (build 41)` — the shape `Copy version number` puts on the
  /// clipboard, per `settings-about.md` § 5.
  String get clipboardText => '$buildName (build $buildNumber)';
}

/// The version string is missing or malformed.
///
/// **The rest of the screen still renders in full** — `settings-about.md` § 4
/// Load error: *The rest of the screen renders completely and unchanged — the
/// three counts, the whole privacy block, the delivery sentence. The version is
/// one string; a missing string must not blank the screen that states what the
/// app does with the reader's data.*
final class VersionUnreadable extends AppVersion {
  const VersionUnreadable({required this.reason});
  final String reason;
}

/// Pure, so its four branches are testable without a build.
/// `flutter test` cannot set a `--dart-define` for the app's own constants, so
/// this function takes them as arguments and the widget passes the two above.
AppVersion resolveVersion({
  required String buildName,
  required String buildNumber,
});
```

/// The three figures that evidence B31 — `settings-about.md` § 2.1 decision 2:
/// *they are the evidence for B31. A guarantee that an upgrade preserves the
/// library is worth nothing without a way to see that it did.*
library;

/// Three counts, each **nullable**.
///
/// Nullable because a failed query must render `—`, **never `0`**
/// (`settings-about.md` § 8: *Query fails → the count is **omitted with `—`**,

  const AboutLocalCounts({
    required this.library,
    required this.downloadedChapters,
    required this.readingPositions,

class AboutCopy {

  final AppLocalizations t;
}

## 3. Algorithmes critiques

### 3.1 Résoudre la version — les quatre branches (couvre **B43**, **C9**)

```
resolveVersion(buildName, buildNumber):

  # ── branche 1 : les deux présents ────────────────────────────────────
  si buildName.isNotEmpty ET buildNumber.isNotEmpty
                          ET buildName suit <nom>-<version>[+<build>]
                          ET buildNumber est une suite de chiffres :
      return VersionKnown(buildName: buildName, buildNumber: buildNumber)
      # C'est le cas nominal. `1.0.0+1` se scinde en `1.0.0` et `1`.

  # ── branche 2 : le nom manque, le numéro est là ──────────────────────
  si buildName.isEmpty ET buildNumber.isNotEmpty :
      return VersionUnreadable(reason: 'LUMEN_BUILD_NAME absent')

  # ── branche 3 : le numéro manque, le nom est là ──────────────────────
  si buildName.isNotEmpty ET buildNumber.isEmpty :
      return VersionUnreadable(reason: 'LUMEN_BUILD_NUMBER absent')

  # ── branche 4 : les deux manquent, ou l'un des deux est malformé ────
  #      (nom vide, numéro non numérique, nom qui n'est pas un nom-de-version)
      return VersionUnreadable(reason: 'LUMEN_BUILD_NAME ou LUMEN_BUILD_NUMBER
                                         illisible')
```

**Les quatre branches mènent à la même phrase pour le lecteur**, et c'est
délibéré : `settings-about.md` § 4.1 n'a **qu'une** clé,
`about.versionUnreadable`. Un lecteur qui reçoit « le numéro de version
installé n'a pas pu être lu » n'a pas besoin de savoir laquelle des deux
constantes manque. La **raison** differentiate reste dans le type et dans un
journal local — jamais à l'écran.

⚠️ **Ne jamais rendre `Version —`.** `settings-about.md` § 4 Load error : *`Version
—` is **not** used: an em dash looks like a version, and C9 requires the owner to
be able to determine which version is installed.* Le tiret cadratin est réservé
aux **comptes** échoués (`data.countUnavailable`), où il dit « on ne sait pas »
et où le lecteur n'a rien à comparer à travers une mise à jour. Une version est
exactement la chose qu'un lecteur doit pouvoir lire à voix haute à quelqu'un
d'autre.

**La validation de forme n'est pas décorative.** `--dart-define` est une chaîne
libre : `LUMEN_BUILD_NUMBER=latest` produit un écran qui affiche « build latest »,
et le propriétaire qui le rapporte à son contact dit une chose fausse sur son
installation. La branche 4 refuse cette forme et la remplace par la phrase
d'erreur, qui est au moins vraie.

### 3.2 Les trois chiffres — branches et rendu (couvre **B31**)

```
readAboutLocalCounts(db) -> AboutLocalCounts:

  ⚠️ LES TROIS EN UNE TRANSACTION, ET LEUR ÉCHEC EST INDÉPENDANT.
  Si l'une des trois requêtes échoue, son champ est null et **les deux autres
  restent valued**. C'est ce qui permet à l'écran de rendre deux chiffres et un
  tiret — état dégradé utile — plutôt que d'abandonner les trois.

  library            = COUNT(novels      WHERE in_library = 1)
  downloadedChapters = COUNT(chapters    WHERE downloaded_at IS NOT NULL)
  readingPositions   = COUNT(reading_positions)

  ⚠️ AUCUNE VALEUR N'EST CALCULÉE À PARTIR D'UNE AUTRE.
  - `downloadedChapters` compte les MARQUES, pas les fichiers.
    C'est deliberé et c'est B6 : la marque est écrite APRÈS le renommage
    atomique, donc un fichier sans marque n'est pas un chapitre téléchargé et
    une marque sans fichier est inatteignable. Compter les fichiers
    (`Directory.list`) serait la probe que ADR-022 a supprimée.
  - `readingPositions` compte les LIGNES, donc les chapitres ouverts. Une
    position peut être à 0 et la ligne existe : c'est une position legitimate.
    ⚠️ Ne pas compter `offset > 0`.

  ⚠️ LE PREMIER CHIFFRE EST `in_library = 1`, PAS COUNT(*).
  Un roman retiré de la bibliothèque reste en base — B32 garde ses chapitres
  téléchargés, et `2-5` ne supprime pas la ligne. Compter `COUNT(*)` afficherait
  « 15 romans » là où la bibliothèque en contient 3, et c'est un chiffre que le
  lecteur compare avant et après une mise à jour : il doit vouloir dire
  « combien de romans je garde ».
```

**Les quatre rendus de la rangée, et ils sont distincts :**

| Situation | Rendu | Règle |
|---|---|---|
| Les trois résolvent, dont des zéros | `14 · 512 · 638` | `settings-about.md` § 4 *Empty — no data* : les trois chiffres lisent **`0 · 0 · 0`**, « set exactly like the non-zero case », **pas** d'`EmptyState`, pas d'illustration, pas d'appel à l'action |
| Un seul échoue | deux chiffres et **un** `—`, et le `DataBlock` **reste** | `settings-about.md` § 8 : la ligne est omise avec `—`, **jamais `0`** |
| Les trois échouent | `— · — · —` | idem |
| Le bloc est en cours de chargement | `LoadingState` **à la forme du contenu remplacé** : des barres `--color-surface-sunken` de la largeur du chiffre qu'elles vont devenir, avec un shimmer, **pas de spinner centré** | `design-system.md` § 2.7 |

⚠️ **`LoadingState` ne doit masquer que les chiffres.** `settings-about.md` § 4
Loading : *Every other block renders fully and immediately, including the whole
privacy block — a privacy statement must never be waiting on a query.* Le bloc de
confidentialité s'affiche **avant** les chiffres, et il est complet dès la
première image.

### 3.5 Les neuf états de l'écran, et leurs quatre qui n'ont rien à rendre

`settings-about.md` § 4 décrit **neuf** états. Deux ne sont pas des états de cette
slice, un l'est malgré lui, et les six autres sont chacun un rendu distinct :

| État | Cette slice | Rendu |
|---|---|---|
| **Loading** | oui | `AboutIdentity` + `PrivacyBlock` + `DeliveryBlock` **immédiats et complets** ; seuls les trois chiffres sont des squelettes à leur forme. `settings-about.md` § 4 : le bloc de confidentialité apparaît **avant** les chiffres, « the claims are static, and only the numbers are not » |
| **Filled** | oui | les six blocs |
| **Empty — never visited** | **non applicable** | Cet état signifie « le lecteur n'a jamais tapé Check for a new version ». Comme ce contrôle n'est pas dans cette slice (§ 7), l'état **n'existe pas** et il n'a rien à rendre |
| **Empty — no data** | oui | `0 · 0 · 0`, **rendus exactement comme les non-zéro**. `settings-about.md` § 4 : *A real zero, shown as a zero.* |
| **Load error** | oui | une ligne `--color-error` à `--text-body-sm` là où serait la version ; **le reste de l'écran rend entièrement**. Test nommé `the version line reports unreadable and everything else still renders` |
| **Submit error** | **non** | Il n'y a aucune soumission sur cette slice — pas de vérification de version, pas de téléchargement. `reader.md` § 4 applique le même raisonnement pour dire « n/a » |
| **Success** | **non** | Idem : aucune opération n'aboutit dans un état. La copie produit un SnackBar, pas un état d'écran |
| **Offline / permissions** | oui | **Identique à Filled.** Aucune de ces données n'est distante. Et **aucune permission n'est jamais demandée** : `settings-about.md` § 4 : *Installing an APK hands off to the **OS install flow**, and the OS prompts; the app asks for nothing* — et il n'y a même pas d'install dans cette slice |
| **Read-only** | oui | Les trois chiffres sont du **texte** : ni chevron, ni ripple, ni état pressé, ni icône de tête. `settings-about.md` § 4 : *They are evidence, and evidence that responds to a tap is not evidence* |

**Ce qui n'a pas de rendu et pourquoi :** un état vide fait sur un écran fait de
déclarations serait une page d'attente, et une confirmation de copie qui
persisterait interromptrait le seul moment où le lecteur lit ce que
l'application fait de ses données. `settings-about.md` § 4 Success : *a claim that
fades is a claim that was not made*.

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| Nom et numéro de version | application | **deux constantes de compilation** | au build, par `apk-pipeline` | **jamais** pendant l'exécution |
| Trois chiffres | écran | `COUNT(*)` drift, en mémoire | à l'ouverture de l'écran | **jamais** — l'écran n'écrit rien |
| Copie en cours | écran | `bool`, dans le `State` | au appui | au retour du presse-papiers |
| Blocs statiques | application | **une constante par chaîne ARB** | à la compilation | **jamais** |

**Ce qui n'est délibérément pas de l'état** : le texte de version. Il n'est ni
écrit en base, ni mis en `shared_preferences`, ni lu depuis un paquet installé. Il
est compilé dans le binaire, ce qui est **la seule façon** qu'il corresponde à ce
qui est réellement installé — un `String` mémorisé pourrait dater d'une version
antérieure et affirmer un numéro faux, ce que **C9** interdit.

**Ce qui n'est pas de l'état non plus** : les « seven things never sent ». Ce sont
des chaînes constantes dans l'ARB. Une liste de « choses que nous ne faisons
jamais » stockée quelque part serait, à la prochaine mise à jour, une liste que
quelqu'un pourrait étendre sans relire l'écran.

**Ce qui n'est pas de l'état non plus** : le total d'espace utilisé, le nombre de
requêtes, un horodatage de dernière ouverture. `settings-about.md` § 11 les écarte
explicitement, et § 10 ajoute une règle qu'il faut écrire dans le code :

```
⚠️ AUCUN CHIFFRE DE CET ÉCRAN N'EST DÉCLARÉ DANS LE CODE.
   § 10 : « Figures on this screen are rendered from the device, never declared.
   14, 512 and 638 are format exemplars in this document; there is no hard-coded
   count anywhere in the app, because a fixed number on a screen whose entire job
   is to be evidence would be the worst possible defect. »

   ⇔ « 14 · 512 · 638 » dans ce plan est un EXEMPLE DE FORME, comme dans l'écran.
      Il n'apparaît nulle part dans `lib/` comme une valeur.
```

## 7. Pièges à éviter

- **⚠️ Ne pas écrire la version en dur dans le Dart.** Le comportement correct
  (**B43**, **C9**, ADR-011) est `String.fromEnvironment`, alimenté par
  `apk-pipeline` depuis `pubspec.yaml`. Une constante comme `'1.0.0'` dans le code
  devient fausse à la première release sans que rien ne le signale — et c'est
  précisément la seule information que cet écran a pour métier.
- **⚠️ Ne pas afficher `Version —` quand la version est illisible.** Le
  comportement correct (`settings-about.md` § 4, **C9**) est la phrase
  `about.versionUnreadable`. Un tiret cadratin **ressemble à une version**, et le
  propriétaire doit pouvoir dire à quelqu'un laquelle il a. Le tiret est
  réservé aux **comptes** échoués, où il dit « on ne sait pas » et où le lecteur
  n'a rien à comparer à travers une mise à jour.
- **⚠️ Ne pas afficher `0` quand la requête de compte échoue.** Le comportement
  correct (`settings-about.md` § 8) est `—` / `data.countUnavailable`. Un `0`
  est une **affirmation** sur le téléphone ; une requête échouée est une absence de
  connaissance. C'est la leçon de **B48** appliquée telle quelle.
- **⚠️ Ne pas compter `COUNT(*)` sur `novels` pour le premier chiffre.** Le
  comportement correct (`2-5`, **B32**) est `WHERE in_library = 1`. Un roman
  retiré reste en base avec ses chapitres téléchargés, et le chiffre doit dire
  « combien de romans je garde ».
- **⚠️ Ne pas compter les fichiers pour le deuxième chiffre.** Le comportement
  correct (**B6**, ADR-022) est `COUNT(*) WHERE downloaded_at IS NOT NULL`. La
  marque est écrite **après** le renommage atomique, donc elle est la seule
  preuve qu'un chapitre est complet ; sonder le disque est la probe qu'ADR-022 a
  supprimée parce qu'elle ne peut pas distinguer « effacé volontairement » de
  « fichier perdu ».
- **⚠️ Ne pas compter les positions non nulles.** Le comportement correct est
  `COUNT(*)` sur `reading_positions`. Une position à `0` est une position
  légitime — le lecteur a ouvert le chapitre, n'a pas défilé, et l'a refermé.
- **⚠️ Ne pas déclarer un chiffre dans le code.** Le comportement correct
  (`settings-about.md` § 10) est que les trois chiffres viennent de la base. Un
  nombre fixe sur un écran dont tout le métier est d'être une preuve serait le
  plus mauvais défaut possible.
- **⚠️ Ne pas rendre les trois chiffres cliquables.** Le comportement correct
  (`settings-about.md` § 4 Read-only) est : ni chevron, ni ripple, ni état pressé,
  ni icône de tête. *Evidence that responds to a tap is not evidence.*
- **⚠️ Ne pas mettre les trois chiffres dans un `StatusChip`.** Le comportement
  correct (`settings-about.md` § 3, `design-system.md` § 2.5) est du texte dans un
  `DataBlock` : un chip est le porteur des comptes que l'application tient sur des
  **romans et des chapitres** (**B48**, **B49**), et une chip impliquerait un
  statut — ces trois chiffres sont des faits de stockage sur l'installation.
- **⚠️ Ne pas faire attendre la déclaration de confidentialité derrière une
  requête.** Le comportement correct (`settings-about.md` § 4 Loading) est : les
  blocs statiques rendent **entièrement et immédiatement**, seuls les chiffres
  sont des squelettes. *A privacy statement must never be waiting on a query.*
- **⚠️ Ne pas mettre d'icône dans un cercle, ni de carte ombrée.** Le
  comportement correct (`settings-about.md` § 2.1) est : six blocs
  `--shadow-none` séparés par `--space-2xl`, aucune ombre sauf sur le snackbar.
- **⚠️ Ne pas centrer la page.** Le comportement correct (`settings-about.md` § 2.1)
  est un alignement à gauche. Le seul alignement à droite est la rangée des trois
  chiffres — et ils sont alignés **à gauche à l'intérieur** de cette rangée.
- **⚠️ Ne pas ajouter de lien « politique de confidentialité ».** Le comportement
  correct (**B4**, `settings-about.md` § 11) est : il n'y a pas d'entité opératrice,
  donc il n'y a pas de politique à publier. Un lien vers un document qui n'existe
  pas est la même faute que `source-unavailable` présentant une liste vide.
- **⚠️ Ne pas ajouter de bouton « effacer le cache » ou de total d'espace.** Le
  comportement correct (`settings-about.md` § 11) est : cet écran dit **ce qui est
  préservé** ; il ne propose pas de le détruire.
- **⚠️ Ne pas mettre d'alerte « plus de données disponibles » ni de
  gamification.** Le comportement correct (`design-system.md` § 0
  anti-références) est : aucune scoreuse, aucun « lu cette semaine », aucune
  célébration. « Vous avez tout lu » ne se fête pas.
- **⚠️ Ne pas demander de permission.** Le comportement correct
  (`settings-about.md` § 4) est : cette écran n'en demande aucune et n'en a
  aucune à demander. Il n'y a ni compte (**B4**), ni fichier, ni stockage, ni
  notification.

**Deux questions ouvertes. Elles ne sont pas des détails d'implémentation.**

1. **`settings-about.md` § 1 note une divergence non résolue sur le module.**
   L'écran déclare `module: more` dans son front matter mais `Route:
   /browse/:sourceId/unavailable` dans sa propre § 1 pour l'écran *source
   unavailable* — et il écrit : *Recorded rather than silently resolved: the route
   placement is what the reader's back stack and the deep link need, and the module
   grouping is a registry question. **Resolution belongs to Phase 4**; neither
   value is changed here.* Pour `settings-about` lui-même il n'y a pas de
   divergence : `module: more`, `Route: /more/settings/about`. **Ce plan suit la
   route de `design-system.md` § 3.5**, qui est cohérente avec le shell.
   **Question ouverte** : aucune action n'est requise ici ; elle est signalée
   parce qu'elle existe dans le même document que l'écran.
2. **Le bloc de mise à jour de l'écran n'a aucune slice.** `settings-about.md`
   § 3 spécifie `UpdateBlock` en entier : une action *Check for a new version*, un
   `GET` d'un fichier de métadonnées publié par la CI, un téléchargement d'APK
   **atomique**, et une remise au flux d'installation de l'OS. `3-5` a pour unique
   règle **B43**, et `state.json` lui donne `depended_on_by: []`. Le bloc est
   donc **absent** de cette slice — ce qui laisse l'écran dans l'état *Empty —
   never visited* de façon permanente, et c'est un état cohérent
   (`settings-about.md` § 4 : *The `UpdateBlock` is **absent** — not greyed, not
   empty, not showing "up to date"*).
   **Mais il faut le dire** : cette absence n'est pas une conséquence de
   B43, c'est un **trou de découpage**. Un `GET` de plus et une installation
   d'APK sont du travail réel, et personne ne le porte.
   **Option la moins coûteuse et réversible** : ne rien construire, et laisser
   l'écran tel que § 3.3 le décrit ici — un écran de(version, chiffres,
   confidentialité, livraison), honnête et complet sur ce qu'il affirme.
   **Question ouverte** : faut-il créer une slice pour le flux de mise à jour, ou
   rattacher `UpdateBlock` à `3-5` avec `apk-pipeline` comme dépendance de
   données — et dans ce cas, quel est le périmètre de `apk-pipeline` côté client
   plutôt que côté CI ?
