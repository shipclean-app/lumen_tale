## 1. Résumé de la slice

`3-1` rend **le catalogue d'une source** : la liste des romans qu'un site publie
sous un tag, ou sous les mots du lecteur quand le site sait chercher.

C'est l'écran sur lequel **B22** se joue, et donc **SC-6**. Le contrat `BrowseOutcome`
(`architecture.md` § 2.2) est une **union scellée à trois états** et la seule chose
que cet écran consomme. Aucune méthode ne renvoie une liste nue et aucun appelant ne
décide à la place : `BrowseSucceeded` avec zéro élément, `BrowseEmpty` et
`BrowseFailed` sont trois valeurs que le compilateur oblige à traiter séparément.

Le cœur de la slice n'est donc pas la liste — c'est **la cartographie exhaustive de
`BrowseOutcome` vers des formes d'écran visuellement séparées**, dont **trois** états
d'échec distincts qui ne doivent jamais rendre la même phrase : le site illisible,
l'absence de connexion, et le site qui déclare lui-même ne rien avoir.

**Aucun tri calculé par l'application, aucun filtre au-delà du tag, aucun numéro de
page.** `design-system.md` § 4.2 déclare une grille de résultats à **deux colonnes
partout**, et c'est `NovelRow` variante `result` qui fait le travail qu'une grille
ferait, à 64dp.

**User stories couvertes** : US-01 (parcourir un site), US-16 (être prévenu qu'un site ne fonctionne plus)
**Règles métier couvertes** : B5, B22, B24
**Edge cases couverts** : E1, E2, E4, E5, E8
**Contraintes couvertes** : C7, C11, C12, SC-6

```dart
// lib/domain/sources/browse_outcome.dart — PRODUIT par failure-discriminator,
// CONSOMMÉ par cette slice. Ne pas le redéfinir ici ; le recopier serait une
// deuxième définition de B22, donc exactement la seconde source de vérité que
// B22 interdit.
import 'package:lumen_tale/core/error/source_failure.dart';

/// `architecture.md` § 2.2 — le contrat à trois états.
///
/// **Rien de plus n'est autorisé.** Ni `null`, ni `BrowseSucceeded(items: [])`
/// après un `catch`, ni un `bool isEmpty` : les trois rétrécissent la distinction
/// de B22, et B22 est SC-6.
sealed class BrowseOutcome<T> {
  const BrowseOutcome();
}

/// Le site a été lu. `items` peut légitimement être vide.
final class BrowseSucceeded<T> extends BrowseOutcome<T> {
  const BrowseSucceeded(this.items);
  final List<T> items;
}

/// Le site n'a pas pu être lu. `reason` est **typé**, jamais une chaîne (B24).
final class BrowseFailed<T> extends BrowseOutcome<T> {
  const BrowseFailed(this.reason, {required this.retriable});
  final SourceFailure reason;
  final bool retriable;
}

/// Lu, et il n'y a vraiment rien — distinct de l'échec, et disponible
/// **seulement là où le site fournit son propre signal** (`architecture.md` § 2.2).
final class BrowseEmpty<T> extends BrowseOutcome<T> {
  const BrowseEmpty(this.siteSuppliedSignal);
  final String? siteSuppliedSignal;
}

/// Une page de catalogue, telle que `2-1` la rend.
final class NovelsPage {
  const NovelsPage({
    required this.items,
    required this.page,
    required this.hasMore,
  });

  /// Dans l'ordre du site. **Aucun tri appliqué par l'application** : le tri du
  /// site est le sien, et l'exposer demanderait d'interpréter ses segments.
  final List<Novel> items;

  /// L'index **du site**, dans sa propre base. FanMTL est en base 0 ; le lecteur
  /// ne voit jamais ce nombre (`browse-catalogue.md` § 8).
  final int page;

  /// Le signal de pagination **du site**. Son absence avec une page pleine
  /// signifie « pas de pied de liste » : l'application n'invente jamais la fin
  /// d'une liste qu'elle n'a pas atteinte.
  final bool hasMore;
}
```

```dart
// lib/domain/sources/models/novel.dart
/// Le roman tel que le site le publie. **Ce que le site dit, pas ce que l'app
/// décide** : le titre est verbatim, l'URL est relative (`03-source-system.md`
/// règle 3), et `coverUrl` est nullable parce que le site peut ne pas publier de
/// couverture.
@freezed
class Novel with _$Novel {
  const factory Novel({
    /// B3 — MD5, stable entre sessions. Jamais écrit à la main.
    required String id,

    /// B2 — le site d'origine. Jamais déduit du titre.
    required String sourceId,

    /// B10 — le titre tel que le site le présente. Jamais normalisé, jamais
    /// réécrit. Deux titres identiques sont deux romans.
    required String title,

    /// ADR-024 — affiché, jamais cherché. Absent quand le site n'en publie pas :
    /// la ligne rend alors une sous-ligne vide, **pas** un tiret, qui se lirait
    /// comme un auteur nommé « — ».
    String? author,

    /// Null signifie « ce roman n'a pas de couverture », pas « nous avons échoué ».
    String? coverUrl,

    /// Relatif (chemin + requête), jamais une URL complète : les hôtes changent,
    /// une URL absolue stockée casse en silence.
    required String url,
  }) = _Novel;
}
```

```dart
// lib/features/browse/catalogue_view_state.dart
import 'package:lumen_tale/core/error/source_failure.dart';
import 'package:lumen_tale/domain/sources/models/novel.dart';

/// L'état de vue de `/browse/:sourceId/genre/:genre`.
///
/// **Six variantes, pas un `AsyncValue` à trois cas.** `AsyncValue` ne peut pas
/// distinguer *chargement* de *vide-sincère* ni *site-illisible* de
/// *pas-de-connexion*, et les trois distinctions sont B22. Le mappage est
/// exhaustif et exhaustif **doit** le rester : ajouter une variante à
/// `BrowseOutcome` casse ce `switch` à la compilation, ce qui est exactement la
/// propriété voulue.
sealed class CatalogueViewState {
  const CatalogueViewState();
}

/// `LoadingState` en forme de ligne : six squelettes de `NovelRow` `result`.
final class CatalogueLoading extends CatalogueViewState {
  const CatalogueLoading();
}

/// La page a été lue et porte des lignes.
final class CatalogueFilled extends CatalogueViewState {
  const CatalogueFilled({
    required this.items,
    required this.page,
    required this.hasMore,
    required this.isAppendingPage,
  });
  final List<Novel> items;
  final int page;
  final bool hasMore;

  /// Le pied de liste remplace sa légende par **trois** squelettes pendant
  /// l'append. La liste que le lecteur lit reste à l'écran : c'est un état
  /// distinct de `CatalogueLoading` parce que l'écran est *utilisable* ici.
  final bool isAppendingPage;
}

/// **Le genre est sincèrement vide.** Centré, calme, **aucune icône**, aucune
/// couleur d'erreur, **aucun réessayer** : rien n'a échoué, et un réessayer
/// serait un aveu d'échec.
final class CatalogueEmptyTag extends CatalogueViewState {
  const CatalogueEmptyTag({required this.sourceName, required this.tag});
  final String sourceName;
  final String tag;
}

/// **Le site n'a pas pu être lu.** Ancré en haut sous la barre de titre, aligné à
/// gauche, icône `--color-error`, `secondary` **Vérifier à nouveau**, et une
/// phrase qui dit ce qui est intact. C'est la forme que SC-6 vérifie.
final class CatalogueSourceUnreadable extends CatalogueViewState {
  const CatalogueSourceUnreadable({
    required this.sourceName,
    required this.tag,
    required this.failure,
  });
  final String sourceName;
  final String tag;
  final SourceFailure failure;
}

/// **Pas de connexion.** Forme distincte du précédent : même ancrage, icône
/// d'erreur, mais le corps nomme la connexion et **non** le site — parce que rien
/// n'a échoué du côté du site (E5, B23).
final class CatalogueNoConnection extends CatalogueViewState {
  const CatalogueNoConnection({required this.sourceName});
  final String sourceName;
}

/// Une source **sans couverture** : le lecteur a ajouté un roman pendant que le
 * catalogue était affiché. `3-2`/`2-5` ne peuvent pas écrire dans l'état de vue,
 * donc le retour passe par l'invalidation du provider et cet état laisse le
 * `Filled` inchangé.
final class CatalogueLoadingFirstPage extends CatalogueViewState {
  const CatalogueLoadingFirstPage();
}
```

```dart
// lib/features/browse/catalogue_controller.dart
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:lumen_tale/domain/sources/browse_outcome.dart';

/// Contrôleur de l'écran catalogue. **`autoDispose`** : c'est un état d'écran, et
/// la règle 10 de `05-state-management.md` dit qu'un état d'écran se libère au
/// pop. Une exception à justifier par écrit.
@Riverpod
class CatalogueController extends _$CatalogueController {
  @override
  Future<BrowseOutcome<NovelsPage>> build({
    required String sourceId,
    String? genre,
    required Scope scope,
  }) {
    return switch (scope) {
      CatalogueScope.popular => ref
          .watch(browseRepositoryProvider)
          .popularNovels(sourceId: sourceId, genre: genre, page: 1),
      CatalogueScope.latest => ref
          .watch(browseRepositoryProvider)
          .latestNovels(sourceId: sourceId, genre: genre, page: 1),
    };
  }

  /// B5 — « Vérifier à nouveau » est **une** nouvelle requête, parce que le
  /// lecteur l'a demandée. Il n'y a pas de boucle de réessai.
  Future<void> retry() async {
    state = const AsyncLoading<BrowseOutcome<NovelsPage>>();
    state = await AsyncValue.guard(
      () => ref.read(browseRepositoryProviderProvider.notifier).refresh(),
    );
  }

  /// Le défilement jusqu'au pied de la liste est un **déclencheur demandé** :
  /// B5 interdit le fond spéculatif, pas la pagination explicite. Le seuil est
  ///.crossing trois lignes, et il ne déclenche qu'une seule requête à la fois.
  Future<void> loadNextPage() async {
    final current = state.value;
    if (current is! BrowseSucceeded) return;
    final page = current.items;
    if (page.isEmpty) return;
    final lastPage = page.length; // le contrôleur connaît la page courante
    state = await AsyncValue.guard(
      () => ref.read(browseRepositoryProviderProvider.notifier).page(lastPage + 1),
    );
  }
}

/// Les deux modes du contrôleur. **Ce n'est pas un `bool`** : un `bool` ferait de
/// `popular` la valeur `false` implicite, et la branche forgettable est celle qui
/// devient un défaut.
enum CatalogueScope { popular, latest }
```

## 3. Algorithmes critiques

> **`browse-catalogue.md` § 4 déclare neuf états. Les neuf sont écrits ici**, avec
> le rendu et la branche qui les produit. C'est la partie de ce plan qu'un
> implémenteur ne doit pas pouvoir raccourcir.

### 3.1 Le mappage `BrowseOutcome` → état de vue (couvre **B22**, SC-6)

C'est l'algorithme central. Il est **total** : les trois bras de la séaled class
apparaissent, et `AsyncValue` ajoute le quatrième cas.

```
map(outcome, sourceName, tag):
  case AsyncError:
    # 4e chemin — la Futures a levé. Le contrôleur l'a déjà enveloppée, donc
    # le catch de `AsyncValue.guard` l'a transformée en SourceFailure typée.
    return CatalogueNoConnection(sourceName)     # voir § 3.6 pour l'indirection
    # ⚠️ JAMAIS `CatalogueEmptyTag`. Jamais. C'est exactement la confusion que
    #   B22 existe pour empêcher, et elle est tentante parce qu'elle est simple.

  case AsyncData(BrowseSucceeded(page)):
    if page.items.isEmpty:
      # ── BRANCHE « VIDE » ──────────────────────────────────────────────
      # ⚠️ LE DISCRIMINATEUR EST LA FORME DE LA PAGE, PAS UNE CHAINE.
      # FanMTL porte la chaîne littérale « No relevant content found » sur sa
      # PAGE D'ÉCHEC DE RECHERCHE. Cette chaîne discriminante est donc
      # multiquery, et ne s'applique pas à un tag.
      # Un tag vide est vide parce qu'il n'y a pas de romans dedans, et l'état
      # le dit EXACTEMENT cela.
      # ⚠️ UNE PAGE VIDE SUR UNE PAGE > 1 EST UN ÉCHEC, PAS UN VIDE.
      #   « Aucun résultat » ne se dit jamais de la deuxième page d'un tag qui
      #   en avait trente : cela effacerait la moitié de la liste devant le
      #   lecteur. → c'est le test de la ligne 2 du tableau de § 3.2.
      if page.page <= 1:
        return CatalogueEmptyTag(sourceName: sourceName, tag: tag)
      else:
        return CatalogueSourceUnreadable(
          sourceName: sourceName, tag: tag,
          failure: SourceFailure.sourceLayoutChanged('...'))
        #   ↑ ⚠️ UNE PAGE VIDE EN PAGE 2+ EST LE SIGNE EXACT DU DÉFAUT DE
        #     DISPOSITION DE `fanmtl-broken-layout.html`. La page répond 200,
        #   elle est bien formée, et le parseur n'y trouve rien.

  case AsyncData(BrowseEmpty(signal)):
    # `BrowseEmpty` n'est atteignable QUE là où le site fournit son propre
    # signal. FanMTL : mesuré, le signal est sur la page d'échec de recherche,
    # donc disponible UNIQUEMENT pour searchNovels → `6-2`, qui est
    # conditionnelle. Pour un TAG, cette branche est du code mort today.
    return CatalogueEmptyTag(sourceName: sourceName, tag: tag)

  case AsyncData(BrowseFailed(reason, retriable)):
    return CatalogueSourceUnreadable(
      sourceName: sourceName, tag: tag, failure: reason)
    # ⚠️ AUCUNE ÉCRITURE, AUCUN PIED DE LISTE, AUCUN « 0 ».
    # `browse-catalogue.md` § 4 : « Zéro ligne de roman n'est rendue, et la page
    # ne défile pas ». Une ligne de centimes sous l'état d'erreur serait
    # exactement « un catalogue vide présenté comme une réponse ».

  case AsyncLoading:
    return CatalogueLoading()
```

**Les six branches, toutes explicites :**

| Situation | Ce qui se passe | Pourquoi c'est correct |
|---|---|---|
| La Futures a levé (`AsyncError`) | `CatalogueNoConnection` | E5 : c'est un fait sur la connexion, pas sur le site. La forme est celle du hors-ligne de `browse-catalogue.md` § 4 |
| Page 1 avec des lignes | `CatalogueFilled` | Le cas normal |
| Page 1 sans ligne | `CatalogueEmptyTag` — **centré, calme, sans icône** | Un tag vide est un fait sur le site, pas une panne. Et pas de réessayer |
| Page 1 sans ligne, `BrowseEmpty` | `CatalogueEmptyTag` | Le site déclare lui-même ; même rendu, parce que la même phrase est honnête dans les deux cas |
| Page ≥ 2 sans ligne | `CatalogueSourceUnreadable` | `BrowseEmpty` est impossible ici : une source ne déclare pas « rien » au milieu d'un flux. Une page vide en position 2 **est** un défaut de disposition |
| `BrowseFailed` | `CatalogueSourceUnreadable` avec `reason` | B22, E4, E8 |
| `BrowseFailed` sur page ≥ 2 | **On conserve les lignes déjà rendues** et on affiche le pied d'erreur sous la liste, **pas** à sa place | Remplacer quarante lignes par une page d'erreur pour une panne de la page suivante serait une perte que B22 ne demande pas et que B24 interdit : « no action fails silently to a blank screen » |

**Pourquoi cette divergence mécanique et pas seulement verbale :** `ErrorState` et
`EmptyState` sont tous deux « une phrase et une action ». Échanger un mot entre les
deux est la façon bon marché de satisfaire B22 — et c'est **exactement pour cela que
c'est faux** : à un lecteur qui balaie du regard, une phrase calme centrée et une
phrase rouge ancrée en haut avec un bouton rempli sont la **même catégorie de
chose**. B22 est une règle sur ce que le lecteur doit pouvoir **distinguer**. Un
lecteur qui a vu les deux une fois les distingue de l'autre côté d'une pièce, la
couleur retirée.

### 3.3 Le catalogue en deux colonnes, et pourquoi pas une de plus

`design-system.md` § 4.2 déclare `Result grid` — **2 colonnes, cellules 96dp,
écart `--space-md`** — et sa règle : *« Le nombre de colonnes ne change pas avec la
largeur. »*

```
AU-DESSOUS DE 600dp : 2 colonnes, cellules 96dp, écart 12dp.
AU-DESSUS  DE 600dp : 2 colonnes, cellules 96dp, écart 12dp, ET C'EST TOUT.
                     La grille se centre, elle ne s'élargit pas.

⚠️ UNE GRILLE QUI GAGNE UNE COLONNE EST LA GRILLE QUI FAIT CHERCHER LE LECTEUR :
   le même roman se retrouve ailleurs sur une tablette. ADR-019 exclut la
   disposition tablette ; `design-system.md` § 1.7 déclare < 600dp « le seul
   layout que v1 livre ».
```

**La forme de rendu dans le code :** `NovelRow` variante **`result`** (64dp,
couverture 40dp, titre + auteur, pas de ligne d'état) dans une colonne de largeur
fixe de 96dp, `Wrap` de deux éléments ou `GridView` à `crossAxisCount: 2` — **le
deux est interdit** parce qu'un `GridView` reconstruit ses enfants au défilement
alors qu'un `Wrap` dans une colonne `SingleChildScrollView` ne construit que ce qui
est là. La version choisie est **une `Column` défilante contenant un `Wrap`** : c'est ce qui
satisfait `15-performance.md` § Listes « les éléments de liste doivent être bon
marché », sans mesure préalable.

> **Note d'implémentation** : le choix `Wrap` contre `GridView` est une décision
> d'implémentation, pas de design — les deux rendent deux colonnes de 96dp. Elle est
> nommée ici pour qu'elle ne soit pas prise deux fois, et pour que le passage à
> `GridView` soit une décision consciente si la mesure le justifie un jour.

### 3.4 Pagination, et la branche qui ressemble à un bug (couvre **E1**)

```
onScrollReached(pixelsRemaining, controller):
  if pixelsRemaining > 3 * rowHeight: return          # jamais en avance
  if currentState is CatalogueFilled:
    if currentState.isAppendingPage: return           # ⛔ UN SEUL EN VOL
    if not currentState.hasMore:
      return                                          # pas de « page suivante »
    # Pas de spinner. Pas de bouton « charger plus ». Le pied de liste
    # remplace sa légende par trois squelettes en forme de ligne pendant que
    # la page arrive : la liste que le lecteur est en train de lire reste à
    # l'écran.
    await controller.loadNextPage()                    # B5 : la demande est visible
```

**Chaque branche :**

| Situation | Ce qui se passe | Pourquoi |
|---|---|---|
| Le lecteur n'est pas encore au pied | rien | Pas de fond spéculatif. B5 |
| Le pied est atteint, une requête est déjà en vol | **rien** — la seconde frappe est ignorée | Trois pages qui se chevauchent enverraient trois requêtes et enverraient les trois réponses dans un ordre inconnu. C'est la seule sous-protection acceptable ici, et elle est explicite |
| `hasMore` est vrai | append de la page suivante, trois squelettes au pied | B5 |
| `hasMore` est faux | **rien ne se passe** | L'application n'invente jamais la fin d'une liste qu'elle n'a pas atteinte |
| La page suivante échoue | **les lignes déjà rendues restent**, et le pied affiche `CatalogueSourceUnreadable` compact (titre + **Vérifier à nouveau**) | B24. Remplacer quarante lignes par une page d'erreur serait la perte que « no action fails silently to a blank screen » interdit |
| La page suivante renvoie **zéro** ligne | `CatalogueSourceUnreadable`, `downloadedAt` inchangé, **aucune** ligne retirée | Une liste tronquée est un mensonge de plus que la moitié d'une liste |

### 3.5 Le filtre B50 — quand le champ de recherche existe ou non

```
buildScreen(source, genre, q):
  isSearchMode = q != null
  searchField = isSearchMode AND source.supportsSearch
  # ⚠️ `supportsSearch` est une PROMESSE DÉCLARÉE, mesurée (ADR-015).
  #   Le 2026-10-02, FanMTL : `false` — sa recherche renvoie 404 avec un
  #   meta-refresh pour TOUTE requête, y compris une qui devrait matcher.
  #   Donc `browse-genre.md` porte l'énoncé `search-unsupported` et cet écran
  #   ne rend AUCUN champ pour FanMTL.
  # ⚠️ SI supportsSearch == true ET le site ne renvoie rien d'utile :
  #   c'est une SOURCE CASSÉE (BrowseFailed), jamais « aucun résultat ».
  #   B50 le dit, et c'est aussi E4.
  #
  # `6-2` est CONDITIONNELLE : elle ne se construit pas avant que `6-11` ait
  # mesuré. Cette slice ne construit donc que le MODE CATALOGUE, et la branche
  # « mode résultats » est écrite ici pour être complète, pas pour être
  # implémentée tout de suite.
```

| Situation | Ce qui se passe | Pourquoi c'est correct |
|---|---|---|
| `supportsSearch == false` | **Aucun champ.** Pas désactivé, pas grisé : absent. `browse-genre` porte l'énoncé `search-unsupported` et propose les genres | B50, ADR-015 |
| `supportsSearch == true`, `q == null` | Mode catalogue : aucun champ rendu | `browse-catalogue.md` § 1.1 : le champ est une conséquence du mode résultats |
| `supportsSearch == true`, `q != null` | Champ rendu **en haut de la zone de contenu**, collant au défilement, et **utilisable pendant** que la liste charge | Le champ est l'entrée du lecteur ; le bloquer derrière le réseau serait à l'envers |
| Le site déclare la recherche et renvoie une page vide | `CatalogueSourceUnreadable`, **jamais** `CatalogueEmptyTag` | B50 : « une source qui déclare la recherche et ne renvoie rien est traitée comme une source cassée » |
| La requête du lecteur est échappée pour l'URL | **Jamais** — `q` va dans le state et dans la requête, pas dans le chemin | Le chemin est un segment d'URL ; une chaîne lue à voix haute par un lecteur borrowed-device ne va pas dans une barre d'adresse |

### 3.6 Ce que cet écran ne peut pas distinguer (couvre **E5**, **C12**)

La distinction que cet écran **ne peut pas** faire, et qu'il doit dire.

```
CatalogueNoConnection déclenché quand :
  - AsyncError de SourceException dont reason.type == noConnection
  - OU le SourceFailure est noConnection venant de fetchChapterContent

⚠️ CE QUE L'APPLICATION NE PEUT PAS DISTINGUER, ET QU'ELLE DIT À L'ÉCRAN :
  « pas de connexion » de « le réseau passe, le site refuse ». Le second est
  un BrowseFailed avec SourceFailure.rateLimited(status, retryAfter), et il
  rend la MÊME forme — mais avec un corps différent, qui nomme le délai.

  Ce n'est pas une weakness de l'écran : c'est la limite de la télémétrie. C2
  interdit toute télémétrie, donc l'application ne saura JAMAIS pourquoi un
  site a renvoyé 503. Elle le rapporte donc tel quel, et C12 exige que le
  lecteur puisse le dire à voix haute.
```

| Situation | Forme | Corps |
|---|---|---|
| `noConnection` | `CatalogueNoConnection` | *Pas de connexion. Rien ne va mal avec FanMTL.* + `secondary` **Vérifier à nouveau** + `ghost` **Ouvrir votre bibliothèque** |
| `rateLimited(status, retryAfter)` | `CatalogueSourceUnreadable` | *FanMTL demande au lecteur de patienter. Réessayez dans 30 secondes.* (la durée vient du champ typé, pas d'un compteur local) |
| `sourceLayoutChanged(selector)` | `CatalogueSourceUnreadable` | *Les pages de FanMTL ont probablement changé.* + la légende C12 qui nomme le tag |
| `sourceUnavailable(status)` | `CatalogueSourceUnreadable` | *FanMTL ne répond pas (503).* + **Vérifier à nouveau** |
| `itemRemovedAtSource(url)` | `CatalogueSourceUnreadable` | *Ce roman n'est plus à FanMTL.* + **Retour** ; le reste du site n'est pas affecté (E9) |
| `parseFailed(path)` | `CatalogueSourceUnreadable` | *La réponse de FanMTL n'a pas pu être lue.* |

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| La page courante | écran | mémoire, dans le `AsyncValue` du contrôleur | `build()`, une seule requête par navigation | `retry()`, `loadNextPage()` |
| La page suivante en vol | écran | un `bool` `isAppendingPage`, **pas** une seconde liste | `loadNextPage()` | retour du `Future` |
| `q` (requête) | écran | **l'état du shell** `go_router`, survit au changement d'onglet | navigation | soumission du champ |
| `inLibrary` par ligne | base | colonne `novels.in_library` | `3-1` a déjà upserté les lignes qu'il affiche | `2-5` écrit, puis **invalidation** |
| Couverture d'une ligne | disque / réseau | cache de `cached_network_image` sous `covers/` | rendu | jamais explicitement invalidée |
| Le catalogue lui-même | — | **jamais persisté** | — | — |

**Ce qui n'est délibérément pas de l'état :** la liste des romans affichés. Elle est
dérivée de la page courante, et une copie dans le state serait une liste qui peut
diverger de la requête qui l'a produite. `AsyncValue` la détient déjà.

**Ce qui n'est délibérément pas de l'état :** le texte de la requête du lecteur.
`browse-catalogue.md` § 8 : « la requête n'est jamais persistée, jamais journalisée,
et ne quitte l'appareil que comme la requête que le lecteur a demandée ». Elle vit
dans le `TextField` (éphémère) et dans l'URL comme `q` du shell, et c'est tout.

## 6. Traçabilité des règles

### 6.1 Règles métier (B*)

| ID | Règle (PRD, texte intégral) | Implémentée où | Approche |
|---|---|---|---|
| **B5** | *« Nothing is fetched from a site unless the user asked for it. There is no bulk or speculative background fetching of chapter content. »* | `CatalogueController.build` § 3.4, `CatalogueFooter` § 4.3 | Une requête **par navigation** et **une** requête par *Vérifier à nouveau*. Aucun `ref.invalidate` périodique, aucun rafraîchissement au retour d'onglet, **pas de `pull-to-refresh`** — un doigt vers le bas qui visite silencieusement un site est un geste dont le lecteur ne peut pas voir le coût (B36). L'append à la pagination est déclenché par un **défilement visible** du lecteur, avec un seuil de trois lignes et un verrou à une requête : ce n'est pas du fond spéculatif |
| **B22** | *« When a site cannot be read the app states that it could not read it, and never presents an empty list as an answer. **"Could not read" and "genuinely nothing" are distinguished like this:** the response parsed successfully AND carries the site's own explicit empty-result signal → genuine nothing, shown as a clear "no results". A successful response whose expected content elements are simply absent, a parse error, or a non-success status → the site could not be read, reported as a failure with a retry. **The discriminator is the site's own empty-result signal, never the absence of a match.** »* | `map()` § 3.1, `CatalogueEmpty` / `CatalogueError` § 3.2 | Le type fait le travail : `BrowseOutcome` est une séaled class à trois bras, et le `switch` de § 3.1 est **total**. Aucune branche ne retourne `BrowseSucceeded(items: [])` après un `catch`, aucune ne retourne `null`. Les trois formes **divergent mécaniquement** — position, icône, action, présence d'un réessayer — pas seulement par un mot échangé, parce que deux composants tous deux faits de « une phrase et un bouton » se ressembleraient à la lecture. Et la forme « vide » **n'a** pas de réessayer : rien n'a échoué |
| **B24** | *« Any action that can fail shows an error the user can read and act on, together with a way to try again. No action fails silently to a blank screen or a silent spinner. »* | `CatalogueError` § 4.3, `retry()` § 3.1 | Chaque `SourceFailure` a **sa** phrase et **son** chemin de sortie (§ 3.6), et tous ont `secondary` **Vérifier à nouveau**. L'échec de pagination **ne remplace pas** la liste déjà rendue : quarante lignes devenues une page d'erreur serait exactement ce que « no action fails silently to a blank screen » interdit. L'ajout à la bibliothèque qui échoue laisse la ligne à sa place d'origine et le dit |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| **E4** | *« Site layout changed between releases — severity **critical** »* → *« The app detects this and reports "this site could not be read"; it never shows an empty catalogue or an empty chapter list as if the novel had none (B22). »* | `SourceFailure.sourceLayoutChanged(selector)` rend `CatalogueSourceUnreadable` avec le nom du sélecteur ayant échoué. **Le test de cette slice est la fixture `fanmtl-broken-layout.html`** : une page réelle capturée dont le conteneur de contenu a été renommé, bien formée, 200, non vide, et dont le parseur ne trouve rien. Elle traverse le chemin `BrowseFailed` et rend l'état d'échec — **et ce chemin est le gate MVP** (`architecture.md` § 3.1b) | § 3.1, § 11.1 |
| **E8** | *« A site returns nothing where content is expected — a site's page loads but contains none of the expected items. »* → *« Treated as a suspected break, not as "no results", and reported as a failure (B22). »* | **C'est le même chemin qu'E4 et c'est le cas que SC-6 existe pour.** Le rendu est identique, donc la fixture du dessus le couvre sans duplication. La seule subtilité : une page **vraiment** vide et une page **sans les éléments attendus** produisent la même sortie du parseur. C'est pourquoi `2-1` distingue les deux au moment du `select`, et pourquoi le retour d'une page vide est `BrowseFailed` et pas `BrowseEmpty` | § 3.1, § 8 |
| **E5** | *« No connection while browsing or searching — severity high. »* → *« A clear "no connection" message with a retry; the library and every stored chapter remain fully usable (B23, C14). »* | `CatalogueNoConnection`, **distinct** de `CatalogueSourceUnreadable` : mêmes ancre et icône, mais un corps qui dit *Rien ne va mal avec FanMTL* — parce que ce qui manque n'est pas le site — et un `ghost` **Ouvrir votre bibliothèque**. L'écran qui risque le plus de laisser un lecteur au sec est celui qui a le droit de ne pas le laisser totalement sec | § 3.6 |
| **E2** | *« Inconsistent chapter titles and numbering — Titles such as "Chapter 1", "Ch. 12.5", "Vol 3", "Extra", "Omake", or none at all. »* → *« Displayed verbatim; all are selectable and openable; none is discarded for being irregular (B10). »* | **Sur cet écran, transposé aux titres de romans**, qui ont la même contrainte : un titre de 60 caractères, un titre en CJK, un titre avec un emoji, un titre **vide** (→ la ligne est **omise** et l'omission journalisée localement, jamais rendue comme une ligne à titre vide). **Deux lignes de même titre sont deux lignes** (B40, E17) : le nom du site dans la barre de titre est ce qui les distingue. Un titre tronqué à deux lignes porte une ellipse et le **titre complet** est l'étiquette d'accessibilité de la ligne et le titre de l'écran de détails | § 4.3 |
| **E1** | *« Chapter list of extreme length — A novel with 120 chapters, or one with several thousands. »* → *« The complete list is displayed in reading order, remains scrollable and responsive, and nothing is dropped or truncated (B9). »* | **⚠️ Cette slice est `3-1`, l'écran de catalogue, et non `3-2`, l'écran de liste de chapitres. L'objet littéral d'E1 — une liste de chapitres — n'existe pas ici.** L'obligation correspondante sur un catalogue paginé est : **ne jamais tronquer, ne jamais inventer une fin, ne jamais remplacer une liste par une page d'erreur.** Les trois sont implémentées : la grille rend les `items` de la page **tels quels**, `hasMore` false ne produit **aucun** pied de liste, et l'échec de la page suivante **conserve** les lignes déjà rendues (§ 3.4). La borne de 10 000 de **B9** appartient à `3-2` et à `6-3` | § 3.4 |

### 6.3 Contraintes (C*)

| ID | Contrainte (PRD) | Comment elle est respectée |
|---|---|---|
| **C7** | *« Source reliability — sites change their pages without warning and can stop working overnight. The app silently returning nothing is the main failure mode to avoid (B22, E4). »* | C'est la raison d'être de la slice. Le retour d'une liste vide **depuis la page 2** est traité comme un défaut de disposition, jamais comme un tag vide. Un nouveau changement de disposition trouvé en production est une **entrée** dans `18-external-contracts.md`, pas une correction silencieuse |

## 7. Pièges à éviter

- **⚠️ Ne pas transformer un `catch` en `BrowseSucceeded(items: [])`.** Le
  comportement correct (**B22**, **SC-6**) est : laisser l'exception remonter au
  `AsyncError` du contrôleur et mapper vers `CatalogueNoConnection` ou
  `CatalogueSourceUnreadable`. Une liste vide renvoyée après un échec est la
  **précisément** la confusion que B22 rend impossible dans le type — et c'est la
  façon dont cette règle a été violée la première fois.
- **⚠️ Ne pas utiliser la chaîne « No relevant content found » de FanMTL comme
  libellé d'état vide.** Le comportement correct (**B22**, `18-external-contracts.md`)
  est : cette chaîne est le texte de la **page d'échec de recherche** de FanMTL. Elle
  est **non applicable à un tag** ; l'utiliser comme libellé attribuerait à l'app la
  parole du site et effondrerait la distinction exacte que B22 protège. Le tag vide
  est jugé **par la forme de la page** — zéro ligne de roman.
- **⚠️ Ne pas afficher une page vide en position 2+ comme un tag vide.** Le
  comportement correct (**E8**, **B22**) est : `CatalogueSourceUnreadable`, et
  **les lignes déjà rendues restent**. Une liste tronquée à la page 2 se lirait
  comme une liste de 30 romans quand il y en a 900.
- **⚠️ Ne pas faire de l'état vide un `ErrorState` recoloré.** Le comportement
  correct (**B22**, `browse-catalogue.md` § 2.1) est : deux formes **mécaniquement**
  divergentes — vide centré, calme, sans icône, sans réessayer ; échec ancré en haut,
  aligné à gauche, avec icône, réessayer et légende. Deux composants tous deux faits
  de « une phrase et un bouton » ne sont distinguables que par la position et la
  couleur, ce qui ne suffit pas.
- **⚠️ Ne pas mettre `pull-to-refresh` sur ce catalogue.** Le comportement correct
  (**B5**, **B36**) est : actualiser, c'est `Vérifier à nouveau`. Un doigt vers le
  bas qui visite silencieusement un site est un geste dont le lecteur ne peut pas
  voir le coût, et « arriver sur l'écran » n'est pas un déclencheur.
- **⚠️ Ne pas mettre le tri du site dans une barre d'outils, ni un filtre au-delà
  du tag.** Le comportement correct (**B41**, `browse-catalogue.md` § 11) est :
  l'ordre est celui du site, le tag **est** le filtre, et l'application n'interprète
  aucune valeur de filtre. Exposer le tri du site obligerait à interpréter ses
  segments de tri, ce qui est exactement ce que B41 interdit.
- **⚠️ Ne pas numéroter les pages pour le lecteur.** Le comportement correct
  (**B41**, `browse-catalogue.md` § 5) est : *Plus de résultats depuis FanMTL* dans
  le pied. L'index 0-based du site est converti à la frontière de la requête et ne
  remonte jamais dans l'interface : un lecteur qui calcule « page 0 sur 34 » se pose
  une question sur un index qui n'est pas le sien.
- **⚠️ Ne pas laisser la requête du lecteur dans le chemin de l'URL.** Le
  comportement correct (`browse-catalogue.md` § 8) est : `q` est un paramètre de
  requête (`?q=`), pas un segment. Le chemin est ce que le lecteur peut lire à voix
  haute ou recopier, et une chaîne de recherche n'a rien à y faire.
- **⚠️ Ne pas appliquer `ignorePointer` au catalogue pendant un chargement de
  page suivante.** Le comportement correct (`browse-catalogue.md` § 4) est : **en
  mode résultats le champ est présent et utilisable pendant que la liste charge** ;
  pour la pagination, les lignes déjà rendues restent **lisibles et cliquables**, et
  seul le pied est en état d'attente. Une liste figée pendant un chargement est un
  écran qui ne répond plus, et `browse-catalogue.md` l'interdit explicitement.
- **⚠️ Ne pas construire le mode recherche de cet écran.** Le comportement correct
  (**B50**, ADR-015, `state.json` → `6-2`) est : le mode résultats appartient à
  `6-2`, qui est **conditionnelle** et attend `6-11`. Le construire ici serait
  construire `6-2` deux fois et franchir une dépendance dure de `6-11`. Cet écran
  porte l'absence : quand `supportsSearch == false`, **aucun champ** n'est rendu.
