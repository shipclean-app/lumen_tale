# Plan d'implémentation — 3-3

> **Une seule tuile, deux actions.** Cette slice rend le téléchargement et la
> suppression d'**un** chapitre — la file entière appartient à `5-1` et `5-2`, et la
> règle que cette slice doit rendre impossible à enfreign est la plus simple et la
> plus coûteuse du projet : **l'interface ne pose jamais la marque de téléchargement.**

## 1. Résumé de la slice

`3-3` rend **deux actions sur un chapitre** et **rien d'autre** :

1. **Télécharger un chapitre**, depuis sa place dans la liste de chapitres d'un
   roman. C'est, dans l'interface, *la file de longueur un* : une enfilement, un
   numéro de position, et rien d'autre. La **sixième** option de B18 — un ensemble
   choisi à la main — réutilise exactement le même chemin.
2. **Supprimer la copie téléchargée d'un chapitre**, en laissant les autres
   chapitres du roman intacts (B33).

Le cœur de la slice est une **interdiction** : **l'interface ne pose jamais
`chapters.downloadedAt`.** Cette colonne est écrite par `2-3`, **après** le
renommage atomique, et l'ordre des deux écritures **est** B6 (ADR-022). Une tuile
qui affiche « téléchargé » avant que le fichier soit complet est l'état exact que la
colonne existe pour rendre inatteignable — et l'interface est le seul endroit où
cet état pourrait être produit sans que le disque soit consulté.

Deuxième interdiction, de la même famille : la suppression **ne supprime pas la
ligne `chapters`**. Elle supprime le **fichier** et met `downloadedAt` à `null`. B9
exige que la liste reste complète quelle que soit sa longueur ; supprimer la ligne
ferait perdre la liste d'un roman de 10 000 chapitres parce qu'un fichier a été
effacé.

**User stories couvertes** : US-06 (Télécharger un seul chapitre)
**Règles métier couvertes** : B6, B18, B33
**Edge cases couverts** : E14, E15, E20
**Contraintes couvertes** : C8, C11, C14

/// **Index `idx_queue_state`.** Le filtre en pause/en file, lu à chaque reprise.
@TableIndex(name: 'idx_queue_state', columns: {#state})
class QueueItems extends Table {
  TextColumn get id => text()();
  TextColumn get chapterId =>
      text().references(Chapters, #id, onDelete: KeyAction.cascade)();

  /// Déclaré `TextColumn` et mappé : `ColumnBuilder.map` est un builder à
  /// type fantôme, donc un type non-String ici fait échouer `flutter analyze`
  /// avant que `drift_dev` ne s'exécute. Le **générateur** est ce qui expose
  /// `DownloadState` sur la ligne générée.
  TextColumn get state => text()
      .map(const DownloadStateConverter())
      .withDefault(const Constant('queued'))();

  /// B18 — **l'ordre d'insertion**. C'est *lui*, et non `chapters.ordinal`, que
  /// la file lit : l'ordre choisi à la main est donc honoré.
  IntColumn get queuePosition => integer()();
  DateTimeColumn get addedAt => dateTime()();
  DateTimeColumn get startedAt => dateTime().nullable()();
  DateTimeColumn get finishedAt => dateTime().nullable()();

  /// B20 — un téléchargement interrompu **reprend** plutôt que de recommencer ;
  /// c'est le nombre de tentatives qui distingue une reprise d'un nouveau fetch.
  IntColumn get attempts => integer().withDefault(const Constant(0))();

  /// B24 / B22 — un code **typé** de la hiérarchie `13-error-handling.md`, pour
  /// que l'interface puisse dire **pourquoi** ça a échoué. « failed » sans
  /// raison est exactement l'état que B22 existe pour empêcher.
  TextColumn get errorCode =>
      text().nullable().withDefault(const Constant(''))();

  /// ⚠️ **AUCUNE COLONNE DE CONCURRENCE.** B18 rend la concurrence constante de
  /// un. Une constante exprimée en colonne est quelque chose qu'une
  /// implémentation pourrait changer, donc `app_database_test.dart` affirme
  /// l'**absence** de la colonne.
}

// lib/domain/downloads/download_enqueue.dart
import 'package:lumen_tale/core/error/source_failure.dart';

/// **Ce que le lecteur a demandé.** Une valeur, pas une procédure.
///
/// La distinction compte : « le chapitre suivant » et « les 25 suivants » sont la
/// **même** action à des échelles différentes. Les réduire à un enum de six
/// valeurs comme le fait la feuille de B18 les multiplierait en six chemins, et
/// cinq d'entre eux ne sont pas des actions.
@freezed
class DownloadRequest with _$DownloadRequest {
  const factory DownloadRequest({
    /// B18 — une liste **explicite**, jamais un intervalle calculé. Un intervalle
    /// est une intention ; une liste est un fait, et c'est le fait que la file
    /// exécute. « Les 25 suivants » est converti en liste **une fois**, au
    /// moment du tap, puis n'est plus jamais recalculé : la position de lecture
    /// du lecteur aura bougé d'ici là.
    required List<String> chapterIds,

    /// B18 — l'ordre demandé. C'est `queuePosition`, jamais `ordinal`, qui est
    /// écrit : l'ordre choisi à la main est honoré.
    required List<int> inThisOrder,
  }) = _DownloadRequest;
}

/// L'issue d'un **enfilement**, jamais un `bool`.
sealed class EnqueueOutcome {
  const EnqueueOutcome();
}

/// En file. Le lecteur verra la tuile en `downloading`.
final class EnqueueAccepted extends EnqueueOutcome {
  const EnqueueAccepted(this.itemIds);
  final List<String> itemIds;
}

/// B18 — le chapitre est **déjà** marqué téléchargé. Ce n'est **pas** une
/// erreur : `07-downloads-offline.md` règle 3 dit qu'un fichier existant et une
/// ligne `downloaded` ne sont pas re-récupérés. Refuser silencieusement serait
/// laisser croire qu'une action a eu lieu.
final class EnqueueAlreadyStored extends EnqueueOutcome {
  const EnqueueAlreadyStored(this.chapterIds);
  final List<String> chapterIds;
}

/// B18 / B19 — le chapitre est **déjà** en file. Pas de doublon : deux lignes
/// `queue_items` pour un même chapitre feraient télécharger deux fois.
final class EnqueueAlreadyQueued extends EnqueueOutcome {
  const EnqueueAlreadyQueued(this.itemIds);
  final List<String> itemIds;
}

/// E5 / B5 — pas de connexion. **Le chapitre n'est PAS en file** : une file qui
/// promet de télécharger sans réseau promet une chose que l'application ne peut
/// pas tenir.
final class EnqueueNoConnection extends EnqueueOutcome {
  const EnqueueNoConnection();
}

/// E20 — le téléphone n'a plus la place. **Rien n'est en file.** Le dialogue dit
/// pourquoi, propose de supprimer un chapitre, et propose de réessayer.
final class EnqueueRefusedForSpace extends EnqueueOutcome {
  const EnqueueRefusedForSpace({required this.requiredBytes, required this.freeBytes});
  final int requiredBytes;
  final int freeBytes;
}

/// B24 — la base n'a pas pu écrire. Rien n'est en file.
final class EnqueueWriteFailed extends EnqueueOutcome {
  const EnqueueWriteFailed(this.reason, {this.cause});
  final DatabaseFailure reason;
  final Object? cause;
}

// lib/domain/downloads/delete_one_chapter.dart
import 'package:lumen_tale/core/error/source_failure.dart';

/// Le résultat de la suppression de la copie téléchargée d'**un** chapitre.
///
/// **Trois issues, pas deux**, et la troisième est celle que l'interface doit
/// savoir rendre : « il n'y avait rien à supprimer » n'est pas un échec, et le
/// présenter comme tel ferait croire que quelque chose a été perdu.
sealed class DeleteOneOutcome {
  const DeleteOneOutcome();
}

/// Le fichier est supprimé, la marque est effacée, la **ligne reste**.
final class DeleteOneRemoved extends DeleteOneOutcome {
  const DeleteOneRemoved({required this.freedBytes});

  /// Le nombre d'octets réellement libérés, mesuré **avant** la suppression.
  /// ⚠️ PAS UNE ESTIMATION. L'application n'a pas de chiffre avant d'avoir
  /// récupéré quoi que ce soit (B18), donc « ≈ 4 Mo » serait un nombre que le
  /// lecteur retiendra contre l'application dès la première nuit d'une vraie
  /// file. Ici la mesure existe, donc elle est affichée.
  final int freedBytes;
}

/// La marque était déjà à `null`. **Pas une erreur.** B33 dit « la copie
/// téléchargée d'un chapitre peut être supprimée seule » ; dire à un lecteur
/// qu'il vient de supprimer quelque chose qui n'existait pas est une fausse
/// déclaration sur une action irréversible.
final class DeleteOneNothingToRemove extends DeleteOneOutcome {
  const DeleteOneNothingToRemove();
}

/// La ligne du chapitre a disparu — son roman a été supprimé de la base, donc la
/// `CASCADE` a emporté le chapitre (ADR-022). B32 : les **fichiers** survivent à
/// la suppression d'une ligne. Le fichier est donc supprimé par le chemin de
/// fichiers, et ce cas est **le seul** où la suppression de fichier précède
/// l'écriture en base.
final class DeleteOneChapterRowGone extends DeleteOneOutcome {
  const DeleteOneChapterRowGone({required this.freedBytes});
  final int freedBytes;
}

/// B24 — la suppression a échoué. **Le chapitre reste téléchargé**, et l'interface
/// le dit : un contrôle qui montre un état que l'application ne détient pas
/// laisse le lecteur croire que l'espace est libéré.
final class DeleteOneFailed extends DeleteOneOutcome {
  const DeleteOneFailed(this.reason, {this.cause});
  final DatabaseFailure reason;
  final Object? cause;
}

```dart
// lib/domain/downloads/chapter_download_repository.dart
/// L'enfilement d'un chapitre. **Aucune écriture sur `chapters` ici, et jamais.**
///
/// C'est la déclaration la plus importante de cette slice : le dépôt qui
/// enfile un chapitre **ne sait pas** qu'un chapitre existe, et donc ne peut
/// pas dire qu'il est téléchargé. Le seul sait est `2-3`'s `ChapterStore`, qui
/// écrit la marque après le renommage atomique.
abstract interface class ChapterDownloadRepository {
  /// B18 — une ligne `queue_items` par chapitre, `queuePosition` incrémental,
  /// `state = queued`. **Rien d'autre.** Pas de `downloadedAt`, pas de fichier,
  /// pas de requête.
  Future<EnqueueOutcome> enqueue(DownloadRequest request);

  /// Annuler l'entrée d'un chapitre qui **n'a pas encore commencé**. B19 : « no
  /// further chapter is fetched after it ».
  ///
  /// ⚠️ Si l'article est `downloading`, l'annulation **ne fait rien** et rend
  /// `CancelTooLate` : ce qui est en cours est une **écriture** de fichier, et
  /// « garder la moitié » n'est pas un état que le format de stockage sait
  /// représenter honnêtement (B6).
  Future<CancelOutcome> cancelIfNotStarted(String chapterId);

  /// B33 — supprimer le fichier d'un chapitre et effacer sa marque. **La ligne
  /// `chapters` reste** (B9).
  ///
  /// ⚠️ DÉLÉGUÉ À `2-3`'s `ChapterStore.deleteOne`. Cette slice n'ouvre pas de
  /// `File`, ne fait pas de `p.join` et ne connaît pas la disposition sur
  /// disque. C'est ce qui rend la règle de `17-security.md` nº 1 inapplicable
  /// ici : le seul composant qui touche au système de fichiers est celui qui
  /// l'a toujours fait, avec `novelId` en MD5.
  Future<DeleteOneOutcome> deleteStoredCopy({
    required String chapterId,
    required String novelId,
    required int ordinal,
  });

  /// La progression d'un chapitre, en flux. `07-downloads-offline.md` règle 2.
  /// `null` quand rien ne tourne : pas de barre du tout.
  Stream<double?> watchProgress(String chapterId);

  /// E20 — l'espace libre, pour que l'interface puisse dire **deux** nombres
  /// plutôt que « espace insuffisant ». Un refus sans chiffres est un refus que
  /// le lecteur ne peut pas contester.
  Future<StorageSnapshot> storageSnapshot();
}

final class StorageSnapshot {
  const StorageSnapshot({required this.freeBytes, required this.totalBytes});
  final int freeBytes;
  final int totalBytes;
}

sealed class CancelOutcome {
  const CancelOutcome();
}
final class CancelSucceeded extends CancelOutcome {
  const CancelSucceeded();
}

/// B6 — l'écriture était déjà en cours. Rien n'a été annulé, et la tuile garde sa
/// barre jusqu'au bout : le chapitre sera **entièrement** téléchargé ou pas du
/// tout, et l'annulation d'une écriture à moitié est exactement le « garder la
/// moitié » que B6 interdit.
final class CancelTooLate extends CancelOutcome {
  const CancelTooLate();
}

/// B19 — l'annulation d'une file en cours a échoué. **La file continue**, et
/// l'interface le dit : montrer une file annulée qui ne l'est pas laisserait des
/// chapitres s'écrire que le lecteur croit être sûrs.
final class CancelFailed extends CancelOutcome {
  const CancelFailed();
}
```

## 3. Algorithmes critiques

### 3.1 Enfiler un chapitre (couvre **B18**, E20)

```
enqueue(request):
  # ── garde 1 : connexion ────────────────────────────────────────────────
  if !connectivity.hasConnection:
    return EnqueueNoConnection()      # ⚠️ RIEN N'EST EN FILE.
    # Une file qui promet un téléchargement sans réseau promet une chose que
    # l'application ne peut pas tenir, et B19 veut dire « paused, cancelled and
    # unfinished chapters are never marked as downloaded » — rien n'est
    # téléchargé, mais un chapitre en file sit dans l'interface comme
    # « en cours », ce qui n'est pas vrai.

  # ── garde 2 : déjà fait ? ─────────────────────────────────────────────
  stored = SELECT chapter_id FROM chapters
           WHERE id IN (…) AND downloaded_at IS NOT NULL
  # ⚠️ `downloaded_at IS NOT NULL`, ET NON « le fichier existe » (ADR-022).
  #   Le fichier est de la DONNÉE ; la marque est le FAIT. B33 supprime le
  #   fichier et efface la marque, donc une sonde d'existence ne pourrait pas
  #   distinguer « supprimé à dessein » de « perdu ».
  if stored.isNotEmpty and stored.length == request.chapterIds.length:
    return EnqueueAlreadyStored(stored)

  # ── garde 3 : déjà en file ? ───────────────────────────────────────────
  queued = SELECT chapter_id FROM queue_items
           WHERE chapter_id IN (…) AND state IN ('queued','downloading')
  if queued.isNotEmpty and covers_everything:
    return EnqueueAlreadyQueued(queued)
  # ⚠️ PAS DE DOUBLON. Deux lignes queue_items pour un même chapitre
  #   téléchargeraient deux fois et overrunteraient la position de la file.

  # ── garde 4 : place disponible (E20) ───────────────────────────────────
  snapshot = readStorage()
  # ⚠️ AUCUNE TAILLE ESTIMÉE. L'application n'a pas de chiffre d'octets avant
  #   d'avoir récupéré quoi que ce soit, et « ≈ 4 Mo » serait un nombre que le
  #   lecteur retiendra contre l'application dès la première nuit d'une vraie
  #   file. Le seul seuil défendable est une **constante de plafond** par
  #   chapitre — `maxChapterBytes`, `17-security.md` règle 3 — parce qu'elle ne
  #   prétend rien sur la taille réelle d'aucun chapitre.
  if snapshot.freeBytes < maxChapterBytes:
    return EnqueueRefusedForSpace(
      requiredBytes: maxChapterBytes, freeBytes: snapshot.freeBytes)
    # ⚠️ RIEN N'EST EN FILE, ET AUCUNE TUILE NE MONTRE DE PROGRESSION.
    #   C'est le refus d'E20 : la file s'arrête, dit pourquoi, garde ce qui
    #   est déjà terminé, et n'enregistre aucun chapitre partiel comme complet.

  # ── l'écriture : queue_items SEULEMENT ─────────────────────────────────
  next = SELECT COALESCE(MAX(queue_position), 0) + 1 FROM queue_items
  for (i, chapterId) in request.chapterIds.indexed:
    # ⚠️ `queue_position` suit inThisOrder, PAS `chapters.ordinal`.
    #   B18 : « c'est cela, et non chapters.ordinal, que la file lit, de sorte
    #   qu'un ordre choisi à la main est honoré ».
    db.into(queueItems).insert(QueueItemsCompanion(
      id:            Value(newQueueItemId()),   # généré à l'enfilement
      chapterId:     Value(chapterId),
      state:         const Value('queued'),      # ⚠️ LE NOM, PAS L'ORDINAL
      queuePosition: Value(next + i),
      addedAt:       Value(DateTime.now()),
      attempts:      const Value(0),
      errorCode:     const Value(''),
    ))

  # ⚠️ `chapters.downloadedAt` N'EST PAS ÉCRIT ICI. JAMAIS. JAMAIS.
  #   `2-3` l'écrit, et **après** le renommage atomique. C'est l'ordre des deux
  #   écritures qui EST B6 (ADR-022), et cette fonction est l'endroit exact où
  #   l'inverser produirait le seul état inatteignable que la colonne existe
  #   pour empêcher.
  return EnqueueAccepted(itemIds)
```

**Chaque branche, toutes explicites :**

| Situation | Ce qui se passe | Pourquoi c'est correct |
|---|---|---|
| Pas de connexion | `EnqueueNoConnection`, **zéro écriture** | E5, B5 |
| Tous les chapitres déjà marqués | `EnqueueAlreadyStored`, **zéro écriture** | `07-downloads-offline.md` règle 3 : un fichier présent et une ligne `downloaded` ne sont pas re-récupérés. Refuser **bruyamment** plutôt que silencieusement : un tap qui ne fait rien est un contrôle qui ment (B24) |
| Partiellement déjà marqué | `EnqueueAlreadyQueued` pour ceux qui le sont, et **seuls les restants** sont enfilés | Une sélection mainlevée est un ensemble partiel, et le dire est exact |
| Déjà en file | `EnqueueAlreadyQueued`, **zéro écriture** | Pas de doublon dans `queue_items` |
| Espace insuffisant | `EnqueueRefusedForSpace` **avec les deux nombres**, **zéro écriture** | **E20** |
| Écriture en base échouée | `EnqueueWriteFailed`, **zéro ligne persistée** (la transaction drift est atomique) | **B24** |
| Nominal | `queue_items` écrit, `chapters` **inchangé** | **B6** : la marque est à `2-3` |

### 3.2 Les cinq états d'un chapitre **du point de vue du lecteur**

L'interface doit rendre ces cinq états, et **aucun autre**. Ce sont exactement les
états que `ChapterListTile` déclare, moins le sixième qui est l'absence de réseau.

```
observeTile(chapter, queueItem, connectivity):

  # 1. DÉJÀ TÉLÉCHARGÉ
  if chapter.downloadedAt != null:
    → ChapterTileState.default (ou `read` si isRead)
    # AFFICHÉ : la rangée est cliquable et ouvre le lecteur.
    # PAS de barre, PAS d'icône de téléchargement, PAS de texte « déjà téléchargé ».
    #   L'état par défaut EST l'état téléchargé ; une étiquette pour cela
    #   appris au lecteur que l'écran ne sait pas ce qu'il montre.
    # Le tap ouvre le lecteur — et le lecteur ne fait AUCUN appel réseau
    #   (C14, B7).

  # 2. EN FILE, PAS ENCORE COMMENCÉ
  if queueItem != null and queueItem.state == 'queued':
    → ChapterTileState.default + une étiquette « En file »
    # Le contrôle EN FILE EST ABSENT, PAS DÉSACTIVÉ : il n'y a pas d'état
    # intermédiaire entre « tap pour mettre en file » et « en file ».

  # 3. EN COURS D'ÉCRITURE
  if queueItem != null and queueItem.state == 'downloading':
    → ChapterTileState.downloading
    # 2dp de ligne déterministe sous le titre, --color-accent.
    # Le pourcentage est dans l'ÉTIQUETTE DE SÉMANTIQUE, pas dans la tuile.
    # ⚠️ LA TUILE N'EST PAS UN CIBLE. Un tuile en vol n'est pas une cible :
    #   on ne navigue pas à mi-écriture.
    # ⚠️ PAS DE CONTRÔLE « ANNULER » SUR LA TUILE. Ce qui est en cours est une
    #   ÉCRITURE de fichier, et « garder la moitié » n'est pas un état que le
    #   format de stockage sait représenter (B6). C'est la file qu'on annule,
    #   à un niveau au-dessus, et elle **jette** le fichier partiel au lieu de
    #   le compléter.

  # 4. EN ÉCHEC
  if queueItem != null and queueItem.state == 'failed':
    → ChapterTileState.failed
    # Icône --color-error + LES MOTS + « Réessayer ».
    # ⚠️ JAMAIS UN TEXTE ROUGE SEUL. § 7 de `14-design-tokens.md` : aucun
    #   état par la couleur seule.
    # Le mot dépend du `error_code` TYpé :
    #   sourceLayoutChanged → « les pages ont changé »
    #   sourceUnavailable   → « le site ne répond pas »
    #   noConnection        → « pas de connexion »
    #   storageFull         → « plus d'espace sur le téléphone »
    #   parseFailed         → « la réponse n'a pas pu être lue »
    # `07-downloads-offline.md` règle 4 : « le nettoyage des fichiers partiels ».

  # 5. PAS ENCORE TÉLÉCHARGÉ, HORS LIGNE
  if !connectivity and chapter.downloadedAt == null:
    → ChapterTileState.offlineAndAbsent
    # La rangée EST PRÉSENTE. Le libellé dit « Non téléchargé ».
    # Le tap ouvre l'état « non téléchargé » du lecteur, qui propose
    # « Télécharger ce chapitre » — et qui mène à EnqueueNoConnection.

### 3.3 Supprimer la copie d'un chapitre (couvre **B33**)

```
deleteStoredCopy(chapterId, novelId, ordinal):
  # ── 1. lire la marque, et la TAILLE RÉELLE ─────────────────────────────
  row = SELECT downloaded_at FROM chapters WHERE id = chapterId
  if row is absent:
    # La CASCADE a emporté la ligne quand le roman a été supprimé (ADR-022).
    # B32 : les FICHIERS survivent à la suppression d'une ligne, donc le
    # fichier est encore là et DOIT être effacé — sinon il devient un orphelin
    # que rien ne pourra jamais nettoyer.
    freed = deleteFile(chapters/<novelId>/<ordinal>.md)   # via 2-3
    return DeleteOneChapterRowGone(freedBytes: freed)
    # ⚠️ C'EST LE SEUL CAS où le fichier est effacé SANS écriture en base,
    #   parce qu'il n'y a plus de ligne à écrire. L'ordre reste « fichier
    #   d'abord ».

  if row.downloaded_at == null:
    return DeleteOneNothingToRemove()   # pas une erreur, pas un dialogue
    # ⚠️ DIRE « SUPPRIMÉ » ICI SERAIT FAUX. L'action a réussi et n'a rien
    #   supprimé ; l'interface dit « Rien à supprimer » et **ne confirme
    #   surtout pas** d'espace libéré.

  freed = fileSize(chapters/<novelId>/<ordinal>.md)
    # ⚠️ MESURÉ, JAMAIS ESTIMÉ. Il existe ici un vrai chiffre, donc il est
    #   affiché : « 41 Ko libérés ».

  # ── 2. la suppression, DÉLÉGUÉE (B33 + 17-security.md règle 1) ─────────
  await chapterStore.deleteOne(ChapterRecord(id, novelId, ordinal))
  #   Ce que `2-3` fait, et qui EST l'implémentation de B33 :
  #     1. supprimer le fichier s'il existe (un fichier absent n'est pas une
  #        erreur)
  #     2. UPDATE chapters SET downloaded_at = NULL WHERE id = chapterId
  #     3. ⚠️ NE PAS SUPPRIMER LA LIGNE `chapters`.
  #        B9 exige la liste complète quelle que soit sa longueur ; supprimer la
  #        ligne ferait perdre les 10 000 titres d'un roman parce qu'UN fichier a
  #        été effacé.

  # ── 3. la file, si l'article existe ────────────────────────────────────
  item = SELECT * FROM queue_items WHERE chapter_id = chapterId
  if item != null and item.state in ('queued'):
    DELETE FROM queue_items WHERE chapter_id = chapterId
    # Un article `queued` pour un chapitre déjà téléchargé n'a aucun sens.
  if item != null and item.state == 'downloading':
    # ⚠️ NE PAS SUPPRIMER. L'écriture est en cours. Le `ChapterStore` la
    #   terminera et posera la marque — donc une suppression demandée pendant
    #   une écriture N'EST PAS HONNÊTE, et le contrôle est absent dans ce cas.
    return CancelTooLate()
  # ⚠️ ET `history_entries` ? RIEN. Une entrée d'historique EST une preuve que
  #   le lecteur a ouvert ce chapitre ; supprimer le fichier ne l'invalide pas
  #   et B32 exige que l'historique survive à une opération sur les fichiers.
  # ⚠️ ET `reading_positions` ? RIEN. B46 : « la position n'est jamais coupée par
  #   une règle de conservation ». Supprimer un téléchargement ne rend pas le
  #   chapitre non lu.
  return DeleteOneRemoved(freedBytes: freed)
```

**Chaque branche, toutes explicites :**

| Situation | Ce qui se passe | Pourquoi c'est correct |
|---|---|---|
| Chapitre téléchargé, fichier présent | fichier supprimé, marque effacée, **ligne conservée**, `41 Ko libérés` affiché | **B33**, **B9** |
| Chapitre téléchargé, **fichier absent** (nettoyage externe) | `deleteOne` ne lève pas — un fichier absent n'est pas une erreur — la marque est effacée, la ligne reste | **B33** : l'action demandée, « supprimer la copie téléchargée », est accomplie. Le compte d'octets vaut 0 et l'interface **ne dit pas** « 41 Ko libérés » parce qu'elle n'a pas mesuré 41 Ko |
| Chapitre **non** téléchargé | `DeleteOneNothingToRemove` — **pas d'erreur, pas de confirmation** | B33 parle de « la copie téléchargée d'un chapitre » ; s'il n'y en a pas, il n'y a rien à dire |
| Ligne du chapitre disparue | fichier effacé, `DeleteOneChapterRowGone` | B32 : les fichiers survivent à la suppression d'une ligne ; ne pas les effacer laisserait des orphelins |
| Article `queued` | supprimé de la file | Un article en file pour un chapitre téléchargé est un doublon |
| Article `downloading` | **`CancelTooLate`**, rien n'est supprimé | **B6** : « garder la moitié » n'est pas représentable |
| La suppression échoue | `DeleteOneFailed` — **le chapitre reste téléchargé**, snackbar *Impossible de supprimer ce chapitre. Rien n'a été modifié.* | **C8**, `downloads.md` § 4 *Submit error* (c) |

### 3.4 E15 — une interruption, et ce qui doit **rester vrai** après

```
# Trois coupures distinctes, trois conséquences distinctes.

# ── A. l'application est tuée PENDANT l'écriture du fichier ──────────────
  À la réouverture :
    le fichier final n'existe pas  (le .part est encore là)
    downloaded_at IS NULL          (la marque n'a pas été écrite)
    queue_items.state == 'downloading'   # ⚠️ LE PIEGE EST ICI
  → au RÉVEIL de la file, `5-2` doit remettre l'article dans le bon état.
    ⚠️ JAMAIS le remettre à `done` : cela poserait la marque d'un fichier absent.
    ⚠️ JAMAIS le laisser `downloading` indéfiniment : la tuile afficherait une
      barre qui n'avance plus, ce qui est un mensonge d'interface.
    → `5-2` le remet à `queued` avec `attempts` incrémenté (B20), et `2-3`
      refait le chapitre DEPUIS LE DÉBUT — jamais depuis un `.part`.
    Cette slice ne fait rien de tout cela ; elle fournit `attempts`, et elle
    l'exige dans sa propre interface : un chapitre dont `attempts > 0` et dont la
    marque est nulle s'affiche « non téléchargé », ce qui est la vérité.

# ── B. le téléphone redémarre ───────────────────────────────────────────
  Strictement le même résultat, donc le même chemin.

# ── C. la connexion tombe ───────────────────────────────────────────────
  E7 : la file S'ARRÊTE, dit pourquoi, et garde chaque chapitre déjà terminé.
  ⚠️ ELLE NE REPART PAS TOUTE SEULE quand le signal revient : la file tourne
    dans le processus et n'a pas d'exécuteur de fond. Le lecteur la reprend.
  Cette slice ne « répare » donc rien : un chapitre arrêté affiche `failed` avec
  le mot « pas de connexion » et « Réessayer », et `Retry` **remet ce chapitre
  seul** en file (B22, B24).
```

**Les quatre affirmations vérifiables qu'E15 impose :**

1. Après toute coupure, `COUNT(chapters WHERE downloaded_at IS NOT NULL)` n'a pas
   **augmenté**.
2. Après toute coupure, le nombre de `.md` définitifs sous
   `<support>/chapters/<novelId>/` **n'a pas** changé — ou alors il a changé **avec**
   la marque, jamais avant.
3. Un `.part` résiduel n'est **jamais** renvoyé par `ChapterStore.fileFor` et
   n'est **jamais** compté comme téléchargé.
4. Le retry est `attempts + 1` et repart de zéro octets récupérés.

### 3.5 E14 — la taille de texte du téléphone, pendant un téléchargement

Le sujet d'E14 est la lecture ; ici il est **le seul endroit où un téléchargement
touche un texte** : le dialogue de confirmation, la feuille de sélection et les
libellés de tuile.

```
À l'échelle système 200 %, pas 1.0 :

  Dialogue de confirmation de suppression :
    titre       « Supprimer le chapitre 214 ? »     --text-h3
    corps        « Le texte de ce chapitre sera effacé de ce téléphone.

                   ce qui est supprimé · ce qui reste · ce qui se passe si

                   que ce dialogue soit rapportable en mots.
    actions     « Annuler » (défaut) · « Supprimer » (danger)
    ⚠️ AUCUNE TAILLE ESTIMÉE ET AUCUNE TAILLE ABSENTE : « 41 Ko » vient de

      afficherait « 0 Ko libérés », ce qui est vrai et ennuyeux, et « 41 Ko »
      serait un mensonge.

  Feuille de sélection (sixième choix de B18) :
    ⚠️ AUCUNE BARRE DE PROGRESSION PLEINE ÉCRAN. Une application de lecture qui
      montre un loader pendant qu'elle écrit un fichier est un écran qui

    Les six options sont des lignes de feuille ; le compteur de chapitres est

  Tuile en cours d'écriture :
    Le pourcentage est dans l'ÉTIQUETTE de sémantique, pas dessiné dans la

| Situation | Ce qui se passe | Pourquoi |
|---|---|---|
| Échelle système 200 %, tuile `downloading` | La barre 2dp occupe sa place ; **le pourcentage n'est pas dessiné** ; le titre tronque à deux lignes avec ellipse | `14-design-tokens.md` § Text scale : les dispositions ne doivent pas déborder aux grandes échelles. Le libellé complet est dans la sémantique |
| Échelle système 200 %, dialogue de suppression | Le corps se ré-enroule sur cinq lignes, **la barre d'actions reste à 48dp** et les deux boutons tiennent côte à côte | Un dialogue qui pousse ses boutons hors de l'écran sur un téléphone réglé à 200 % est un dialogue que le lecteur ne peut pas confirmer |
| Échelle système 200 %, feuille de sélection | Les six lignes s'enroulent ; les compteurs en `Wrap` passent à la ligne suivante | Un `Row` de compteurs déborderait |
| La taille change **pendant** que le dialogue est ouvert | Le dialogue se reconstruit ; **rien** n'est perdu ; aucune action n'a été engagée | Aucune écriture n'a eu lieu : c'est un dialogue de confirmation, pas un formulaire |

### 3.6 E20 — le refus pour stockage, et ce qu'il ne fait pas

```
enqueue → EnqueueRefusedForSpace(requiredBytes, freeBytes)
  →
  AFFICHER :
    dialogue « Le téléchargement n'a pas démarré. Le téléphone n'a pas
              assez d'espace libre. Il manque 2,1 Mo ; il en reste 900 Ko. »
    secondary  « Supprimer un chapitre téléchargé »   → downloads.md
    primary    « Réessayer »

  ⚠️ CE QUE LE DIALOGUE NE FAIT PAS :
    ✗ il ne propose pas « télécharger quand même » — il n'y a pas de « quand
      même » quand il n'y a pas la place
    ✗ il ne met PAS un chapitre en file « en attendant de la place » : une
      entrée en file pour un chapitre qui ne peut pas démarrer est une
      promesse que l'application ne tient pas
    ✗ il ne SUPPRIME RIEN. C8 : il n'y a pas de sauvegarde, donc proposer de
      résoudre un problème d'espace en supprimant des données non demandées
      serait faire de la rareté une raison de perte
    ✗ il ne dit pas « 900 Ko sur 128 Go » — un total de stockage ne sert à rien
      pour décider quoi que ce soit, et il rend le refus contestable au mauvais
      endroit

  ⚠️ CE QUI RESTE VRAI PENDANT LE REFUS :
    chaque chapitre DÉJÀ téléchargé reste téléchargé, reste lisible, et reste
    compté. Un refus de place n'est pas une perte : c'est un arrêt (E20).
```

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| Ligne `queue_items` | base | `queue_items` | `enqueue()` de cette slice | `5-1` (exécution), `5-2` (pause/reprise), `5-3` (échecs) |
| `chapters.downloadedAt` | base | colonne `downloaded_at` | `null` | **`2-3` uniquement**, après le renommage atomique |
| Fichier `.md` | disque | `<support>/chapters/<novelId>/<ordinal>.md` | `2-3` | `2-3.deleteOne` |
| Progression d'un chapitre | mémoire, live | `queue_items.attempts` + octets en cours | `5-1` | `5-1` |
| Espace libre | — | **jamais persisté** : c'est une mesure du système de fichiers | à chaque appel de `storageSnapshot` | à la demande |
| `downloadedCount` d'un roman | base | `COUNT(downloaded_at IS NOT NULL)` | `2-5` | recalculé |
| Snackbar de confirmation | écran | **éphémère**, 4 s | action réussie | `SnackBar` |
| Confirmation de suppression | écran | **éphémère**, un dialogue | tap sur le contrôle | confirmation ou annulation |

**Ce qui n'est délibérément pas de l'état :** « est-ce que ce chapitre est
téléchargé ? ». C'est `chapters.downloadedAt`, et le contrôle le **lit** — il ne
maintient pas de copie. Une copie serait une seconde source de vérité, libre de
diverger de la colonne, et la divergence se lirait comme un chapitre téléchargé
dont le fichier n'existe pas.

**Ce qui n'est délibérément pas de l'état :** la taille d'un chapitre. L'application
n'a pas de chiffre avant d'avoir récupéré quoi que ce soit, et elle **n'invente
aucun** : la seule taille qu'elle affiche est `fileSize` d'un fichier **déjà sur le
disque**, mesurée à l'instant de la suppression. C'est la différence entre un
chiffre et une estimation, et `downloads.md` § 4 refuse explicitement d'en imprimer
une.

**Ordre d'écriture, et il est la règle :** *valider → écrire → puis mettre à jour
l'interface.* Concrètement : `enqueue` n'écrit `queue_items` qu'après les quatre
gardes, et ne pose **jamais** `downloadedAt`. `deleteStoredCopy` supprime le
fichier **avant** d'effacer la marque, dans cet ordre — l'inverse laisserait une
marque sans fichier, l'état qu'ADR-022 rend inatteignable par construction.

## 6. Traçabilité des règles

### 6.1 Règles métier (B*)

| ID | Règle (PRD, texte intégral) | Implémentée où | Approche |
|---|---|---|---|
| **B6** | *« A chapter is stored atomically: it is either completely present on the phone and readable, or it is not stored. A partially stored chapter is never shown as downloaded and never opens as if complete (E6, E18). »* | `enqueue` § 3.1, `cancelIfNotStarted` § 2.2, § 3.4 | **Cette slice ne pose jamais `downloadedAt`.** Elle écrit `queue_items` et **rien d'autre**, et la seule fonction qui écrit la marque est `2-3`'s `ChapterStore.store`, **après** le `rename()`. L'ordre des deux écritures est B6 (ADR-022) et cette slice est l'endroit exact où l'inverser rendrait possible le seul état que la colonne existe pour empêcher. Corollaire : `cancelIfNotStarted` **échoue** sur un article `downloading` (`CancelTooLate`) — ce qui est en cours est une écriture de fichier, et « garder la moitié » n'est pas un état que le format sait représenter. Corollaire 2 : le `downloadedCount` d'un roman est `COUNT(downloaded_at IS NOT NULL)` et **jamais** `COUNT(fichiers)`, donc un téléchargement interrompu ne compte pas |
| **B18** | *« Downloading a novel enqueues its chapters one at a time in reading order. The bulk choices offered are: the next chapter, the next 5 / 10 / 25 chapters, **all unread chapters**, or an explicit set the user selected by hand. There is no "download every chapter including ones already read" shortcut — that is reachable only by selecting every chapter deliberately. »* | `DownloadRequest` § 2.2, `enqueue` § 3.1, § 3.6 | **B18 s'applique à la file, et la file est `5-1`.** Ce que `3-3` en hérite est la partie qui concerne **un** chapitre : un `DownloadRequest` **matérialisé** — une liste explicite d'ids **et** leur ordre — parce qu'un intervalle est une intention et qu'une liste est un fait. *Les 25 suivants* est converti en liste **une fois**, au tap, et n'est plus recalculé : la position de lecture du lecteur aura bougé d'ici là. `queuePosition` suit `inThisOrder` et **jamais** `chapters.ordinal`, pour qu'un ordre choisi à la main soit honoré. Et **il n'existe aucun raccourci « tout, lus compris »** : la seule façon de l'atteindre est de tout sélectionner, ce que B18 réserve à une sélection délibérée — donc **pas** de bouton « tout sélectionner » dans la feuille de sélection |
| **B33** | *« The downloaded copy of a single chapter can be deleted on its own, leaving the other chapters of the novel untouched. »* | `deleteStoredCopy` § 3.3, `DeleteStoredChapterDialog` § 4.3.4 | La suppression est **déléguée** à `2-3`'s `ChapterStore.deleteOne`, qui supprime le **fichier** et met `downloadedAt` à `null` — **et ne supprime pas la ligne `chapters`**, parce que B9 exige la liste complète quelle que soit sa longueur. « Les autres chapitres intacts » est vrai **mécaniquement** : la requête porte sur un `chapterId`, il n'y a aucune opération de masse, et le dialogue nomme le nombre de chapitres frères. Le cas `DeleteOneChapterRowGone` couvre la suppression d'un roman : les fichiers survivent à la suppression de la ligne (B32), donc les effacer est **le** comportement correct, et ne pas le faire laisserait des orphelins qu'aucun composant ne pourrait nettoyer |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| **E14** | *« Font size changes mid-read — The user changes the phone's font size while a chapter is open. »* → *« The reader's text resizes immediately, no text is clipped or overlapped, and the reading position is preserved (B27). »* | **Transposé au seul texte qu'un téléchargement touche** : la confirmation de suppression, la feuille de sélection et les libellés de tuile. Trois décisions : (1) **le pourcentage de progression n'est pas dessiné dans la tuile** — il est dans l'étiquette de sémantique — parce qu'un pourcentage dessiné à 200 % dans une tuile de 56dp rognerait le titre du chapitre, et B10 exige le titre verbatim ; (2) les six options de B18 sont des lignes de feuille et les compteurs sont une `Wrap` de `StatusChip`, donc ils s'enroulent au lieu de déborder ; (3) les boutons du dialogue restent à **48dp** même corps à cinq lignes, donc le dialogue reste confirmable à 200 % | § 3.5 |
| **E15** | *« The app is closed or the phone restarts mid-queue — A fifty-chapter download is interrupted by the app being closed or the phone rebooting. »* → *« The queue continues from the chapter it reached when the app is opened again; it does not restart the novel (B21). »* | **Quatre affirmations vérifiables**, dont deux sont des interdictions de cette slice : (1) `COUNT(downloaded_at IS NOT NULL)` n'a pas **augmenté** après toute coupure ; (2) le nombre de `.md` définitifs n'a changé **qu'avec** la marque, jamais avant ; (3) un `.part` résiduel n'est **jamais** renvoyé par `fileFor` et **jamais** compté comme téléchargé ; (4) le retry est `attempts + 1` et repart de zéro octet. Le piège propre à cette slice est ailleurs : un `queue_items.state == 'downloading'` au réveil ne doit **jamais** être remis à `done` par l'interface, car cela poserait la marque d'un fichier absent. C'est `5-2` qui remet à `queued` avec `attempts` incrémenté (B20) | § 3.4 |
| **E20** | *« The phone runs out of storage mid-download — A queue exhausts the available space. »* → *« The queue stops, says why, keeps every already-completed chapter, and never records a partial chapter as complete (B6). »* | **Refus à l'enfilement** (`EnqueueRefusedForSpace`) et **arrêt en cours de file** (`5-3`). Cette slice implémente le refus : rien n'est en file, aucune tuile ne montre de progression, et le dialogue nomme **les deux nombres** — il manque 2,1 Mo, il en reste 900 Ko — parce qu'un refus sans chiffres est un refus que le lecteur ne peut pas contester. Le seuil est une **constante de plafond** par chapitre (`17-security.md` règle 3), pas une estimation de la taille du chapitre : l'application n'a pas de chiffre avant d'avoir récupéré quoi que ce soit. Et le dialogue **ne supprime rien** : sous C8, faire de la rareté une raison de perte serait l'inverse du produit | § 3.6 |

| **E6** | *« Download interrupted partway — The connection drops, or the app is killed, while a chapter is being saved. »* → *« The chapter is not marked as downloaded, never opens with partial text, and is fetched again from the start (B6, B20). »* | **La propriété est celle de `2-3`, et cette slice en hérite sans la dupliquer.** `enqueue` n'écrit que `queue_items` ; la seule fonction qui écrit `chapters.downloadedAt` est `ChapterStore.store`, **après** le `rename()` (ADR-022). Un chapitre interrompu n'a donc pas de marque, et cette slice le rend par `ChapterTileState.offlineAndAbsent` ou `default` — **jamais** « téléchargé », **jamais** un texte partiel. Deux conséquences lui sont propres : (1) `downloadedCount` est `COUNT(downloaded_at IS NOT NULL)`, donc un chapitre interrompu **ne compte pas** et le roman affiche *148 sur 480*, un fait exact ; (2) le contrôle *Télécharger* d'une tuile non stockée **relance depuis le début** — `attempts + 1`, jamais depuis un `.part` résiduel, que `ChapterStore.fileFor` renvoie `null` par construction. Le test qui prouve l'ordre des deux écritures est dans `2-3`, parce que la propriété appartient à son ordre d'écriture | § 3.1, § 3.2 |

### 6.3 Contraintes (C*)

| ID | Contrainte (PRD) | Comment elle est respectée |
|---|---|---|
| **C8** | *« Data loss is structurally accepted — there is no backup and no export (B31, C2). An interrupted or partially written download must therefore never be presented as complete (B6, E6, E7). »* | Trois applications. (1) L'interface ne pose **jamais** la marque, donc elle ne peut pas présenter un chapitre partiel comme complet. (2) Le dialogue de suppression **confirme d'abord** et n'a **pas** d'Annuler — `downloads.md` § 4 argumente que retirer un roman est réversible **parce que rien n'est détruit**, et que supprimer le téléchargement **est** la destruction : un Annuler devrait promettre de retélécharger un contenu qui a pu changer ou disparaître. (3) Un `DeleteOneFailed` laisse la tuile **téléchargée** et dit *Rien n'a été modifié* : montrer « Non téléchargé » alors que le fichier est là est un contrôle qui ment sur l'espace |

Le contrôle d'annulation n'est **pas** sur la tuile : il est sur la barre d'état persistante, à un niveau au-dessus, où le lecteur le cherche. Aucun balayage sur une tuile. La confirmation de suppression met **Annuler** par défaut |
| **C14** | *« No network call may be required to open the app, open the library, list stored chapters, open history, or read a stored chapter (B7). »* | **Enfiler ne touche pas le réseau.** `enqueue()` écrit `queue_items` et s'arrête — la requête réseau est faite par `5-1`, quand la file **tourne**. C'est ce qui rend la suppression et la liste entièrement fonctionnelles hors ligne, et c'est vérifiable : le compteur de requêtes `dio` du test vaut **zéro** pour `enqueue`, `deleteStoredCopy` et `cancelIfNotStarted` |

## 7. Pièges à éviter

- **⚠️ Ne pas écrire `chapters.downloadedAt` depuis l'interface.** Le comportement
  correct (**B6**, ADR-022) est : la marque est écrite par `2-3`'s `store()`, **après**
  le renommage atomique. Écrire la marque au moment de l'enfilement produirait le
  seul état qu'ADR-022 rend inatteignable par construction : un chapitre «
  téléchargé » sans fichier, qui s'ouvre vide et qui ment au compte du roman.
- **⚠️ Ne pas mettre la marque avant le `rename`, et ne pas la mettre du tout
  ailleurs.** Le comportement correct (**B6**, ADR-022) est : fichier d'abord, marque
  ensuite. Un crash entre les deux laisse un fichier sans marque — la **direction
  sûre**, parce que le chapitre s'offre au téléchargement au lieu de s'ouvrir comme
  complet. L'inverse, marque sans fichier, est inatteignable, et c'est cela qui rend
  B6 exprimable plutôt que simplement vraie sur le chemin heureux.
- **⚠️ Ne pas supprimer la ligne `chapters` quand on supprime un fichier.** Le
  comportement correct (**B33**, **B9**) est : supprimer le fichier, mettre
  `downloadedAt` à `null`, **garder** la ligne. Sinon la liste de chapitres d'un
  roman de 10 000 chapitres disparaît parce qu'**un** fichier a été effacé — et le
  compte de non-lus, qui est dérivé de ces lignes (B14, B48), tombe à zéro.
- **⚠️ Ne pas mettre un bouton « Annuler » sur la tuile en cours d'écriture.** Le
  comportement correct (**B6**, **B19**) est : la tuile en vol n'est **pas** une
  cible, et l'annulation vit sur la barre d'état persistante, un niveau au-dessus.
  Ce qui est en cours est une **écriture** de fichier ; « garder la moitié » et
  « mettre en pause à mi-fichier » ne sont pas des états que le format de stockage
  sait représenter honnêtement.
- **⚠️ Ne pas remettre un article `downloading` à `done` au réveil.** Le comportement
  correct (**E15**, **B20**, **B6**) est : le remettre à `queued` avec `attempts`
  incrémenté, et refaire le chapitre **depuis le début**. Le remettre à `done`
  poserait la marque d'un fichier qui n'existe pas.
- **⚠️ Ne pas afficher de taille estimée.** Le comportement correct (**B18**,
  `downloads.md` § 4) est : n'afficher que **`fileSize` d'un fichier déjà sur le
  disque**, mesuré à l'instant de la suppression. L'application n'a pas de chiffre
  d'octets avant d'avoir récupéré quoi que ce soit, et « ≈ 4 Mo » serait un nombre
  que le lecteur retiendra contre l'application dès la première nuit d'une vraie
  file. Le pied de Telechargements affichant `calculating…` est le précédent : un
  chiffre absent est admis ; un chiffre inventé ne l'est pas.
- **⚠️ Ne pas mettre un chapitre en file « en attendant de la place ».** Le
  comportement correct (**E20**) est : `EnqueueRefusedForSpace` avec **zéro**
  écriture, et un dialogue qui propose **Supprimer un chapitre téléchargé** et
  **Réessayer**. Une entrée en file pour un chapitre qui ne peut pas démarrer est une
  promesse que l'application ne tient pas, et c'est la forme exacte de la fausse
  file que `browse-catalogue.md` § 4 interdit pour le catalogue.
- **⚠️ Ne pas supprimer de données pour résoudre un manque d'espace.** Le
  comportement correct (**C8**, **E20**) est : le dialogue **propose**, il ne
  **fait** rien. Sous une contrainte où la perte de données est structurellement
  acceptée, faire de la rareté une raison de perte serait l'inverse du produit.
- **⚠️ Ne pas toucher à `history_entries` ni à `reading_positions` dans une
  suppression.** Le comportement correct (**B32**, **B46**) est : ne rien y toucher.
  Une entrée d'historique prouve que le lecteur a ouvert ce chapitre ; supprimer le
  fichier ne l'invalide pas. Et une position de lecture n'est **jamais** coupée par
  une règle de conservation — supprimer un téléchargement ne rend pas le chapitre
  non lu.
- **⚠️ Ne pas mettre d'Annuler sur la suppression d'un téléchargement.** Le
  comportement correct (**C8**, `downloads.md` § 4) est : confirmation d'abord,
  **sans Annuler**. Retirer un roman de la bibliothèque est réversible **parce que
  rien n'est détruit** (B32) ; supprimer la copie téléchargée **est** la destruction,
  il n'y a ni sauvegarde ni export (B31), donc un Annuler devrait promettre de
  retélécharger un contenu qui a peut-être changé ou disparu.
- **⚠️ Ne pas ajouter de bouton « Tout sélectionner » à la feuille de sélection.**
  Le comportement correct (**B18**) est : la sélection est *déjà* le sixième choix,
  « un ensemble choisi à la main ». Un bouton « tout » est l'exact contraire de
  délibéré, et il rendrait le raccourci que B18 refuse d'exposer — « tous les
  chapitres y compris lus » — atteignable en un tap.
- **⚠️ Ne pas utiliser un `Row` pour les compteurs de la feuille de sélection.** Le
  comportement correct (**E14**, `14-design-tokens.md` § Text scale) est : une
  `Wrap` de `StatusChip`. Un `Row` de compteurs déborde à l'échelle système 200 %, et
  une disposition qui déborde à grande échelle est un défaut, pas un détail
  cosmétique.

### 11.5 Vérifications manuelles

**Toutes les vérifications se font à une seule largeur : 360dp.** C'est la largeur de
conception (`design-system.md` § 1.7 : `< 600dp` est *le seul* layout que v1 livre)
et la seule largeur des tests de widgets. Il n'y a **pas** de « vérifier chaque
point de rupture » : **ADR-019** exclut tablette, bureau, rail et deux-panne ; au-delà
de 600dp la disposition **cesse de grossir et se centre**. Il n'y a donc rien à
vérifier à 600dp, 1024dp ou 1440dp.
