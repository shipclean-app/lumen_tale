## 1. Résumé de la slice

`2-1` écrit **le premier adaptateur de source** : FanMTL, en un seul fichier
Dart, au-dessus du contrat `Source`. C'est la slice qui rend toute la chaîne de
lecture hors ligne possible — `2-2` nettoie et convertit ce qu'elle rapporte,
`2-3` l'écrit, `2-4` le lit sans réseau.

Le contrat a une propriété que ce plan ne doit jamais contourner :
**toutes les méthodes de lecture renvoient `BrowseOutcome<T>`** — jamais une
liste nue, jamais `null`. C'est l'expression de **B22** dans le système de
types : un résultat vide et un échec ne peuvent pas s'écrire de la même manière,
donc ils ne peuvent pas se confondre. `failure-discriminator` fournit le
vocabulaire ; `2-1` est le premier producteur réel de sondes.

**Trois faits sur FanMTL, mesurés le 2026-10-02, qui décide la forme du fichier** :

1. **La recherche texte est inatteignable.** `GET` et `POST` renvoient tous deux
   404 avec un meta-refresh, y compris pour une requête qui devrait
   correspondre. Donc `supportsSearch = false` (ADR-015, règle 5a), et
   **`/search.html` n'est pas implémenté** — c'est `B50`.
2. **Le chemin de découverte est le genre.** `/browsetags/` expose **huit**
   genres plus une entrée pseudo `all`, et `/list/<tag>/<sort>-<page>.html` rend
   une page pleine. « Trouver un roman » veut dire parcourir des tags.
3. **La prose n'est pas dans des `<p>`.** Un chapitre contient **zéro** `<p>` :
   les paragraphes sont des nœuds de texte nus séparés par `<br><br>`. C'est un
   fait pour `2-2`, mais la sélection de l'article est ici, et le bon sélecteur
   est `.chapter-content` — **pas** `#chapter-article`, qui enveloppe le
   sélecteur de police et les boutons Précédent/Suivant.

**User stories couvertes** : US-01, US-03, et US-16 par le chemin d'échec
**Règles métier couvertes** : B2, B3, B5, B10, B22, B23, B29, B41, B50
**Edge cases couverts** : E1, E2, E3, E4, E5, E8, E16, E21

### 2.1 Schémas de validation

**Aucun nouveau schéma.** `local-store` est livrée : `novels` et `chapters`
existent avec toutes leurs colonnes, et `schemaVersion` reste à 1.

Ce que `2-1` **produit**, ce sont des objets `domain` — `Novel`, `Chapter`,
`NovelsPage` — et **ce n'est pas** `2-1` qui les écrit en base. Qui écrit quoi :

```
novels   écrit par  2-5 (ajout à la bibliothèque)  et  6-4 (mise à jour)
chapters écrit par  2-5 (liste complète au premier ajout)  et  6-4 (nouveaux)
```

`2-1` est **lecture de site pure** : elle parle à FanMTL et rend des modèles. La
première ligne qu'elle produit est un `novels.url` **relatif**
(`/novel/ke383028.html`), jamais une URL complète — règle 3.

### 2.2 Types et interfaces

**Le contrat, tel que `03-source-system.md` le déclare, avec la substitution de
`failure-discriminator`.** `architecture.md` § 5.1 énonce en prose que *toutes*
ces méthodes rendent `BrowseOutcome<T>` ; son bloc de code montre
`Future<NovelsPage>` pour les quatre premières, ce qui est antérieur à la
fondation. **Ce plan suit la prose** — B22 est SC-6, et un catalogue qui peut
rendre une liste nue est exactement ce que SC-6 interdit. Le point est signalé
en § 7 et dans le rapport.

```dart
// lib/domain/sources/source.dart — le contrat, transposé de source-api,
// avec fetchChapterContent remplaçant getPageList.
abstract class Source {
  /// Stable, unique id. MD5 of '${name.toLowerCase()}/$lang/$versionId'.
  String get id;

  String get name;
  String get lang;              // ISO 639-1 ('en', 'fr', ...)
  bool get supportsLatest;

  /// Whether this site GENUINELY implements search — i.e. its own search
  /// returns results a reader would call useful. See rule 5a and ADR-015.
  /// False = the UI offers genre/tag browsing instead, never a search box.
  bool get supportsSearch;

  /// Filters declared by the source for search AND for genre browsing.
  /// Empty list = no filters. The platform never interprets their states.
  FilterList get filterList;

  /// **Toutes quatre rendent `BrowseOutcome<T>`.** B22 : la réponse analysée
  /// avec le signal de vide du site → BrowseEmpty ; 2xx sans les éléments
  /// attendus, erreur d'analyse, ou statut non-succès → BrowseFailed.
  Future<BrowseOutcome<NovelsPage>> getPopularNovels(int page);
  Future<BrowseOutcome<NovelsPage>> getLatestNovels(int page);
  Future<BrowseOutcome<NovelsPage>> searchNovels(
    int page,
    String query,
    FilterList filters,
  );
  Future<BrowseOutcome<NovelUpdate>> getNovelUpdate(
    Novel novel,
    List<Chapter> chapters, {
    required bool fetchDetails,
    required bool fetchChapters,
  });

  Future<BrowseOutcome<Novel>> getNovelDetails(Novel novel);
  Future<BrowseOutcome<List<Chapter>>> getChapterList(Novel novel);
}

abstract class HttpSource extends Source {
  /// No trailing slash.
  String get baseUrl;

  /// Bump when URLs break, so a user's stored novel keeps resolving
  /// (rule 1 — the id is derived from it, and 18-external-contracts.md).
  int get versionId;
}

abstract class ParsedHttpSource extends HttpSource {
  /// Raw HTML of a chapter. This replaces Mihon's getPageList (images).
  ///
  /// Rule 11: **conversion to Markdown is not the source's job.** The source
  /// selects the article node, extracts nothing else, joins the pages in the
  /// site's order when a chapter runs over several, and stops there.
  Future<BrowseOutcome<String>> fetchChapterContent(Chapter chapter);
}
```

## 3. Algorithmes critiques

### 3.1 Identité stable (couvre **B3**, règle 1)

```
md5(texte) = 32 caractères hexadécimaux de [0-9a-f]

Source.id      = md5('${name.toLowerCase()}/$lang/$versionId')
                 = md5('fanmtl/en/1')
                 = f321cc5e31408b67cc64f3c498053e71

novel.id       = md5('${source.id}${Novel.url}')
                 = md5('f321cc5e…31//novel/ke383028.html')
                 = 90db9662f191bf2418033ab0bee1e629

chapter.id     = md5('${novel.id}${Chapter.url}')
                 = md5('90db9662…629//novel/ke383028_1.html')
                 = 3003a98742f53c4b4f2ae62d8105a4e9
```

**Les trois valeurs ci-dessus sont figées dans les tests.** Elles ne sont pas des
exemples : ce sont les valeurs attendues, écrites à la main dans le test, de sorte
qu'un changement de composition — un slash en trop, un `.trim()` oublié, une
casse différente — casse un test au lieu de produire des identifiants qui
« marche à peu près ».

Les trois propriétés que l'hexadécimal donne gratuitement, et que `2-3` utilise :

```
un id ne contient NI '/' NI '.' NI ESPACE
  → il est sûr comme nom de fichier et comme segment de chemin (C5)
  → `2-3` peut écrire <support>/chapters/<novelId>/<ordinal>.md sans vérifier

B2 : source.id est dans novel.id
  → deux romans homonymes de deux sites ne peuvent pas fusionner (E17)

B3 : rien ici ne dépend d'une horloge, d'un compteur, ni d'un aléa
  → le même roman donne le même id après un redémarrage et après une mise à jour
```

### 3.2 URL : relatives partout, base 0-indexée à la frontière (règles 2 et 3)

```
baseUrl = 'https://www.fanmtl.com'          # PAS de barre oblique finale (règle 2)

Chemins vérifiés :
  détails + liste de chapitres   /novel/<id>.html            ex. /novel/ke383028.html
  corps d'un chapitre            /novel/<id>_<n>.html        ex. /novel/ke383028_1.html
  catalogue / tag / pagination   /list/<tag>/<sort>-<page>.html
  derniers chapitres             /updates/
  index des genres               /browsetags/

⚠️ Le <page> de FanMTL est **0-based**. L'argument `page` du contrat est
   **1-based** (« page numbers are 1-based », § Models). Conversion à la
   frontière, jamais ailleurs :

     requestPage = contractPage - 1
     contractPage = requestPage + 1

   Un test le prouve dans les deux sens : page 1 → «-0.html», page 2 → «-1.html».
   Le lecteur ne voit que la page 1 (browse-catalogue.md § 8) ; la pagination
   est déclenchée par le défilement, jamais par un numéro.

Stockage :
  Novel.url   = setUrlWithoutDomain(resolve(novel.url))   # chemin + requête
  Chapter.url = setUrlWithoutDomain(resolve(chapter.url))
  → JAMAIS une URL complète. Les hôtes changent ; une URL absolue stockée
    casse en silence.
```

### 3.3 Lecture d'un catalogue — toutes les branches (couvre **B22**, **E4**, **E5**, **E8**)

`_readCatalogue` est le chemin partagé par `getPopularNovels` et
`getLatestNovels`. Il est écrit ici en entier parce que **c'est le chemin que SC-6
démontre**.

```
_readCatalogue(page, kind) -> BrowseOutcome<NovelsPage>:

  # ── 1. construire le chemin ────────────────────────────────────────────
  sort  = kind == popular ? 'all-lastdotime' : 'all-lastupdate'
  tag   = le SelectFilter de filterList, PASSE PAR LE SITE (règle 5)
  path  = '/list/$tag/$sort-${page - 1}.html'      # base 0, § 3.2
         ou '/updates/' si kind == latest           # § 3.2, chemin vérifié

  # ── 2. une seule requête. PAS de fetch spéculatif (B5) ────────────────
  fetch = await _client.get(path)

  # ── 3. SONDER le corps, puis classer ───────────────────────────────────
  # ⚠️ L'ORDRE EST LE POINT. On ne classe JAMAIS avant d'avoir cherché les
  #    éléments attendus : « HTTP 200 » seul ne dit rien, et une page dont le
  #    conteneur a été renommé est exactement le cas que 0-1 a fabriqué.

  doc = fetch est FetchSucceeded ? parseDocument(fetch.body) : null
  rows = doc == null ? [] : doc.querySelectorAll(FanMtlSelectors.catalogueRow)

  content =
      doc == null                    -> ParseBroke()
    : rows.isEmpty && le conteneur de liste attendu est absent
                                   -> ExpectedContentAbsent()      # E4, E8, SC-6
    : sinon                          -> ExpectedContentFound(rows.length)

  attempt = ReadAttempt(
    stage: ReadStage.catalogue,      # PAS genreListing : la policy par défaut
                                      # est zeroIsBroken, ce qui est correct
                                      # (§ 3.4)
    fetch: fetch,
    content: content,
    siteEmptySignal: <§ 3.5>,
    expectedSelector: FanMtlSelectors.catalogueRow,
    requestPath: path,
  )

  switch classify(attempt):                        # failure-discriminator
    BrowseFailed : return tel quel                # aucune liste n'est rendue
    BrowseEmpty  : return tel quel
    BrowseSucceeded :
        novels = rows.map(parseNovel).whereType<Novel>().toList()
        # ⚠️ Une ligne dont le titre est illisible est **supprimée**, jamais
        #    rendue avec un titre vide (browse-catalogue.md § 8). La suppression
        #    est journalisée localement avec le source id et le chemin — JAMAIS
        #    avec le titre du site (B29).
        return BrowseSucceeded(NovelsPage(
          novels: List.unmodifiable(novels),
          hasNextPage: rows.length >= 30,   # 30 par page, mesuré
        ))
```

### 3.4 La politique de zéro, et pourquoi le catalogue est `zeroIsBroken`

```
kZeroItemsPolicyByStage :  genreListing -> zeroIsGenuine
                          tout le reste  -> zeroIsBroken

Un `/list/<tag>/…` qui rend 200 avec un conteneur intact et zéro roman
  → SourceLayoutChanged, PAS une page vide.
```

La raison est celle de B22, mot pour mot : *the discriminator is the site's own
empty-result signal, **never the absence of a match***.* Sans signal du site, on
ne peut pas démontrer que « zéro » veut dire « rien » — et le coût d'une erreur
est asymétrique. Rendre une liste vide alors que le site est cassé est
**SC-6** ; rendre une page vide alors qu'un tag est réellement vide fait perdre au
lecteur une liste, ce qui est réparable.

Le seul `zeroIsGenuine` par défaut est `genreListing`, parce que
`browse-genre.md` § 4 le spécifie : *« The source declares no genres at all — a
real state, not an error, and not a broken source ».*

### 3.5 Le signal de vide du site — où il vit, et pourquoi FanMTL ne l'atteint pas (couvre **B50**)

```
siteEmptySignal = doc.body.text.contains(FanMtlSelectors.siteEmptyMarker)
                      ? FanMtlSelectors.siteEmptyMarker
                      : null
```

`18-external-contracts.md` § FanMTL point 7, mot pour mot : la chaîne
*« No relevant content found »* **existe sur la page d'échec de recherche du
site**, et « Do not read it as 'no results' on a browse page — it lives on the
search failure page, so it discriminates for search calls only ».

Conséquence directe pour cette slice, et c'est le cœur de **B50** :

```
FanMTL : supportsSearch = false
  → l'UI ne rend AUCUN champ de recherche (règle 5a, ADR-015)
  → searchNovels n'est jamais appelé (§ 3.6)
  → BrowseEmpty est INATTEIGNABLE pour FanMTL en v1

  ⇔ l'application a deux états pour ce site, et elle doit le dire.
    architecture.md § 2.2 : « A source with no site-supplied signal gets two
    states, and the UI must say which situation it cannot distinguish. »

  ⇔ browse-genre.md § 4 « Empty — no data » le formulated déjà :
    « an empty genre index is not an empty screen », et le texte distingue
    « declares nothing » de « could not read » **par construction** :
    pas de couleur d'erreur, pas d'icône, pas de réessai.
```

`0-2` est la slice qui mesure cela sur les fixtures. **Si `0-2` découvre un
signal présent sur une page de catalogue**, `ReadStage.catalogue` passe à
`zeroIsGenuine` et la branche 9a devient atteignable — **une ligne à changer**,
et c'est la mesure qu'on demandait.

### 3.7 Liste de chapitres — complète, ordonnée, jamais renumérotée (couvre **E1**, **E2**, **B10**)

```
getChapterList(novel) -> BrowseOutcome<List<Chapter>>:

  path = novel.url                      # relatif, déjà stocké (règle 3)
  fetch = await _client.get(path)
  doc   = parseDocument(fetch.body) si fetch est FetchSucceeded, sinon null

  rows = doc == null ? [] : doc.querySelectorAll(FanMtlSelectors.chapterRow)

  # ⚠️ AUCUNE PAGINATION ICI. B9 : la liste est complète quelle que soit sa
  #    longueur ; au-delà de 10 000 chapitres l'app le DIT, elle ne tronque pas.
  #    Un « show more » ici serait une entrée différée, donc une entrée perdue.

  content =
      doc == null                  -> ParseBroke()
    : conteneur de chapitres absent -> ExpectedContentAbsent()   # E2, E4, E8
    : sinon                        -> ExpectedContentFound(rows.length)

  attempt = ReadAttempt(
    stage: ReadStage.chapterList,  # zeroIsBroken : une liste de chapitres vide
                                   # n'est JAMAIS « ce roman n'a pas de
                                   # chapitres », c'est « je n'ai pas su la lire »
    fetch: fetch, content: content,
    expectedSelector: FanMtlSelectors.chapterRow,
    requestPath: path,
  )

  switch classify(attempt):
    BrowseFailed : return tel quel     # AUCUNE liste de chapitres n'est rendue
    BrowseEmpty  : return tel quel     # inatteignable, cf. § 3.5
    BrowseSucceeded :
        chapters = []
        for (row in rows):
            name   = texte du titre du site, VERBATIM (B10)
            if name.isEmpty: name = null      # rendu « Untitled », jamais un index
            number = ChapterRecognition.parse(name)
                     # ⚠️illisible -> -1, JAMAIS 0. `0` est un vrai numéro
                     # de chapitre (Extra, Omake, note d'auteur) et confondre
                     # les deux est une violation de B10. Le défaut de la
                     # colonne est -1, et `0` reste atteignable.
            url    = setUrlWithoutDomain(resolve(lien de la ligne))
            chapters.add(Chapter(
              name: name, number: number, url: url,
              dateUpload: <lu sur la page, ou null>,
            ))
        # ⚠️ AUCUNE déduplication. E10 : le site liste deux fois le même titre,
        #    les deux lignes sont rendues, l'application ne fusionne pas et ne
        #    supprime pas. L'ordre est celui du site, index par index.
        return BrowseSucceeded(List.unmodifiable(chapters))
```

**`ordinal` n'est pas produit ici, et il faut le dire.** `Chapter`
(`03-source-system.md` § Models) ne porte pas de champ d'ordre : `url`, `name`,
`number`, `scanlator?`, `dateUpload`, `memo`. L'ordre du site est donc **la
position dans la liste rendue**, et c'est le persiteur — `2-5` au premier ajout,
`6-4` ensuite — qui écrit `chapters.ordinal = index`. **Trier par `number` est
interdit** : il vaut `-1` quand il est illisible et il repart à chaque volume, un
extras ou une histoire annexe ; trier par là réordonne les volumes.

### 3.8 Page de chapitre — extraire, ne pas convertir (couvre **E3**, règle 11)

```
fetchChapterContent(chapter) -> BrowseOutcome<String>:

  # 04-html-to-markdown.md règle 4 : un chapitre réparti sur plusieurs pages
  # doit être assemblé par la SOURCE, dans l'ordre du site, AVANT conversion.
  # L'ordre de la liste fait autorité ; les index venant du site sont ignorés.

  pages = [ <chemin de la page 1> ]
  loop:
      next = lien « page suivante » sur la page courante, résolu contre baseUrl
      if next == null or next == page précédente déjà vue: stop      # anti-boucle
      pages.add(next)

  fragments = []
  for path in pages:
      fetch = await _client.get(path)
      doc   = parseDocument(fetch.body) si fetch est FetchSucceeded, sinon null
      art   = doc?.querySelector(FanMtlSelectors.chapterContent)   # .chapter-content
      if art == null:
          # E3 : une page de continuation qui ne s'assemble pas est
          # layout_changed SUR CE CHAPITRE. Aucun texte partiel n'est montré,
          # aucun texte à moitié assemblé n'est stocké (B6).
          return BrowseFailed(classify(SourceLayoutChanged(
            failedSelector: FanMtlSelectors.chapterContent, status: …)))
      # ⚠️ On extrait le CONTENU, pas #chapter-article. Ce dernier contient
      #    `.chapter-header` (titre du roman h1, titre du chapitre h2) et
      #    `.control-action` (choix de police + Précédent/Suivant). Les garder
      #    livrerait un sélecteur de police dans la prose du lecteur.
      #
      # ⚠️ Le `<script src=/d/js/ad/page_01.js>` vit DANS le div de contenu
      #    (mesuré). Il est retiré par `2-2` en tant que `<script>`, et il ne
      #    doit JAMAIS être demandé : `/d/` est dans robots.txt. Le retirer est
      #    ce qui l'empêche.
      fragments.add(art.outerHtml)

  # ⚠️ On rend du HTML, PAS du Markdown. Règle 11 : la conversion n'est pas le
  #    travail de la source. `2-2` l'extrait, nettoie et convertit.
  return BrowseSucceeded(fragments.join('\n\n'))
```

Branches, toutes explicites :

| Situation | Issue | Règle |
|---|---|---|
| Page 1 en 200, `.chapter-content` présent | `BrowseSucceeded` | E3 |
| Page 1 en 200, `.chapter-content` **absent** | `SourceLayoutChanged` | E4, E8 |
| Page 1 + 2 pages de continuation, toutes lisibles | `BrowseSucceeded`, **3 fragments joints dans l'ordre du site** | E3, B8 |
| Une page de continuation est cassée | `SourceLayoutChanged` — **rien** n'est rendu, rien n'est stocké | E3, B6 |
| Le lien « suivante » boucle sur une page déjà vue | Arrêt de la boucle, sortie avec ce qui est assemblé | anti-boucle |
| `.chapter-content` présent mais vide | `BrowseSucceeded` avec un fragment vide — **ce n'est pas à `2-1` de juger**, c'est le seuil E18 de `2-2` | § 3.7 |

### 3.9 Mise à jour d'un roman (couvre **E16**, **B5**, **B38**)

```
getNovelUpdate(novel, existingChapters, {fetchDetails, fetchChapters})
  -> BrowseOutcome<NovelUpdate>:

  ⚠️ Cette méthode n'est JAMAIS appelée par un écran. Seul `6-4` l'appelle,
     depuis le bouton « vérifier la bibliothèque » (B36). B5 : rien n'est
     demandé sans que le lecteur l'ait demandé.

  # a. détails
  updated = fetchDetails ? (await getNovelDetails(novel)) : BrowseSucceeded(novel)

  # b. liste de chapitres
  listed = fetchChapters ? (await getChapterList(novel)) : BrowseSucceeded([])

  # c. NE RÉÉMETTRE QUE CE QUE L'APPELLANT N'A PAS
  #    § Models : « getNovelUpdate receives the **existing** chapters so the
  #    source can return only what changed; a source must not re-emit chapters
  #    the caller already holds. »
  known = existingChapters.map((c) => c.url).toSet()
  fresh = listed.items.where((c) => !known.contains(c.url))

  # d. AUCUNE conclusion sur ce qui n'est pas là
  # ⚠️ Ne jamais renvoyer « rien de nouveau » comme affirmation. Un site peut
  #    avoir publié depuis la dernière vérification ; la source n'a pas le droit
  #    de conclure, elle constate. `6-4` écrit novel.lastCheckedAt (B49) et
  #    n'écrit RIEN du temps de lecture, aucun fichier, aucune file (B38).
  return BrowseSucceeded(NovelUpdate(novel: updated.items, chapters: fresh))
```

| ID | Règle (PRD) | Implémentée où | Approche |

A successful response whose expected content elements are simply absent, a parse error, or a non-success status → the site could not be read, reported as a failure with a retry. **The discriminator is the site's own empty-result signal, never the absence of a match.** | § 3.3, § 3.4, § 3.5, § 3.7, § 3.8 | Chaque lecture construit un `ReadAttempt` et le passe à `OutcomeDiscriminator.classify` (§ 2 de `failure-discriminator.md`). **L'ordre est fixe : sonder le corps, puis classer.** Un 200 n'est jamais rendu comme une liste. `catalogue` et `chapterList` sont `zeroIsBroken`, donc « zéro avec conteneur intact » devient `SourceLayoutChanged`, jamais une page vide |

| **B41** | Searching inside a site searches whatever that site searches. ### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| **E1** | Chapter list of extreme length — la liste complète reste affichée dans l'ordre, rien n'est abandonné ni tronqué | `getChapterList` ne pagine **pas** et n'a pas de limite : `querySelectorAll` rend tout. `ordinal` est l'index du site (B9). Le catalogue, lui, **est** paginé — `hasNextPage` vient du comptage des lignes, et l'application n'invente jamais une fin | § 3.3, § 3.7 |
| **E2** | Inconsistent chapter titles and numbering — rendus verbatim, tous sélectionnables, aucun jeté pour être irrégulier | `ChapterRecognition` (§ 3.7). Un titre vide devient `null` et s'affiche *Untitled*, **jamais** un index. `number = -1` s'affiche en tiret cadratin. Un chapitre sans `<p>`, un *Extra*, un *Omake* : tous présents, tous sélectionnables | § 3.7 |
| **E3** | Chapter split across several pages — assemblées dans l'ordre d'origine avant lecture | La source suit la chaîne « suivante », **ignore les index du site** (§ Models : *the order of the list is authoritative*), extrait `.chapter-content` de chaque page et joint les fragments. ## 7. Pièges à éviter

- **⚠️ Ne pas rendre une liste nue.** Le comportement correct (**B22**,
  `failure-discriminator`) est `Future<BrowseOutcome<NovelsPage>>` pour les
  quatre méthodes de catalogue et de mise à jour. Rendre `List<Novel>` rend le
  compilateur incapable de distinguer « rien trouvé » de « site cassé », et c'est
  la première des trois réponses interdites par § 2.2 de l'architecture.
- **⚠️ Ne pas classer avant d'avoir sondé le corps.** Le comportement correct
  (**B22**, **E8**) est : fetch → `querySelectorAll` → `ReadAttempt` → `classify`.
  Classer sur le statut seul donne `SourceUnavailable` pour une page dont le
  conteneur a été renommé, et le lecteur reçoit « le site ne répond pas » au lieu
  de « les pages de ce site ont changé ». La seconde phrase est celle qui mène à
  une réparation.
- **⚠️ Ne pas utiliser `#chapter-article` comme sélecteur de contenu.** Le
  comportement correct (`18-external-contracts.md` point 2) est `.chapter-content`.
  `#chapter-article` enveloppe le titre du roman, le titre du chapitre et le
  sélecteur de police Default/Dyslexic/Roboto/Lora — le lecteur recevrait un
  sélecteur de fonte dans son texte.
- **⚠️ Ne pas convertir en Markdown ici.** Le comportement correct (règle 11,
  `04-html-to-markdown.md`) est de rendre du **HTML brut**, `.chapter-content`
  extrait. La conversion est le travail de `2-2`, et c'est la seule façon dont
  chaque source peut ajuster son extraction sans forker un paquet tiers (ADR-003).
- **⚠️ Ne pas implémenter `/search.html` ni `/e/search/index.php`.** Le
  comportement correct (**B50**, règle 5a) est `supportsSearch = false` et
  `searchNovels` qui lève `SourceException` avant tout fetch. Les deux chemins
  renvoient 404 avec un meta-refresh — implémenter « quand même » produirait un
  site cassé présenté comme une recherche sans résultat, ce que **B50 nomme
  explicitement** comme un défaut.
- **⚠️ Ne pas écrire `0` quand un numéro de chapitre est illisible.** Le
  comportement correct (**B10**, règle 9) est `-1`. `0` est un vrai numéro — un
  *Extra*, un *Omake*, une note d'auteur — et la colonne a pour défaut `-1`
  précisément pour que les deux restent distinguables.
- **⚠️ Ne pas dédupliquer ni réordonner la liste de chapitres.** Le comportement
  correct (**B10**, **E10**) est l'ordre du site, un `Chapter` par ligne, sans
  fusion. Deux entrées de même titre restent deux lignes. Et **ne jamais trier
  par `number`** : il vaut `-1` quand il est illisible et il repart à chaque
  volume.
- **⚠️ Ne pas écrire une URL complète dans `Novel.url` ou `Chapter.url`.** Le
  comportement correct (règle 3) est `setUrlWithoutDomain`, donc chemin + requête.
  Les hôtes changent ; une URL absolue stockée casse en silence et sans aucune
  entrée de journal, parce qu'elle semble encore correcte.
- **⚠️ Ne pas confondre la base de pagination de FanMTL avec celle du contrat.**
  Le comportement correct (`18-external-contracts.md`, `browse-catalogue.md` § 8)
  est `requestPage = contractPage - 1`, **à la frontière**. Le contrat est
  1-based (« page numbers are 1-based »), FanMTL est 0-based.
- **⚠️ Ne pas deviner un sélecteur.** Le comportement correct
  (`18-external-contracts.md`, règle 12) est de le lire sur la fixture de `0-1`
  et de le **reporter dans `18-external-contracts.md`** avant de l'utiliser. Un
  sélecteur deviné ne matche rien, toute page devient `SourceLayoutChanged`, et
  la fixture fabriquée par `0-1` devient indiscernable d'un site qui marche.
- **⚠️ Ne pas journaliser un titre de chapitre ni une URL de requête.** Le
  comportement correct (**B29**) est : id de source, chemin, nombre de lignes
  supprimées. Un titre de chapitre est du contenu tiers, et une URL de requête
  contient les mots du lecteur.
- **⚠️ Ne pas faire de `getNovelUpdate` un point d'entrée de téléchargement.**
  Le comportement correct (**B38**) est qu'il rend des `Chapter` et **rien
  d'autre** ; seul `6-4` l'appelle, et `6-4` n'écrit dans `queue_items`. Le
  chemin « vérification → téléchargement » doit être introuvable par `grep`.

**Quatre questions ouvertes. Aucune n'est tranchée ici.**

1. **`core/network` n'a aucune slice qui le possède.** `state.json` liste cinq
   fondations — `apk-pipeline`, `local-store`, `failure-discriminator`,
   `localisation`, `theme-type` — et aucune n'est le client dio ; aucune slice ne
   le déclare non plus dans `depends_on`. **Option la moins coûteuse et
   réversible** : `2-1`, premier consommateur, construit le minimum — client dio,
   UA honnête `LumenTale/<version> (personal reader)` (ADR-014), limiteur
   partagé, `Retry-After` honoré, et le mapping vers `FetchResult`.
   **Question ouverte** : à qui appartient `core/network` en entier, et est-ce
   `2-1` qui doit le porter ?
2. **Aucun paquet ne fournit MD5, et le contrat l'exige.** La règle 1 exige MD5 ;
   `pubspec.yaml` ne déclare ni `crypto` ni quoi que ce soit qui le fasse, et
   `architecture.md` § 1.1 dit *« Nothing else may be added »*. **Option
   recommandée** : `flutter pub add crypto` — Dart pur, sans FFI, absent de la
   liste bannie, et `17-security.md` règle 13 n'est donc pas déclenché.
   **L'alternative** — écrire MD5 à la main — n'est autorisée par aucune règle et
   ne doit pas être choisie. **Question ouverte** : l'ajout de `crypto` est-il
   accepté, ou `architecture.md` § 1.1 doit-il être amendé ? Tant que la
   question est ouverte, les trois valeurs MD5 de § 3.1 restent **écrites à la
   main dans les tests**, ce qui les fige indépendamment de l'implémentation.
3. **Trois sélecteurs ne sont pas documentés** : `catalogueRow`, `novelSummary`,
   `chapterRow`. Ils sont `String` vides dans § 2.2, donc le code compile, et le
   test `every FanMTL selector is filled in` les refuse — un test rouge est le
   résultat correct. Ils doivent être lus sur les fixtures de `0-1`
   (`/list/<tag>/…`, `/novel/<id>.html`) et reportés dans
   `18-external-contracts.md` **avant** que les tests de catalogue et de liste de
   chapitres ne soient rendus verts. **Aucune valeur n'est devinée ici.**
4. **`Source.id` est un MD5, et les exemples de l'architecture montrent
   `fanmtl`.** `app_database.dart` et la règle 1 disent MD5 ; `architecture.md`
   § 4.1 donne `fanmtl` comme exemple de `novels.sourceId`. Ce plan suit la règle 1
   et `app_database.dart`, parce que `2-3` § 7 s'appuie sur « `chapter.novelId` est
   un MD5, donc sans `/` ni `.` », et que cette propriété est utilisée pour écrire
   des chemins. **Question ouverte** : l'exemple de § 4.1 est-il illustratif, ou
   les colonnes doivent-elles porter le slug lisible ? Les deux ne sont pas
   compatibles, et le choix change `SourceManager`.
