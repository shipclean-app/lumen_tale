## 1. Résumé de la slice

La fondation `localisation` est **déjà livrée** : `l10n.yaml` épingle
`arb-dir` et `output-dir`, `pubspec.yaml` déclare `flutter: generate: true`, les
deux ARB existent dans `lib/l10n/`, le code généré est commité dans
`lib/l10n/generated/`, et `lib/main.dart` porte déjà `localeListResolutionCallback`
avec repli sur le français. **Cinq tests de widget** couvrent ce mécanisme.

Ce qui manque est le **contenu** : 16 clés existent, toutes de navigation ou
d'état vide générique. B28 exige *chaque* chaîne visible par l'utilisateur dans
les deux langues, **y compris tous les messages d'erreur et de statut de
téléchargement**. Ce sont ces derniers qui manquent le plus, parce qu'ils
n'existent nulle part tant que la taxonomie d'échecs n'a pas de slice qui les
rende.

Cette slice produit donc trois choses :

1. **L'inventaire des clés** — toute la copie des dix-huit fichiers d'écran, plus
   les sept causes d'échec de `architecture.md` § 5.2, plus les trois états de
   B22, plus les quatre `DownloadState`.
2. **Le mapping exception → message**, en un seul endroit
   (`13-error-handling.md` règle 5), avec une phrase par cause dans les deux
   langues, et une phrase qu'un lecteur sur appareil emprunté peut **lire à voix
   haute** (C12).
3. **La barrière de complétude** — un test qui échoue si une clé existe dans un
   ARB et pas dans l'autre, ou si une chaîne visible est écrite en dur dans un
   widget.

Elle ne construit **aucun écran**, ne dessine **aucune** icône, et **n'ajoute pas
de sélecteur de langue** : B28 interdit un sélecteur de langue dans
l'application, et `settings.md` § 11 le dit par son titre — *Deliberately absent —
and why that is not a gap*.

**User stories couvertes** : US-13, US-16
**Règles métier couvertes** : B28
**Edge cases couverts** : E12

## 2. Contrats de données (code)

### 2.1 Schémas de validation

**Aucun schéma, et aucun modèle.** Une localisation n'a pas de « schéma de
validation » au sens de `drift` : elle a un **fichier ARB**, dont la structure
est déjà épinglée par `l10n.yaml`, et deux règles que `gen-l10n` vérifie
lui-même — une clé sans jumeure dans l'autre fichier est une erreur de
génération, et un placeholder absent d'un `@key` l'est aussi.

Ce que cette slice ajoute **n'est pas une clé** mais un **contrat de nommage**,
et il faut l'écrire parce que `16-i18n.md` règle 3 et les fichiers d'écran ne sont
pas d'accord sur la forme (question ouverte de § 7) :

```dart
// lib/core/utils/i18n/app_error_strings.dart
import 'package:lumen_tale/core/utils/errors/app_exception.dart';
import 'package:lumen_tale/l10n/generated/app_localizations.dart';

/// La forme qu'un message d'erreur doit avoir pour être affichable.
///
/// **C'est un `enum`, pas une `String`.** `13-error-handling.md` règle 5 exige un
/// endroit unique qui mappe exception → message localisé, et
/// `architecture.md` § 5.2 interdit « a bare `Exception`, a `String` reason ».
/// Une clé `String` libre dans un appel de widget est exactement la moitié du
/// travail que cette classe rend impossible.
enum AppErrorString {
  // — les sept causes d'architecture.md § 5.2, dans son ordre ————————
  noConnection,
  rateLimited,
  sourceLayoutChanged,
  sourceUnavailable,
  itemRemovedAtSource,
  storageFull,
  parseFailed,

  // — les trois états de B22, qui ne sont pas des exceptions mais des
  //   résultats, et qui doivent être aussi traduits que les autres ———————
  browseEmpty,
  browseFailed,
  browseSucceeded,

  // — les quatre DownloadState de app_database.dart ————————————————————
  downloadQueued,
  downloadDownloading,
  downloadDone,
  downloadFailed,

  // — les échecs applicatifs qui n'ont pas de cause site ————————————————
  settingsLoadFailed,
  settingsWriteFailed,
  historyClearFailed,
  historyCountUnavailable,
  notificationPermissionDenied,
  checkCancelled,
}

/// Le seul endroit du produit où une exception devient une phrase.
///
/// Une méthode par cause, jamais un `switch` sur `AppException` dans un widget :
/// `13-error-handling.md` règle 5 impose un point unique, et c'est ce qui permet
/// d'ajouter une cause sans chercher dans vingt écrans.
extension AppErrorCopy on AppLocalizations {
  AppErrorString forAppException(AppException error) => switch (error) {
    NetworkException() => AppErrorString.noConnection,
    // `RateLimitedException` porte sa durée ; la phrase qui attend est
    // « Réessayer dans {duration} » — voir rateLimited() plus bas.
    RateLimitedException() => AppErrorString.rateLimited,
    SourceException() => AppErrorString.sourceLayoutChanged,
    StorageException() => AppErrorString.storageFull,
    ChapterNotAvailableException() => AppErrorString.parseFailed,
    CancelledException() => AppErrorString.checkCancelled,
    DatabaseException() => AppErrorString.settingsLoadFailed,
  };

  /// La phrase. **Jamais** le nom d'une classe d'exception, jamais un code, jamais
  /// `e.toString()` (règle 3).
  ///
  /// `recoverable` décide si la phrase porte une action : « Réessayer » pour ce
  /// qui peut être retenté, « Signaler le bug » pour ce qui ne peut pas. C'est la
  /// colonne « Recoverable by retry » de § 5.2, rendue exécutable.
  String message(AppErrorString which, {Duration? retryAfter}) =>
      switch (which) {
        AppErrorString.noConnection => errorNoConnection,
        AppErrorString.rateLimited => retryAfter == null
            ? errorRateLimited
            : errorRateLimitedIn(retryAfter.inSeconds),
        AppErrorString.sourceLayoutChanged => errorSourceLayoutChanged,
        AppErrorString.sourceUnavailable => errorSourceUnavailable,
        AppErrorString.itemRemovedAtSource => errorItemRemovedAtSource,
        AppErrorString.storageFull => errorStorageFull,
        AppErrorString.parseFailed => errorParseFailed,
        AppErrorString.browseEmpty => browseEmpty,
        AppErrorString.browseFailed => errorSiteUnreadable,
        AppErrorString.browseSucceeded => browseSucceeded,
        AppErrorString.downloadQueued => downloadQueued,
        AppErrorString.downloadDownloading => downloadDownloading,
        AppErrorString.downloadDone => downloadDone,
        AppErrorString.downloadFailed => downloadFailed,
        AppErrorString.settingsLoadFailed => errorSettingsLoad,
        AppErrorString.settingsWriteFailed => errorSettingsWrite,
        AppErrorString.historyClearFailed => errorHistoryClear,
        AppErrorString.historyCountUnavailable => errorCountUnavailable,
        AppErrorString.notificationPermissionDenied => warningNotifications,
        AppErrorString.checkCancelled => checkCancelled,
      };

  /// Ce qu'un lecteur peut faire. `null` = rien à faire hormis lire ce qui est
  /// téléchargé — et c'est le cas le plus fréquent, ce qui est le sujet de
  /// `architecture.md` § 5.2.
  String? recovery(AppErrorString which) => switch (which) {
    AppErrorString.noConnection => commonRetry,
    AppErrorString.rateLimited => null,          // attendre — B37, 17-security règle 6
    AppErrorString.sourceLayoutChanged => null, // signaler le bug — rien à retenter
    AppErrorString.sourceUnavailable => commonRetry,
    AppErrorString.itemRemovedAtSource => commonBack,
    AppErrorString.storageFull => actionFreeSpace,
    AppErrorString.parseFailed => actionReportBug,
    AppErrorString.historyCountUnavailable => null,
    AppErrorString.notificationPermissionDenied => warningNotificationsAction,
    _ => commonRetry,
  };
}
```

### 2.2 Le contrat de nommage, en code

```dart
// lib/core/utils/i18n/arb_key.dart

/// Les **deux seules** formes autorisées pour une clé, et la règle qui décide.
///
/// `16-i18n.md` règle 3 : les clés décrivent un **sens**, pas une
/// disposition, et **une notion, une clé**. Le point médian est litéral
/// (`group.reading`) ; il devient un getter `groupReading` après
/// `gen-l10n`, ce qui est exactement la convention que `16-i18n.md` décrit
/// ailleurs dans la même règle. Les deux règles sont donc compatibles dans les
/// faits, et c'est ce que la fonction ci-dessous fixe.
extension type const ArbKey(String value) {
  /// Le getter Dart que `gen-l10n` produira. Écrit ici pour que le test de
  /// complétude puisse **vérifier** le nom plutôt que le supposer.
  String get dartGetter => value.replaceAllMapped(
        RegExp(r'[._]([a-zA-Z0-9])'),
        (m) => m[1]!.toUpperCase(),
      );

  /// `true` si la clé est dans l'espace de noms réservé aux messages d'erreur.
  /// Ce sont celles dont l'absence fait échouer la barrière de complétude avec
  /// le plus de conséquences, parce qu'un message d'erreur non traduit est un
  /// écran muet pour un lecteur sur appareil emprunté (C12).
  bool get isErrorString => const {
        'error',
        'warning',
        'browse',
        'download',
        'check',
      }.any(value.startsWith(_));
}

/// Les points que la barrière doit savoir surveiller : le mot `error` est le seul
/// préfixe qu'une exception affiche, donc une clé `error.*` absente en anglais
/// est un **écran vide**, pas un libellé laid.
const Set<String> mustBeBilingual = {
  'error', 'warning', 'browse', 'download', 'check',
};
```

### 3.1 Résolution de la locale — **toutes** les branches (couvre **B28**, **E12**)

```
_resolveLocale(preferredLocales, supportedLocales)   // déjà écrit dans lib/main.dart

  # [en, fr] + [Locale('fr')]  → Locale('fr')

  # ── branche 3 : langue non reconnue → FRANÇAIS ─────────────────────
  # [en, fr] + [Locale('de'), Locale('ja')]  → Locale('fr')

  # (app_en.arb → anglais). Le français est la langue primaire du projet
  # (16-i18n.md règle 5) ; un repli anglais afficherait au lecteur allemand
  # une langue qu'il n'a pas demandée et que l'application ne prétend pas
  # parler. C'est une faute SILENCIEUSE : rien ne signale l'erreur.

  # ── branche 4 : liste de préférences vide ou nulle ─────────────────
  # [] ou null  → Locale('fr')     # même branche que 3, même raison

  # ── branche 5 : le téléphone passe de fr à en pendant l'usage (E12) ─
  # Le MaterialApp se reconstruit, `AppLocalizations.of(context)` rend la
  # nouvelle langue, et RIEN D'AUTRE ne bouge :
  #   - aucune requête base n'est relancée
  #   - la bibliothèque, les téléchargements, les positions, l'historique
  #     sont intacts (E12 : « with no loss of library, downloads or progress »)
  #   - la requête de recherche active et la sélection multi-fiches SURVIVENT
  #     (library.md § 5 : « This branch keeps its scroll offset and its query »)
  # ⚠️ AUCUNE de ces écritures ne dépend de la locale. Une clé de tri ou un
  # filtre stocké en `shared_preferences` doit être une valeur ENUM, jamais une
  # chaîne déjà localisée : une chaîne localisée stockée devient une chaîne
  # dans une langue abandonnée au changement de téléphone.

  # ── branche 6 : une locale avec d'autres règles de pluriel ─────────
  # `chapterCount` utilise `{count, plural, =0{…} =1{…} other{…}}`.
  # Les clauses `=0` et `=1` sont testées AVANT les catégories de la locale,
  # donc elles sont correctes en français comme en anglais sans que la règle
  # CLDR ait besoin d'être connue.
  # ⚠️ Toute nouvelle clé à compteur DOIT utiliser `=0` et `=1` explicites.
  # Une clé qui écrit seulement `one`/`other` est correcte en anglais et
  # fausse en français pour 0, parce que le français classe 0 dans `one`.
```

**Trois règles d'écriture que ces phrases respectent, et que le test vérifie :**

1. **Chaque phrase se lit à voix haute et se décrit.** C'est C12 : le lecteur sur
   appareil emprunté n'a aucun moyen de renvoyer quoi que ce soit, donc la phrase
   est le canal. Aucun identifiant interne, aucun nom de sélecteur CSS, aucun nom
   de classe d'exception, aucun code.
2. **Chaque phrase d'erreur nomme ce qui est resté.** `settings.md` § 4, `history.md`
   § 4 et le tableau ci-dessus le font toutes, parce que dans un produit sans
   sauvegarde (ADR-010) une erreur sans survivances nommées se lit comme une perte.
3. **Aucune n'est un seul mot.** « Erreur. » est un écran vide habillé. Chaque
   cause a une phrase complète et, quand il y a lieu, une action.

### 3.3 La barrière de complétude (couvre **B28**)

```
translation_completeness_test():

  # ── contrôle 1 : les deux fichiers ont les MÊMES clés ───────────────
  en = keys(app_en.arb); fr = keys(app_fr.arb)
  assert(en == fr)
  # ⚠️ L'égalité est dans les DEUX sens. Une clé présente en anglais et absente
  # en français est un écran muet pour le lecteur francophone ; l'inverse est
  # un écran muet pour le lecteur anglophone. gen-l10n ne rapporte QUE la
  # première des deux.

  # ── contrôle 2 : les @@keys déclarent leurs placeholders ────────────
  for key in en:
      placeholdersInValue(en[key]) == placeholdersInMetadata(en, key)
      # et idem en français, avec le MÊME ensemble de placeholders
  # ⚠️ Une divergence de placeholders entre les deux fichiers produit une
  # chaîne qui compile et qui s'affiche avec un `{name}` littéral à l'écran.

  # ── contrôle 3 : les deux fichiers ont le MÊME @@locale ─────────────
  assert(app_en.arb['@@locale'] == 'en'); assert(app_fr.arb['@@locale'] == 'fr')

  # ── contrôle 4 : aucune clé d'erreur absente ───────────────────────
  for key in en where ArbKey(key).isErrorString:
      assert(fr.contains(key))          # redondant avec 1, mais explicite :
                                       # c'est la catégorie dont l'absence
                                       # fait le plus de dégâts

  # ── contrôle 5 : AUCUNE chaîne visible écrite en dur dans un widget ─
  # files = glob('lib/**/*.dart') moins generated/, moins *.g.dart
  for file in files:
      for line in file.lines:
          # ⚠️ On interdit Text('…'), label: '…', title: '…', tooltip: '…',
          # hintText: '…', helperText: '…', Snackbar(… '…' …)
          # et tout Dart qui passe une constante de texte à un widget.
          assert(no user-visible literal is passed to a widget)
  # ⚠️ Les exceptions sont lesjetons de design (AppLocalizations ne les
  # traduit pas : `--color-accent` n'a pas deux langues), les clés de routes,
  # et les noms de sources — qui sont des DONNÉES de site, pas de la copie.

  # ── contrôle 6 : chaque clé d'erreur a une phrase, pas un mot ────────
  for key where isErrorString:
      assert(fr[key].split(RegExp(r'[.!:]')).where((s) => s.trim().isNotEmpty).length >= 2)
  # « Erreur. » et « Failed. » échouent. « This site changed and can no longer
  # be read. » passe. C'est mécanique, donc c'est testable.
```

| Composant | Type | Fichier cible | Rôle |
|---|---|---|---|
| `AppErrorString` | enum (19 valeurs) | `lib/core/utils/i18n/app_error_strings.dart` | L'inventaire fermé des messages. **Une cause, une valeur** |
| `AppErrorCopy` | extension | idem | Le point unique exception → phrase, exigé par `13-error-handling.md` règle 5 |
| `ArbKey` | extension type | `lib/core/utils/i18n/arb_key.dart` | Le contrat de nommage et la catégorie « c'est une chaîne d'erreur » |
| `app_en.arb` / `app_fr.arb` | sources | `lib/l10n/` | Les deux moitiés, **jamais** séparées dans le temps |
| `lib/l10n/generated/*` | **généré, commité** | `lib/l10n/generated/` | Sortie de `flutter gen-l10n`, dans le **même** commit que les ARB |
| `translation_completeness_test` | test | `test/l10n/translation_completeness_test.dart` | La barrière de § 3.3 |

**Riverpod** : **aucun**. Une table de traduction n'est pas de l'état. Les
lectures se font par `AppLocalizations.of(context)`, comme les thème et les
polices.

### 4.3 États par écran

**Aucun.** Cette slice ne construit pas d'écran. Elle ne change **aucun** rendu :
elle change le **texte** que les écrans des autres slices rendent, et elle fournit
le mapping dont ils ont besoin pour écrire leurs messages d'erreur.

Le seul rendu qu'elle touche est celui de l'**échec de lecture des préférences**
(`settings.md` § 4, *Load error*) — parce qu'un `ErrorState` qui affiche une
chaîne codée en dur est exactement l'état muet que B28 interdit.

### 4.4 Formulaires

Aucun. Et surtout : **aucun sélecteur de langue**. B28 dit que la langue suit le
téléphone et qu'une langue non reconnue tombe sur le français. `settings.md` § 11
liste *An in-app language picker* parmi les absences délibérées, avec sa raison :
*« A picker would be a second source of truth for a value the platform already
owns »*. La ligne `Language` de l'écran est **en lecture seule**, sans chevron,
sans ondulation, sans état pressé — et le dire fait partie du travail de cette
slice, parce qu'une ligne qui a l'air cliquable et qui ne l'est pas apprend au
lecteur à ne plus croire les lignes de réglages.

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| Clés ARB | compilation | `lib/l10n/*.arb` → code généré | `flutter gen-l10n` | à chaque édition d'ARB, dans le **même** commit |
| Locale active | application | `MaterialApp.locale`, résolu par `_resolveLocale` | au démarrage | quand le téléphone change de langue (E12) |
| Instance `AppLocalizations` | application | reconstruite par Flutter | à chaque changement de locale | jamais manuellement |
| Tri et facettes de la bibliothèque | session | `shared_preferences`, valeurs **enum** | au premier lancement | au changement de tri |
| Aucune | — | — | — | — |

**Ce qui n'est délibérément pas de l'état** : la langue choisie. Elle n'est pas
écrite dans `shared_preferences`, pas dans une base, pas dans un paramètre de
système. Elle est **lue** à chaque construction de l'application, ce qui rend le
sélecteur de langue de `settings.md` § 11 impossible à écrire — et c'est
l'argument, pas une coïncidence.

**La seule règle de durée pour les préférences** : une valeur stockée est une
**clé d'enum** (`'lastRead'`, `'recentlyAdded'`, `'titleAz'`, `'unopened'`,
`'site'`), **jamais** une chaîne déjà localisée (`'Dernière lecture'`). Une
chaîne localisée stockée survit au changement de langue comme une chaîne dans une
langue abandonnée, et le libellé affiché devient fou. Le test de § 11 le vérifie
sur chaque clé de tri et de filtre.

## 7. Pièges à éviter

- **⚠️ Ne pas écrire une chaîne visible en dur dans un widget. Le comportement
  correct (B28)** est : `Text(AppLocalizations.of(context).libraryEmptyBody)`.
  Le contrôle 5 de la barrière échoue sur `Text('…')`, `label: '…'`,
  `hintText: '…'`, `tooltip: '…'`. Les jetons de design et les clés de routes
  sont les seules exceptions, et elles ne sont pas de la copie.
- **⚠️ Ne pas éditer un seul des deux ARB. Le comportement correct (B28,
  `16-i18n.md` règle 2)** est : les deux fichiers, dans le **même** commit.
  `gen-l10n` ne rapporte que la clé absente de la **template** ; une clé présente
  seulement en français produit un getter qui rend la chaîne française en
  anglais, ce qui est **invisible** jusqu'à la lecture.
- **⚠️ Ne pas faire le repli vers l'anglais pour une langue inconnue. Le
  comportement correct (B28, `16-i18n.md` règle 5)** est :
  `_resolveLocale` renvoie `Locale('fr')`. Le repli par défaut de `gen-l10n` est
  le fichier modèle, c'est-à-dire `app_en.arb` — un allemand verrait de
  l'anglais, sans aucun signal d'erreur.
- **⚠️ Ne pas écrire une clé de compteur avec seulement `one` / `other`. Le
  comportement correct (B28)** est : `=0` et `=1` explicites, comme
  `chapterCount`. Le français classe 0 dans `one`, donc une clé sans clause `=0`
  affiche « 0 chapitre » au singulier en français et « 0 chapters » en anglais.
- **⚠️ Ne pas traduire les titres de romans ni de chapitres. Le comportement
  correct (`prd.md` § 7.4, B10)** est : ce sont les libellés du site, affichés
  tels quels. `history.md` § 7 le dit dans la couche d'accessibilité : les
  étiquettes sémantiques sont localisées, **les titres de chapitre ne le sont
  jamais**.
- **⚠️ Ne pas mettre de sélecteur de langue. Le comportement correct (B28)** est :
  la ligne `Language` est **en lecture seule**, sans chevron, sans ondulation,
  sans état pressé, avec une ligne d'explication. Un sélecteur serait une seconde
  source de vérité pour une valeur que la plateforme possède déjà.
- **⚠️ Ne pas raccourcir la divulgation E11 en français. Le comportement correct
  (E11)** est : les deux phrases entières, dans les deux langues.
  `onboarding.md` § 4.1 le dit : *« the one place in this app where a compressed
  translation would be a weaker disclosure »*. C'est le seul texte du produit où
  une traduction plus courte est une divulgation plus faible.
- **⚠️ Ne pas commit `flutter gen-l10n` sans les ARB, ni les ARB sans le code
  généré. Le comportement correct (`AGENTS.md`, Définition de Done point 4)** est :
  les trois dans le même commit. `lib/l10n/generated/` est commité et exclu de
  l'analyse ; un ARB édité sans régénérer donne un `flutter analyze` propre et un
  écran qui affiche l'ancienne phrase.
- **⚠️ Ne pas faire correspondre les pluriels à la main. Le comportement correct
  (`16-i18n.md` règle 6)** est : la syntaxe ICU `{count, plural, …}` et
  `gen-l10n` génère la méthode. Écrire « 1 chapitre » ou « %d chapitres » à la
  main produit un anglais correct et un français faux.

> **Question ouverte — `commonRetry` / `commonCancel` et `button.retry` /
> `button.cancel` désignent la même chose, deux fois.** Les ARB existants
> portent `commonRetry` et `commonCancel` (et le test
> `resolves English strings` les vérifie déjà). `settings.md` § 4.1 liste
> `button.retry` et `button.cancel`. `16-i18n.md` règle 3 dit *« Never translate a
> key twice; one concept, one key »*. **L'option réversible la moins chère est
> retenue : ce sont `commonRetry` et `commonCancel` qui servent partout**, et
> `button.retry` / `button.cancel` ne sont **pas** ajoutés — réutiliser une clé
> déjà générée évite de supprimer du code généré et évite de dupliquer une notion.
> **Le déclencheur de clôture** : le propriétaire de `settings.md` confirme que son
> tableau § 4.1 doit être amendé pour pointer vers `commonRetry` / `commonCancel`.
> **Ne pas créer les quatre clés.**

> **Question ouverte — la forme du nommage des clés est contestée entre deux
> documents approuvés.** `16-i18n.md` règle 3 dit *« **Not** dot-namespaced »* ;
> `settings.md` § 4.1 et `onboarding.md` § 4.1 spécifient des clés à point
> (`group.reading`, `step2.disclosure`). **Les deux règles sont compatibles dans les
> faits** : `gen-l10n` accepte un point dans une clé ARB et produit un getter
> `groupReading`, ce qui est exactement la convention que `16-i18n.md` décrit dans
> la même règle (« `gen-l10n` flattens keys into camelCase getters »). **L'option
> réversible la moins chère est retenue : les clés des fichiers d'écran sont reprises
> **telles quelles**, avec leur point**, parce qu'elles sont déjà écrites dans
> dix-huit documents approuvés et que les réécrire en `libraryEmptyTitle` prendrait
> dix-huit décisions. `ArbKey.dartGetter` existe précisément pour que le test
> **vérifie** le nom produit plutôt que de le supposer. **Le déclencheur de clôture**
> : `16-i18n.md` est amendé pour dire « un point est autorisé, `gen-l10n` aplatit ».
> **Ne pas normaliser les clés.**

> **Question ouverte — `navMore` n'existe pas.** `design-system.md` § 3.2 fixe
> cinq destinations, **Library · Updates · History · Browse · More** (ADR-018).
> `app_en.arb` / `app_fr.arb` portent `navLibrary`, `navBrowse`, `navUpdates`,
> `navHistory`, `navDownloads`, `navSettings` — et **aucun `navMore`**. Le
> cinquième onglet n'a donc pas de libellé. **L'option réversible la moins chère
> est retenue : `navMore` est ajouté par cette slice** (`More` / `Plus`), parce
> qu'un onglet sans libellé est un défaut visible et que la valeur est déjà
> décidée par ADR-018 et par le tableau § 3.2. **Le déclencheur de clôture** :
> aucun — la valeur est dans `design-system.md` § 3.2, il n'y a rien à décider.

> **Question ouverte — l'inventaire ne peut pas être « complet » avant que chaque
> slice d'écran n'ait figé sa copie.** B28 exige la complétude, et la complétude
> est une propriété de l'ensemble du produit, pas de cette slice : une chaîne
> écrite par `3-1` dans six mois n'est pas dans l'inventaire de `6-7`.
> **L'option réversible la moins chère est retenue : la barrière de § 3.3 est
> posée maintenant sur les clés existantes, et la liste des clés attendues est un
> fichier `test/l10n/expected_keys.dart` que chaque slice d'écran **ajoute** au
> moment où elle écrit sa copie.** Le déclencheur de clôture : le gate V1, où le
> test doit passer avec l'inventaire complet de dix-huit écrans. **Ne pas inventer
> ici la copie d'un écran qui n'est pas écrit.**
