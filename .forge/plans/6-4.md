# Plan d'implémentation — 6-4

> **Ce plan décrit *comment implémenter* cette slice**, de façon qu'un
> implémentateur n'ait rien à décider et n'ait pas à lire le PRD.
>
> `6-4` est **l'action manuelle « mettre à jour la bibliothèque »**. Ce n'est
> **pas** la notification : celle-ci est `6-10` (ADR-021). Cette slice lit des
> listes de chapitres, ne télécharge rien, et rend compte roman par roman.

## 1. Résumé de la slice

`6-4` exécute **une passe de vérification manuelle de toute la bibliothèque** et
dit au lecteur, roman par roman, ce qu'il a trouvé — et ce qu'il n'a pas pu
regarder. Elle est déclenchée **uniquement** par une action explicite du lecteur
(B36) : ouvrir l'application n'est pas un déclencheur, et il n'y a **aucune
planification** dans aucune version tant que le déclencheur de `prd.md` § 9 n'a
pas-fired (ADR-023).

La propriété qui définit cette slice est **B38** : la vérification **ne télécharge
jamais**. Elle lit des listes de chapitres et n'écrit que trois choses — des lignes
`chapters`, un `novels.last_checked_at`, un `sources.last_error_code`. Elle
n'appelle **jamais** `fetchChapterContent`, ne crée **aucune** ligne
`queue_items`, et ne déclenche **aucun** téléchargement. C'est ce qui rend la
vérification sans dialogue de confirmation possible : elle ne coûte ni DATA ni
stockage.

La seconde propriété est **B39** : **tous** les romans de la bibliothèque sont
visités, aucun n'est sauté, pour aucune raison. Pas de « roman terminé », pas de
« déjà vérifié il y a dix minutes », pas de plafond. La progression est comptée
en romans et n'est jamais plafonnée, parce que c'est la seule chose que le lecteur
peut vérifier par lui-même.

La troisième est **B22** : « vérifié et rien de nouveau » et « impossible de
vérifier » sont **deux états distincts**, jamais deux valeurs du même nombre.
Un roman dont le site est cassé conserve son **compte exact** et porte à côté le
marqueur « could not check ».

Cette slice ne construit **aucun écran**. Elle produit un interactor, un
notifier, et la couture que trois écrans consomment. La notification de premier
plan est `6-10`.

**User stories couvertes** : US-10, US-16
**Règles métier couvertes** : B36, B38, B39
**Edge cases couverts** : E4, E8, E9

```dart
class Novels extends Table {
  TextColumn get id => text()();
  TextColumn get sourceId => text()();
  TextColumn get title => text()();
  BoolColumn get inLibrary => boolean().withDefault(const Constant(false))();
  DateTimeColumn get lastCheckedAt => dateTime().nullable()();   // B49 — null = jamais vérifié
}

class Sources extends Table {
  TextColumn get id => text()();
  BoolColumn get enabled => boolean().withDefault(const Constant(true))();
  DateTimeColumn get lastCheckedAt => dateTime().nullable()();
  TextColumn get lastErrorCode => text().nullable().withDefault(const Constant(''))();
}

class Chapters extends Table {
  TextColumn get id => text()();
  TextColumn get novelId =>
      text().references(Novels, #id, onDelete: KeyAction.cascade)();
  TextColumn get name => text()();                                 // B10 — verbatim
  RealColumn get number => real().withDefault(const Constant(-1))();
  TextColumn get url => text()();
  BoolColumn get isRead => boolean().withDefault(const Constant(false))();
  DateTimeColumn get readAt => dateTime().nullable()();
  DateTimeColumn get downloadedAt => dateTime().nullable()();      // B6 — jamais écrit ici
  IntColumn get ordinal => integer()();                            // B9 — ordre du site
}
```

**Trois colonnes sont écrites, trois ne le sont pas.** `last_checked_at` oui.
`is_read` **jamais** : ouvrir un chapitre est le seul geste qui l'écrit (B13), et
une vérification qui marquerait des chapitres comme lus prendrait le lecteur à
trahir. `downloaded_at` **jamais** : c'est la marque de `2-3`, écrite après le
renommage atomique (ADR-022), et B38 l'interdit explicitement. `read_at` non
plus. Si une ligne de cette slice écrit `is_read`, c'est un bug.

### 2.2 Types et interfaces

```dart
// lib/domain/updates/library_check.dart
import 'package:lumen_tale/core/error/app_exception.dart';
import 'package:lumen_tale/domain/sources/source.dart';

/// Pourquoi la vérification d'un roman a échoué.
///
/// Les six causes ci-dessous sont exactement celles de `architecture.md` § 5.2
/// qu'une **vérification** peut produire. `storageFull` et `parseFailed` sur un
/// fichier local ne sont pas dans cette liste : cette slice ne touche pas au
/// disque de stockage, et elle ne convertit pas de HTML. Un cas qui n'est pas
/// dans l'énumération est un cas qui n'a pas été pensé.
enum CheckFailureKind {
  noConnection,
  rateLimited,
  sourceLayoutChanged,
  sourceUnavailable,
  itemRemovedAtSource,
  parseFailed,
}

/// Le résultat pour **un** roman. Trois états, jamais deux
/// (`architecture.md` § 2.2) : « vérifié » et « impossible » ne doivent pas
/// pouvoir se confondre parce qu'ils sont tous les deux un `int`.
sealed class NovelCheckOutcome {
  const NovelCheckOutcome();
}

/// Le site a été lu. [newChaptersFound] peut légitimement valoir 0 : c'est un
/// résultat, pas une absence.
final class NovelChecked extends NovelCheckOutcome {
  const NovelChecked({
    required this.newChaptersFound,
    required this.siteChapterCount,
    required this.checkedAt,
  });

  final int newChaptersFound;
  final int siteChapterCount;
  final DateTime checkedAt;
}

/// Le site n'a pas pu être lu. [kind] est typé, jamais une `String` libre
/// (B24). [failedSelector] n'est renseigné que pour `sourceLayoutChanged` :
/// c'est le sélecteur qui a échoué, et c'est la seule information qui aide le
/// propriétaire à réparer le site (`18-external-contracts.md`).
final class NovelCheckFailed extends NovelCheckOutcome {
  const NovelCheckFailed({
    required this.kind,
    required this.failedSelector,
    required this.sourceId,
  });

  final CheckFailureKind kind;
  final String? failedSelector;
  final String sourceId;
}

/// Un chapitre que le site publie et que l'app n'a pas encore.
///
/// **Ce n'est pas un corps de chapitre.** Il n'y a ni texte, ni HTML, ni URL
/// absolue : seulement ce qu'il faut pour créer une ligne `chapters`. C'est la
/// forme mécanique de B38.
final class NewChapter {
  const NewChapter({
    required this.url,
    required this.name,
    required this.number,
    required this.ordinal,
  });

  /// Relatif (chemin + requête), jamais une URL complète
  /// (`03-source-system.md` règle 3).
  final String url;

  /// Le libellé du site, tel quel (B10).
  final String name;

  /// `-1` quand le site ne publie pas de numéro lisible ; `0` est un vrai
  /// chapitre et doit rester atteignable.
  final double number;

  /// L'ordre du site (B9). Jamais re-dérivé de [number].
  final int ordinal;
}

/// Progression d'une passe. Comptée **en romans**, jamais plafonnée (B39).
final class LibraryCheckProgress {
  const LibraryCheckProgress({
    required this.total,
    required this.done,
    required this.inFlightNovelId,
  });

  /// Le nombre total de romans de la bibliothèque au moment où la passe a
  /// commencé. Il ne change pas pendant la passe : B39 est une promesse sur
  /// l'instantané, pas sur la base qui bouge pendant qu'on la regarde.
  final int total;

  /// Roman déjà traités, succès ou échec. Les échecs comptent comme traités —
  /// sinon un site cassé ferait tourner le compteur pour toujours.
  final int done;

  final String? inFlightNovelId;

  bool get isComplete => done >= total;
}

/// Le résultat complet d'une passe, persistable et affichable.
final class LibraryCheckResult {
  const LibraryCheckResult({
    required this.startedAt,
    required this.finishedAt,
    required this.perNovel,
    required this.interrupted,
  });

  final DateTime startedAt;
  final DateTime finishedAt;

  /// Un entrée par roman de la bibliothèque. **Sa longueur est le nombre de
  /// romans**, et c'est l'assertion que `6-4` doit faire passer : une passe qui
  /// a sauté un roman est invisible de l'extérieur, donc la liste est la preuve.
  final List<NovelCheckOutcome> perNovel;

  /// `true` si la passe s'est arrêtée avant [LibraryCheckResult.total]. Une passe
  /// interrompue n'est **jamais** rapportée comme une passe réussie.
  final bool interrupted;

  int get checkedCount => perNovel.whereType<NovelChecked>().length;
  int get failedCount => perNovel.whereType<NovelCheckFailed>().length;

  /// Le nombre de chapitres **nouveaux trouvés par cette passe**, pas le total
  /// des non-ouverts. Le total des non-ouverts est local et exact (B48, `6-3`) ;
  /// ce nombre-ci est ce que la passe a **découvert**, et c'est ce que la
  /// notification de `6-10` et la ligne de statut annoncent.
  int get discoveredChapters =>
      perNovel.whereType<NovelChecked>().fold(0, (sum, e) => sum + e.newChaptersFound);
}

/// Échec du run lui-même — pas d'un roman. Un seul cas aujourd'hui : le lecteur
/// a annulé. `13-error-handling.md` règle 7 exige `CancelledException` pour que
/// l'appelant distingue « annulé » de « échoué » et n'affiche pas d'erreur.
final class CheckCancelledException extends AppException {
  const CheckCancelledException()
    : super('the reader cancelled the library check');

  @override
  String toString() => 'CheckCancelledException: the library check was cancelled';
}
```

```dart
// lib/domain/updates/interactors/check_library.dart
import 'package:lumen_tale/domain/updates/library_check.dart';

/// Le cas d'usage de `6-4`. L'implémentation est `data/interactors/check_library.dart`.
abstract interface class CheckLibrary {
  /// Lance **une** passe sur **tous** les romans de la bibliothèque (B39).
  ///
  /// [onProgress] est appelé après chaque roman, jamais avant le premier et
  /// jamais après le dernier : `total` vaut [LibraryCheckProgress.total] dès la
  /// première émission, donc l'écran peut afficher « 0 sur 23 » sans attendre.
  ///
  /// [cancellation] est consulté **avant chaque roman**. C'est la seule porte
  /// d'annulation : une passe annulée s'arrête au roman suivant, jamais au
  /// milieu d'un appel réseau. Une implémentation doit aussi consulter
  /// [cancellation] **après** chaque appel réseau, pour qu'une annulation faite
  /// pendant une requête ne prenne pas un roman de plus.
  Future<LibraryCheckResult> run({
    required void Function(LibraryCheckProgress) onProgress,
    required Future<bool> Function() cancellation,
  });
}
```

```dart
// lib/domain/library/library_repository.dart — le morceau que 6-3 fournit
import 'package:lumen_tale/domain/updates/library_check.dart';

/// Les écritures dont cette slice a besoin. Lues et validées par `6-3` ;
/// **c'est la frontière entre les deux slices** et elle ne bouge pas.
abstract interface class LibraryCheckStore {
  /// Tous les romans `in_library = 1`, dans l'ordre de la bibliothèque.
  /// **Aucun autre prédicat.** C'est B39 : une liste filtrée par « pas vérifié
  /// récemment » ou « non terminé » est exactement le saut que la règle interdit,
  /// et il serait invisible depuis l'interface.
  Future<List<LibraryNovelRef>> listLibraryNovels();

  /// Marque le roman comme vérifié à [at] (B49). **N'efface pas**
  /// `last_error_code` : c'est `recordCheckFailure` qui l'écrit, et le succès
  /// l'écrase aussi — voir § 3.2, branche 6.
  Future<void> recordChecked(String novelId, DateTime at);

  /// Écrit le code d'échec typé (B22 / B24). `sources.last_error_code` reçoit le
  /// même code pour le site, afin que `updates.md` puisse afficher `unavailable`
  /// sans avoir tenté un fetch.
  Future<void> recordCheckFailure(String novelId, CheckFailureKind kind);

  /// Fusionne une liste de chapitres fraîchement lue dans `chapters`.
  ///
  /// **INSERT OR IGNORE sur `chapters.id`** : l'id d'un chapitre dérive de l'id
  /// du roman + son url (B3), donc un chapitre déjà connu ne peut pas dupliquer.
  /// La méthode **ne modifie jamais** `is_read`, `read_at` ni `downloaded_at`.
  /// Renvoie le nombre de lignes réellement ajoutées.
  Future<int> mergeChapterList(String novelId, List<NewChapter> fresh);
}

/// L'identifiant et le site d'un roman de la bibliothèque. Suffisant pour la
/// vérification, et **rien de plus** : cette slice ne lit ni couverture, ni
/// description, ni compte de chapitres.
final class LibraryNovelRef {
  const LibraryNovelRef({
    required this.novelId,
    required this.sourceId,
    required this.title,
    required this.url,
  });

  final String novelId;
  final String sourceId;
  final String title;

  /// Chemin relatif déjà stocké, reconstruit par la source. Jamais une URL
  /// complète reconstruite à la main : c'est la source qui la compose.
  final String url;
}
```

### 2.3 Contrats API

Cette slice appelle **deux** méthodes du contrat source, et **une seule fois
chacune par roman**. Elle n'en appelle aucune autre.

```dart
// lib/domain/sources/source.dart — extrait, tel que 2-1 l'écrira
abstract class Source {
  String get id;                       // MD5 — jamais écrit à la main
  String get name;
  String get baseUrl;
  int get versionId;

  /// La liste complète des chapitres du roman, telle que le site la publie.
  /// **C'est le seul appel que fait `6-4`.**
  Future<BrowseOutcome<List<Chapter>>> getChapterList(Novel novel);

  /// Sert à distinguer E9 (le roman a disparu du site) d'une page vide.
  /// Optionnel : si elle est omise, un `getChapterList` en `sourceLayoutChanged`
  /// sur un roman jamais vu est traité comme `sourceUnavailable`.
  Future<BrowseOutcome<Novel>> getNovelDetails(Novel novel);
}
```

**La méthode que cette slice n'appelle pas, et pourquoi c'est une règle.**
`ParsedHttpSource.fetchChapterContent(chapter)` retourne le HTML brut d'un
chapitre. Elle n'est **jamais** invoquée par `6-4`. Un chemin de code allant de
`getChapterList` à `fetchChapterContent` viole B38 et § 7 le dit en toutes
lettres. `fetchChapterContent` appartient à `2-2`/`2-3`, et le seul producteur de
`queue_items` est `5-1`.

## 3. Algorithmes critiques

### 3.1 La passe (couvre **B39**, **B36**, **B38**)

```
checkLibrary.run(onProgress, cancellation):

  # ── B36 : le SEUL point d'entrée. Aucun appel réseau au démarrage de
  # l'application, à la reprise, au scroll d'une liste, ni à l'ouverture d'un
  # onglet. Ces endroits n'appellent pas run() et il n'existe aucune autre
  # porte d'entrée dans le code.
  novels = store.listLibraryNovels()          # in_library = 1, rien d'autre
  total  = novels.length
  results = []
  emit(LibraryCheckProgress(total, 0, null))  # première émission, avant tout réseau

  for novel in novels:
      if cancellation():                        # porte 1 — entre deux romans
          return LibraryCheckResult(interrupted: true, perNovel: results, …)

      emit(progress(total, results.length, novel.novelId))

      outcome = checkOne(novel)                 # § 3.2 — toutes les branches
      results.add(outcome)
      # ⚠️ AUCUNE ÉCRITURE D'ICI À checkOne() NE PEUT PROVOQUER UN TÉLÉCHARGEMENT.
      # mergeChapterList n'insère que des LIGNES chapters. Une ligne
      # queue_items insérée ici ferait échouer B38 — voir § 7.

  if cancellation():                            # porte 2 — après le dernier
      return LibraryCheckResult(interrupted: true, perNovel: results, …)

  return LibraryCheckResult(interrupted: false, perNovel: results, …)
```

**Toutes les branches de la boucle :**

| Situation | Ce qui se passe | Pourquoi c'est correct |
|---|---|---|
| Bibliothèque vide | `total = 0`, une émission `(0, 0, null)`, résultat vide, `interrupted: false` | B12 rend l'état « rien de gardé » possible ; une passe sur zéro roman n'est pas un échec |
| Passe complète | `results.length == total` | **B39, l'assertion** : `perNovel` a une entrée par roman |
| Annulation avant le roman *k* | `results.length == k-1`, `interrupted: true` | `perNovel` est plus court que `total`, et c'est **visible** |
| Annulation pendant le roman *k* | le roman *k* finit, **puis** la boucle s'arrête | § 3.2, branche 0 : on n'abandonne pas une écriture à moitié |
| Un roman échoue | une entrée `NovelCheckFailed`, la boucle **continue** | B39 : « no novel is skipped **for any reason** » inclut les échecs |
| Tous les romans échouent | `failedCount == total`, `checkedCount == 0`, `interrupted: false` | Une passe qui n'a rien pu lire est **rapportée**, jamais rendue comme « rien de nouveau » |
| `listLibraryNovels` échoue | `DatabaseException` remonte au notifier | Le store est local ; un store illisible est l'`ErrorState` de l'écran, pas un échec de vérification |

### 3.2 Un roman : les huit issues (couvre **B22**, **E4**, **E8**, **E9**)

```
checkOne(novel):
  source = sources.byId(novel.sourceId)      # SourceManager, ADR-013

  # ── garde 0 : source désactivée ou inconnue ──────────────────────────
  if source is null:
      fail(itemRemovedAtSource)               # un roman sans source lisible
                                                  # ne peut pas être vérifié ;
                                                  # ce n'est PAS un roman enlevé
  if not source.enabled:
      fail(sourceUnavailable)
      # ⚠️ NE PAS ÉCRIRE last_checked_at. « On n'a pas regardé » ≠ « on a
      # regardé et il n'y avait rien ». B49 rend cette distinction visible.

  details = await source.getNovelDetails(novel.fromStoredUrl(novel.url))

  # ── branche 1 : E9 — le roman a disparu du site ────────────────────
  if details is BrowseFailed(kind: ItemRemovedAtSource):
      fail(itemRemovedAtSource)
      # last_checked_at EST écrit : on a regardé, on a vu qu'il n'y était plus.
      # B7 : les chapitres téléchargés restent lisibles, intacts, non touchés.

  # ── branche 2 : E4 — la maquette a changé ──────────────────────────
  if details is BrowseFailed(kind: SourceLayoutChanged):
      fail(sourceLayoutChanged, failedSelector: details.failedSelector)
      # ⚠️ JAMAIS "rien de nouveau". E4 est *critical* : la réponse a bien
      # parsé, et n'a simplement rien produit de lisible.

  # ── branche 3 : E8 — la page charge, aucun élément attendu ──────────
  if details is BrowseFailed(kind: ParseFailed):
      fail(parseFailed)
      # MÊME VERDICT, motif différent. E8 est "aucun des éléments attendus
      # n'est là" — c'est une rupture supposée, jamais "aucun résultat".

  # ── branche 4 : réseau / limitation de débit / indisponible ─────────
  if details is BrowseFailed:
      fail(map(details.reason))               # noConnection | rateLimited |
                                               # sourceUnavailable
      # rateLimited porte Retry-After : on n'insiste pas, on rend la main.

  # ── branche 5 : le roman est bien là ────────────────────────────────
  chapters = await source.getChapterList(details.items.single)

  if chapters is BrowseFailed:                 # mêmes quatre verdicts que
      fail(map(chapters.reason))               # ci-dessus, même typage
  if chapters is BrowseEmpty:                  # une source peut déclarer un
      store.recordChecked(novel.novelId, now)  # signal « aucun chapitre ».
      return NovelChecked(0, 0, now)           # B22 : c'est un VRAI zéro, et
                                               # BrowseEmpty n'existe que là où
                                               # le site fournit son signal
  # ⚠️ BrowseEmpty n'est atteignable que si la source déclare le signal. Sur une
  # source sans signal, une liste vide arrive en BrowseFailed(ParseFailed) et
  # devient un échec — jamais un "rien de nouveau".

  added = store.mergeChapterList(novel.novelId, chapters.items.map(toNewChapter))
  store.recordChecked(novel.novelId, now)
  return NovelChecked(newChaptersFound: added, siteChapterCount: …, checkedAt: now)

  # ── branche 6 : succès après un échec précédent ─────────────────────
  # recordChecked efface AUSSI sources.last_error_code pour cette source.
  # ⚠️ NE PAS effacer le code pour les AUTRES sources : un site cassé ne
  # disparaît pas parce qu'une vérification a réussi pour un autre site.

  # ── branche 7 : exception inattendue ────────────────────────────────
  on AppException e:  fail(mapKind(e))
  on other:           fail(parseFailed)        # jamais un `Exception` nue qui
                                               # remonte au notifier (13-error
                                               # règle 1)
```

| Issue du site | `CheckFailureKind` | `last_checked_at` | Écrit `last_error_code` |
|---|---|---|---|
| `NoConnection` | `noConnection` | **non** — on n'a pas regardé | oui |
| `RateLimited` | `rateLimited` | **non** | oui |
| `SourceLayoutChanged` (E4) | `sourceLayoutChanged` | **non** | oui |
| `ParseFailed` / aucun élément attendu (E8) | `parseFailed` | **non** | oui |
| `SourceUnavailable` (statut ≥ 500, hors ligne déclarée) | `sourceUnavailable` | **non** | oui |
| `ItemRemovedAtSource` (E9) | `itemRemovedAtSource` | **oui** | oui |
| Source désactivée | `sourceUnavailable` | **non** | oui |
| Succès, y compris `BrowseEmpty` | — | **oui** | **effacé** |

**La ligne « non » de `last_checked_at` est le cœur de B49.** Écrire
`last_checked_at` sur un échec ferait passer « on a regardé et il n'y avait rien »
pour « on n'a pas pu regarder ». C'est exactement la distinction que `6-3` rend
visible et que `updates.md` rend avec le mot *Could not check*.

### 3.3 L'invariant de B38, écrit comme une propriété vérifiable

```
B38 holds if, for every execution of checkLibrary.run():

  1. no call reaches ParsedHttpSource.fetchChapterContent
  2. no INSERT reaches queue_items                      # 5-1 est le seul producteur
  3. no UPDATE sets chapters.downloaded_at              # ADR-022 — 2-3 seul
  4. no UPDATE sets chapters.is_read or read_at         # B13 — ouvrir seul
  5. no UPDATE sets novels.in_library                   # B11/B12 — le lecteur décide
  6. no DELETE touches any row                          # B32/B33 — rien n'est effacé
  7. the only network calls are source.getNovelDetails and source.getChapterList
```

Ces sept lignes sont les **assertions** du plan de tests (§ 11.3). Elles sont
écrites parce que B38 est une propriété **structurelle** — elle ne peut pas être
prouvée en executant une passe réussie, puisque la passe réussie ne fait rien
d'interdit. C'est l'obligation de vérification que `architecture.md` § 6.6 a
transférée de `6-3 → 5-2` à cette slice, parce qu'elle est celle qui possède les
deux côtés de la revendication.

### 3.4 Progression et rendu (couvre **B39**)

```
onProgress(total, done, inFlightNovelId):
  # updates.md § 5 : « Checking 7 of 23 novels · nothing is downloaded »
  # La ligne dit les DEUX faits de B39 et B38 dans la même phrase.
  status = "Checking $done of $total novels · nothing is downloaded"
  # ⚠️ JAMAIS de pluriel tronqué, JAMAIS de « top 50 », JAMAIS d'ellipse.
  # Le compteur est la seule preuve visible que rien n'a été sauté.
```

Terminal (après une passe complète) : `All 23 novels checked · none skipped.`
Terminal (après une passe interrompue) : `Check stopped at 7 of 23 novels.`
Terminal (passe terminée, certains échoués) : `Checked 19 of 23 novels · 4 could not
be checked.` — **le compte d'échecs n'est jamais replié dans un succès**
(updates.md § 4 *Submit error*).

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| Liste des romans à vérifier | passe | mémoire | `listLibraryNovels()` | jamais — l'instantané de B39 est fixe |
| Progression `done/total` | session | `Notifier`, mémoire | `(0, total, null)` | après chaque roman |
| Résultat par roman | passe | mémoire | `NovelCheckOutcome` | jamais modifié après ajout |
| `last_checked_at` | base | `novels.last_checked_at` | `null` (B49) | `recordChecked`, **succès et E9 seulement** |
| `last_error_code` | base | `novels` / `sources` | `''` | échec → code typé ; succès → effacé |
| Lignes `chapters` | base | `chapters` | ce que `6-3` a déjà | `INSERT OR IGNORE` uniquement |
| Compteur de non-ouverts | base | **dérivé** `COUNT(is_read = 0)` | `6-3` | jamais stocké (B14, B48) |

**Ce qui n'est délibérément pas de l'état** : un total de « chapitres à vérifier ».
Il n'existe nulle part. Le seul compte que la passe produit est
`discoveredChapters`, qui est un **résultat affiché une fois** et n'est stocké dans
aucune colonne. Une colonne `pendingCount` serait une source de vérité libre de
diverger des lignes qu'elle compte — exactement le défaut que B14 interdit pour
le compteur de non-ouverts.

**Invalidation** (`05-state-management.md`) : à la fin de `run()`, appeler
`invalidateLibraryProviders(ref)` — le helper groupé qui rafraîchit la
bibliothèque, les compteurs de `updates` et les horodatages en une fois. Le
compteur de non-ouverts ne change pas (B48 : il est local, et la passe ne touche
pas `is_read`), mais l'horodatage et les marqueurs d'échec, si.

### 6.1 Règles métier (B*)

| ID | Règle (PRD) | Implémentée où | Approche |
|---|---|---|---|

Aucune planification n'existe : ADR-023 a retiré B35 de `prd.md` § 9, donc il n'y a rien à « être disponible malgré » |
| **B38** | **A new-chapter check never starts downloading.** Checking and downloading are separate and never overlap: the check reads chapter lists and nothing else. | **B39** | **A check visits every novel in the library.** No novel is skipped for any reason. | § 3.1 (la boucle et `listLibraryNovels`) ; `LibraryCheckProgress.total` ; le terminal de § 3.4 | `listLibraryNovels()` n'a **aucun** prédicat au-delà de `in_library = 1`. | **B22** | When a site cannot be read the app states that it could not read it, and never presents an empty list as an answer. | `sealed class NovelCheckOutcome` ; § 3.2, branches 1–4 et 7 | Trois états au niveau du type : `NovelChecked`, `NovelCheckFailed`, et `BrowseEmpty` de `failure-discriminator` — qui n'est atteignable que là où la source déclare son propre signal de vide. « Vérifié et vide » et « impossible » ne sont pas deux valeurs du même entier |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| **E4** | Site layout changed between releases — the app can no longer read it | `sourceLayoutChanged`, avec le **sélecteur qui a échoué** dans `failedSelector`. `last_checked_at` n'est **pas** écrit : on ne sait pas. Le roman garde son compte exact et porte le chip *Could not check*. **Jamais** « rien de nouveau », **jamais** une ligne vide | § 3.2, branches 2 et 6 ; `CheckFailureKind.sourceLayoutChanged` |
| **E8** | A site's page loads but contains none of the expected items | `parseFailed`. Même verdict qu'E4, motif différent, **et c'est intentionnel** : E8 est « la page a répondu et n'a rien produit de lisible », ce qui est une rupture supposée, pas un catalogue vide. Une source qui déclare son propre signal de vide fournit `BrowseEmpty`, et c'est le seul chemin vers `NovelChecked(0)` | § 3.2, branches 3 et 5 |
| **E9** | A followed novel disappears from its site | `itemRemovedAtSource`. **Le seul échec qui écrit `last_checked_at`**, parce qu'on a réellement regardé. Les chapitres téléchargés et leurs fichiers ne sont **pas** touchés (B7, C14) : cette slice n'a aucun `DELETE`. Hors connexion, l'app ne dit rien du tout sur le site — c'est `6-3` qui lit l'horodatage | § 3.2, branche 1 ; absence de `DELETE` dans § 3.3, point 6 |
| **E16** | A site publishes a chapter. Expected: the app cannot know about it until a check finds it. Until then the novel shows its existing count and when it was last checked, and **never** implies there is nothing new (B48, B49). Once found, it is counted immediately like any other unopened chapter — the count itself never waited for the check. Every already-stored chapter is unchanged and stays readable (B13, B14) | **Trois temps, trois comportements distincts.** *(a) **Avant** la vérification* : rien à faire ici, et c'est le contrat — cette slice ne s'exécute pas, donc l'application ne peut pas savoir. Ce qui est déjà implémenté est ce qui empêche le mensonge : `last_checked_at` reste à sa valeur antérieure et `unopened_count` reste exact, donc la ligne dit « 12 non ouverts · vérifié il y a 3 jours », et **jamais** « rien de nouveau ». *(b) **Au moment où la vérification le trouve*** : `mergeChapterList` insère la ligne avec `is_read = false` et `downloaded_at = null` — donc elle compte **immédiatement** comme un non-ouvert, exactement comme n'importe quel autre, et son corps n'est **pas** récupéré. `discoveredChapters` l'annonce. *(c) **Après*** : la ligne suivante s'affiche sans qu'aucune seconde passe soit nécessaire, parce que le compte est local. **Le point qui décide de tout** : `mergeChapterList` est un `INSERT OR IGNORE` et ne touche **jamais** une ligne existante — donc un chapitre déjà téléchargé reste marqué, et un chapitre déjà lu reste lu. Une passe ne peut donc pas **déclasser** ce que le lecteur a déjà fait | § 3.2 branche 5 ; § 3.3 points 3 et 4 ; § 11.1 « un chapitre déjà connu n'est pas reclassé » |

## 7. Pièges à éviter

- **⚠️ Ne pas écrire `last_checked_at` sur un échec. Le comportement correct (B49,
  B15)** est : `recordChecked` **uniquement** sur `NovelChecked` et sur
  `ItemRemovedAtSource`. Écrire l'horodatage sur un `noConnection` fait passer
  « on n'a pas pu regarder » pour « on a regardé et il n'y avait rien » — la
  faute exacte que B49 a été écrite pour empêcher.
- **⚠️ Ne pas aplatir « impossible de vérifier » en « zéro nouveau chapitre ». Le
  comportement correct (B22, E4, E8)** est : `NovelCheckFailed`, un `enum` typé,
  et un chip *Could not check* à côté du compte local intact. Le compte reste
  exact : perdre le contact avec un site ne change pas un nombre local.
- **⚠️ Ne pas sauter un roman « parce qu'il a déjà été vérifié » ou « parce qu'il
  est terminé ». Le comportement correct (B39)** est : `listLibraryNovels()` sans
  aucun prédicat au-delà de `in_library = 1`, et l'assertion
  `perNovel.length == total`. B39 a été rewordée le jour où sa règle de saut a été
  supprimée : un état « terminé » n'existe dans aucune règle de ce projet, donc
  le sauter serait sauter un ensemble inconnu.
- **⚠️ Ne pas appeler `fetchChapterContent` depuis une vérification, ni insérer
  dans `queue_items`. Le comportement correct (B38)** est : seuls `getNovelDetails`
  et `getChapterList` sortent de cette slice, et `mergeChapterList` n'écrit que
  des lignes `chapters`. Un chemin de code vers un téléchargement est vérifiable
  par les sept propriétés de § 3.3, pas par une intention.
- **⚠️ Ne pas utiliser `BrowseEmpty` quand la source ne fournit pas de signal
  d'être vide. Le comportement correct (B22)** est : `BrowseEmpty` n'existe que là
  où le site a son propre signal explicite. Partout ailleurs, une liste vide
  arrive en `BrowseFailed(ParseFailed)` et devient `sourceLayoutChanged` /
  `parseFailed` — jamais un « rien de nouveau » qui n'a pas été vérifié.
- **⚠️ Ne pas plafonner le compteur de romans. Le comportement correct (B39)** est :
  `Checking 7 of 23 novels`, jamais `Checking 7 of 50+`, et
  `perNovel.length == total` en fin de passe.
- **⚠️ Ne pas avoir de dialogue de confirmation avant une vérification. Le
  comportement correct (B38, updates.md § 5)** est : aucun dialogue, parce qu'une
  vérification ne coûte ni DATA ni stockage. Tous les téléchargements en ont un —
  l'asymétrie est le point.
- **⚠️ Ne pas marquer `is_read` en « marquant les nouveaux comme vus ». Le
  comportement correct (B13, B14)** est : ouvrir un chapitre est le seul geste qui
  écrit `is_read`. Une passe qui le ferait transformerait le relevé de lecture du
  lecteur, et il n'y a aucune sauvegarde (C8).

> **Question ouverte — aucune slice ne porte l'écran *Updates*.**
> `architecture.md` § 3.1 ne contient aucune slice dont la responsabilité soit de
> construire l'écran *Updates* : `6-3` est le modèle de comptage, `6-4` est
> l'action manuelle, `6-6` est le badge et la recherche. Le fichier
> `design-system.md` § 3.5 déclare la route `/updates`, et `0-5` construit le
> **tableau de routes** mais pas l'écran. Cette slice **ne le construit donc pas**
> et ne l'ajoute pas à son périmètre — inventer un écran ici serait créer une
> deuxième surface d'une route que trois écrans claimants se partagent déjà.
> **Le déclencheur de clôture** : l'écran doit être réclamé par une slice, ou
> `6-4` doit être re-scellée pour le porter. En attendant, l'option réversible la
> moins chère est celle-ci : `6-4` livre la couture, et l'écran est monté par la
> slice qui le réclame en premier. **Ne pas inventer de slice ici.**

> **Question ouverte — `6-4` est ordonnancée avant le contrat source.**
> `state.json` place `6-4` en vague 2 et `2-1` — qui écrit `Source`,
> `SourceManager`, `BrowseOutcome` — en vague 3. `6-4` ne peut pas compiler sans
> eux. L'arête n'est pas déclarée, et ce plan **ne modifie ni `state.json` ni le
> graphe** : il déclare la dépendance en § 8 et l'implémentateur doit soit
> attendre `2-1`, soit traiter `failure-discriminator` comme un préalable de même
> vague. **Le déclencheur de clôture** : `dependency-check --write` doit montrer
> `2-1 → 6-4`. **Ne pasConstruire un registre de sources parallèle** pour
> contourner cela : ce serait un second serveur de sources (ADR-013).
