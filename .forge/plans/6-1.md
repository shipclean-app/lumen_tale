## 1. Résumé de la slice

`6-1` écrit **`RoyalRoadSource`** : le deuxième adaptateur du contrat `Source`, en anglais,
sur `royalroad.com`. C'est la slice qui rend **SC-1** vrai pour deux sites au lieu d'un, et
qui est le seul test réel du contrat : *« the only real test of the source contract: a second
site is where a design that accidentally hard-codes FanMTL reveals itself »*
(`architecture.md` § 3.1).

Trois décisions que cette slice porte :

| Décision | Raison |
|---|---|
| **`supportsSearch => false` tant que `6-11` n'a pas rendu son verdict** | ADR-015 : c'est une **promesse mesurée**, jamais une devinette. Le site publie bien des liens vers `/fictions/search?tagsAdd=…`, et **ce n'est pas** une preuve que la recherche y est utilisable — c'est précisément ce que `6-11` doit trancher. Une valeur `true` non mesurée est le défaut que `03-source-system.md` règle 5a nomme |
| **`data-chapters` du tableau de chapitres est un **témoin d'exhaustivité** | `table#chapters` porte `data-chapters="109"`. Si la page renvoie 40 lignes pour un attribut de 109, la liste est **tronquée** : `BrowseFailed`, pas une liste courte. C'est la forme mécanique de **B9** et d'**E1** sur ce site |
| **`There is nothing here :(` est le signal de résultat vide du site** | `div.fiction-list#result > div.text-center > h3`. C'est exactement ce que B22 exige : le discriminant est **le signal du site**, jamais l'absence de correspondance. Vérifié le 2026-10-02 sur `/fictions/best-rated?page=999999`, qui répond **200** avec zéro ligne et ce texte |

**User stories couvertes** : US-01 (parcourir un site), US-02 (recherche — la
méthode est là, la promesse n'est pas ; ADR-015), US-16 (être prévenu quand un site
ne marche plus)
**Règles métier couvertes** : B1, B2, B3, B5, B22, B23, B29
**Edge cases couverts** : E1, E2, E3, E4, E5, E8, E10, E16, E18, E19, E21

### 2.1 Schémas de validation

**Aucun.** Un `Source` ne possède aucune table : il retourne des **modèles de domaine**
(`Novel`, `Chapter`, `NovelsPage`), que `data/` mappe ensuite vers drift. C'est
`02-architecture.md` §Repository pattern qui l'impose : *« Sources
(`sources/implementations/`) are consumed through the `Source` contract in `domain/sources`,
never directly from a feature »*.

```dart
  /// Le réseau + le parse, **une seule fois**, avec la traduction des
  /// exceptions en `BrowseFailed`.
  ///
  /// ⚠️ `13-error-handling.md` rejette explicitement `Result<T>` et `Either` :
  /// *« We deliberately do not use a `Result<T>` / `Either` return type »*.
  /// Donc le client **lève** une exception typée, cette méthode la **rattrappe
  /// à la frontière** (règle 2) et rend un `BrowseFailed`. Aucun troisième
  /// type de retour n'est inventé, et aucune exception diprimitive ne remonte
  /// au consommateur de la source.
  Future<BrowseOutcome<Document>> _fetchDocument(
    String path, {
    Map<String, String> query = const {},
  }) async {
    try {
      final body = await client.get(path, query: query);
      return BrowseSucceeded(html_parser.parse(body));
    } on RateLimitedException catch (e, st) {
      // `Retry-After` est porté par l'exception ; le rate limiter de
      // `core/network` l'a honoré avant de rendre la main.
      return BrowseFailed(
        reason: const SourceFailure.rateLimited(),
        retriable: true,
      );
    } on NetworkException catch (e, st) {
      // E5 : pas de réseau, timeout, DNS. C'est la **même** cause qu'un site
      // cassé du point de vue de l'écran, et c'est B23 qui empêche la
      // confusion de dmgir aux chapitres stockés.
      return BrowseFailed(
        reason: const SourceFailure.noConnection(),
        retriable: true,
      );
    } on SourceUnavailableException catch (e, st) {
      return BrowseFailed(
        reason: const SourceFailure.sourceUnavailable(),
        retriable: true,
      );
    }
  }

  /// La lecture d'une liste — **une seule** implémentation pour les trois
  /// points d'entrée, parce que les trois partagent le même conteneur
  /// (`div.fiction-list#result`), le même sélecteur de ligne et le même
  /// signal de vide.
  Future<BrowseOutcome<NovelsPage>> _readListing(
    String path,
    int page, {
    Map<String, String> extraQuery = const {},
  }) async {
    // ── 1. Le réseau, déjà filtré en BrowseFailed ─────────────────────────
    final BrowseOutcome<Document> fetched =
        await _fetchDocument(path, query: {'page': '$page', ...extraQuery});
    if (fetched case BrowseFailed()) {
      return BrowseFailed(reason: fetched.reason, retriable: fetched.retriable);
    }
    final document = (fetched as BrowseSucceeded<Document>).items;

    // ── 2. Le discriminant de B22, dans cet ordre ─────────────────────────
    // ⚠️ L'ordre compte. « Y a-t-il des lignes ? » ne peut PAS décider seul :
    // c'est le signal du site qui décide, et une réponse 200 sans lignes SANS
    // signal est une **soupçon de changement de mise en page** (E8).
    final rows = document.querySelectorAll(catalogueRows);
    final emptyHeading = document.querySelector(siteEmptyHeading);

    if (rows.isEmpty && emptyHeading != null) {
      // Genuinement rien, et **le site le dit**. C'est le seul cas
      // BrowseEmpty de cette source.
      return BrowseEmpty(siteSuppliedSignal: emptyHeading.text.trim());
    }
    if (rows.isEmpty) {
      // 200, aucune ligne, aucun signal : **suspect de rupture** (E4, E8).
      return BrowseFailed(
        reason: const SourceFailure.layoutChanged(selector: catalogueRows),
        retriable: false,
      );
    }

    // ── 3. Les mapper ─────────────────────────────────────────────────────
    final novels = <Novel>[];
    for (final row in rows) {
      // Une ligne sans titre est **omise**, pas rendue vide. La raison est
      // journalisée localement (jamais le HTML).
      final title = row.querySelector(novelTitle)?.text.trim();
      if (title == null || title.isEmpty) {
        log('royalroad: a catalogue row had no title — omitted');
        continue;
      }
      novels.add(_novelFromRow(row));
    }

    // ── 4. La pagination ──────────────────────────────────────────────────
    // `hasNextPage` vient du **pied de page du site**, jamais d'une
    // heuristique du type « une page pleine ». `design-system.md` § 4.2 :
    // « L'application n'invente jamais une fin à une liste qu'elle n'a pas atteinte ».
    final hasNextPage = _hasNextPage(document, page);

    return BrowseSucceeded(NovelsPage(novels: novels, hasNextPage: hasNextPage));
  }

  /// Le pied de page est `ul.pagination > li > a[data-page]`, avec un lien
  /// « Next » et un lien « Last ». Présence d'un lien dont `data-page` vaut
  /// `page + 1`.
  static bool _hasNextPage(Document document, int page) =>
      document
          .querySelectorAll("ul.pagination a[data-page='${page + 1}']")
          .isNotEmpty;
```

```dart
  Future<BrowseOutcome<Novel>> getNovelDetails(Novel novel) async {

  /// première étiquette » : on prend celle dont le texte est dans le
  /// vocabulaire. Voir § 7.
  static NovelStatus _mapStatus(Document document) {
    for (final label in document.querySelectorAll(detailStatus)) {
      switch (label.text.trim().toUpperCase()) {
        case 'COMPLETED':
          return NovelStatus.completed;
        case 'ONGOING':
          return NovelStatus.ongoing;
        case 'ON HIATUS':
          return NovelStatus.onHiatus;
        case 'PUBLISHING FINISHED':
          return NovelStatus.publishingFinished;
        case 'CANCELLED':
          return NovelStatus.cancelled;
        default:
          continue; // « Original », et tout statut nouveau : on l'ignore
      }
    }
    return NovelStatus.unknown; // le site ne l'a pas dit — pas « vide »
```

```dart
  // ── La liste de chapitres ──────────────────────────────────────────────
  @override
  Future<BrowseOutcome<List<Chapter>>> getChapterList(Novel novel) async {
    final BrowseOutcome<Document> fetched = await _fetchDocument(novel.url);
    if (fetched case BrowseFailed()) {
      return BrowseFailed(reason: fetched.reason, retriable: fetched.retriable);
    }
    final document = (fetched as BrowseSucceeded<Document>).items;

    final rows = document.querySelectorAll(chapterRows);

    // ── B9 / E1 : le témoin d'exhaustivité ───────────────────────────────
    // `data-chapters="109"` est le nombre que le SITE déclare. Si on en a
    // moins, la liste est tronquée : c'est une **rupture**, pas une liste
    // courte. Un roman de 10 000 chapitres doit arriver entier, et c'est la
    // seule chose qui le rende vérifiable sans compter à la main.
    final declared = int.tryParse(
      document.querySelector(chapterTable)?.attributes['data-chapters'] ?? '',
    );
    if (rows.isEmpty) {
      return BrowseFailed(
        reason: const SourceFailure.layoutChanged(selector: chapterRows),
        retriable: false,
      );
    }
    if (declared != null && rows.length < declared) {
      // ⚠️ La taxonomie de `architecture.md` § 5.2 est **fermée** : sept
      // causes. Une troncature n'en est pas une nouvelle, c'est un
      // `layoutChanged` dont le sélecteur en cause est `data-chapters` — et
      // c'est exact : c'est bien cet attribut qui a été contredit.
      return BrowseFailed(
        reason: const SourceFailure.layoutChanged(selector: 'data-chapters'),
        retriable: false,
      );
    }

    // ── E2 : l'ordre du site,verbatim, doublons compris ──────────────────
    // ⚠️ `ordinal` est l'**index de la ligne**, pas le numéro extrait du
    // titre. B10 : « The app never renumbers, reorders, deduplicates, or hides
    // them ». Deux lignes de même titre restent deux lignes (E10 côté app).
    return BrowseSucceeded([
      for (final (index, row) in rows.indexed)
        _chapterFromRow(row, ordinal: index),
    ]);
  }

  static Chapter _chapterFromRow(Element row, {required int ordinal}) {
    final link = row.querySelector(chapterLink)!;
    final time = row.querySelector(chapterTime);
    return Chapter(
      // Règle 3 : **relatif**, jamais une URL complète. L'hôte change.
      url: link.attributes['href']!,
      name: link.text.trim(),                          // B10 : verbatim
      number: ChapterRecognition.parse(link.text),     // -1 si illisible
      dateUpload: time == null
          ? null
          : DateTime.fromMillisecondsSinceEpoch(
              int.parse(time.attributes['unixtime']!) * 1000,
              isUtc: true,
            ),
      ordinal: ordinal,
    );
  }
```

```dart
    // E18 : un article absent, vide, ou réduit à des marqueurs est un
    // **échec**, jamais un chapitre vide. Le seuil des 100 caractères
    // appartient à `5-3` (`hasRealText`) ; ici on refuse seulement
    // l'article absent, parce que c'est une erreur de sélecteur.
    final body = document.querySelector(chapterBody);
    if (body == null || body.text.trim().isEmpty) {
      return BrowseFailed(
        reason: const SourceFailure.layoutChanged(selector: chapterBody),
        retriable: false,
      );
    }

    // Le retour est du **HTML brut**. La conversion est le travail de `2-2`,
    // jamais celui de la source (`03-source-system.md` règle 11).
    return BrowseSucceeded(body.outerHtml);
  }

  // ── Ce que la source déclare comme mobilier à retirer ───────────────────
  // Règle 11 de `03-source-system.md` : la source **sélectionne** et déclare
  // ce qu'il faut retirer ; elle n'émet pas de Markdown.
  @override
  Set<String> get removableSelectors => const {
        chapterBodyFirstParagraph, // le titre du chapitre répété en tête
        '.adsbygoogle',
        'div.nitropay-ad-placeholder',
        '.fic-buttons',
        'ul.pagination',
      };
```

## 3. Algorithmes critiques

### 3.1 Le discriminant B22, dans l'ordre (couvre **E4**, **E8**, **E19**, **B22**)

```
_readListing(path, page):
  fetched = get(path, query: {page: page})
  # ── branche 1 : échec réseau / statut non-succès ──────────────────────
  if fetched is Failure:
     return BrowseFailed(reason)          # NoConnection, RateLimited,
                                           #   SourceUnavailable, ItemRemoved
                                           # → « could not read », avec retry

  document = parse(fetched.value)
  rows     = querySelectorAll(catalogueRows)
  empty    = querySelector(siteEmptyHeading)

  # ── branche 2 : le SITE dit qu'il n'y a rien ──────────────────────────
  if rows.isEmpty and empty != null:
     return BrowseEmpty(signal: empty.text)   # « There is nothing here :( »
                                             # → « Aucun résultat », RIEN de cassé

  # ── branche 3 : 200, zéro ligne, AUCUN signal ──────────────────────────
  if rows.isEmpty:
     return BrowseFailed(layoutChanged(selector: catalogueRows)) # ⚠️ PAS BrowseEmpty
                                             # → « could not read Royal Road »

  # ── branche 4 : des lignes ────────────────────────────────────────────
  novels = rows.map(_novelFromRow)          # une ligne sans titre est OMISE
  return BrowseSucceeded(NovelsPage(novels, hasNextPage: _hasNextPage(...)))
```

**Les quatre issues, et ce que l'interface en fait :**

| Réponse | Résultat | Écran | Règle |
|---|---|---|---|
| Timeout, pas de réseau | `BrowseFailed(NoConnection)` | `ErrorState` *No connection. Nothing is wrong with Royal Road* + **Check again** + **Open your library** | **E5**, B23 |
| `403` / `429` / `5xx` | `BrowseFailed(RateLimited \| SourceUnavailable)` | idem, avec `Retry-After` honoré | règle 6 de `17-security.md` |
| `200` + 0 ligne + *There is nothing here :(* | **`BrowseEmpty`** | `EmptyState` *No novels in this tag* — **centré, silencieux, sans icône, sans retry** | **B22** |
| `200` + 0 ligne + pas de signal | **`BrowseFailed(SourceLayoutChanged)`** | `ErrorState` *Lumen Tale could not read Royal Road* — **ancré en haut, icône d'erreur, `Check again`, ligne de rapport C12** | **E4**, **E8**, **B22**, SC-6 |

> **⚠️ C'est la branche 3 qui est le cœur de la slice.** Elle est aussi la plus facile à
> écrire de travers : `if (rows.isEmpty) return BrowseSucceeded(NovelsPage(const []))` est
> trois caractères plus court et **est exactement le bug que SC-6 existe pour attraper**. Le
> test qui la vérifie est `test/fixtures/sources/royalroad/broken-layout.html`, produit par
> `0-1`.

**Et c'est aussi la réponse à E19.** Les quatre branches ci-dessus sont le **seul** endroit
qui décide « rien trouvé » contre « site illisible », et `searchNovels` passe par
`_readListing` comme les deux catalogues — donc il n'y a **aucune** seconde formulation de
cette décision. **E19** (*« A search genuinely matches nothing — the search is well-formed and
the site has no match → an explicit "no results" message, visibly distinct from a failure
message »*) est donc rendu par la branche 2, et **la branche 2 exige le signal du site** :
une recherche bien formée qui ne trouve rien donne `BrowseEmpty` **uniquement** si
`There is nothing here :(` est présent. Sans ce texte, c'est la branche 3 qui tranche — un
site qui ne sait pas dire qu'il n'a rien est un site qu'on ne peut pas distinguer d'un site
cassé, et B22 tranche du côté cassé.

### 3.2 La carte d'URL et la conversion de page (couvre **B5**, **B10**)

```
popular : /fictions/best-rated?page=<n>          n ≥ 1, 1-based
latest  : /fictions/latest-updates?page=<n>      n ≥ 1, 1-based
genre   : /fictions/best-rated?genre=<valeur>&page=<n>

# ⚠️ Royal Road est 1-based comme le contrat. FanMTL est 0-based et exige une
# conversion à la frontière (`/list/<tag>/<sort>-<page>.html`). NE PAS appliquer
# la conversion de FanMTL ici : le premier écran du lecteur est la page 1,
# et sur Royal Road c'est bien `?page=1`. Une conversion donnerait `?page=0`,
# que le site traite comme une page 1 — donc ça « marcherait » et l'erreur
# serait invisible. C'est le pire genre de bug.
#
# `page` vient de l'appelant, qui vient du défilement de la liste. Il n'y a
# **aucun** auto-défilement infini et aucune pagination par « charger plus »
# (`15-performance.md` §Lists).
```

**Les trois issues :**

| Situation | Ce qui est demandé | Ce qui est rendu |
|---|---|---|
| Page 1 d'un catalogue | `?page=1` | 20 lignes, `hasNextPage: true` |
| Dernière page | `?page=<dernier>` | `hasNextPage: false`, **aucune** ligne du pied de page |
| Page hors bornes (`999999`) | `?page=999999` | **200**, `BrowseEmpty` avec le signal du site |

### 3.3 Numéro de chapitre : `-1`, jamais `0` (couvre **E2**, **B10**)

```
ChapterRecognition.parse(text)
# `03-source-system.md` règle 9 : regex [0-9]+(\.[0-9]+)?(\.?[a-z]+)?
#   extra / omake / special → 0.99 / 0.98 / 0.97
#   illisible → -1
```

| Titre sur le site | `number` | Rendu |
|---|---|---|
| `1. Good Morning Brother` | `1.0` | `1` |
| `12.5. Side Story` | `12.5` | `12.5` — **pas** arrondi |
| `Extra` | `0.99` | **pas** `0` |
| *(vide)* | `-1` | `—` (tiret cadratin), **jamais** `0` |

**⚠️ Le piège Royal Road est le suivant :** le site préfixe **chaque** chapitre par son
numéro (`1.`, `2.`, `12.`), y compris les annexes. Un extracteur naïf qui prend le premier
nombre du titre obtient `0` pour un chapitre dont le titre commence par un mot, et `0` est un
**vrai numéro de chapitre** dans le modèle. Absent et `0` doivent rester distinguables — c'est
la raison de `-1`, et `app_database_test.dart` a un test là-dessus.

### 3.4 La liste de chapitres, le témoin d'exhaustivité, et la page de continuation (couvre **E1**, **E3**, **B8**, **B9**)

```
getChapterList(novel):
  rows    = querySelectorAll(chapterRows)
  declared= int.parse(table#chapters@data-chapters)   # le nombre du SITE

  # ── branche 1 : aucune ligne ──────────────────────────────────────────
  if rows.isEmpty:
     return BrowseFailed(layoutChanged(selector: chapterRows))
     # ⚠️ JAMAIS BrowseEmpty. Un roman a toujours au moins un chapitre
     # (Royal Road refuse d'en publier un roman sans). Donc 0 ligne est un
     # sélecteur cassé, pas un roman vide. « An empty chapter list » est
     # exactement ce que B22 interdit de montrer.

  # ── branche 2 : moins de lignes que le site n'en déclare ───────────────
  if rows.length < declared:
     return BrowseFailed(layoutChanged(selector: 'data-chapters'))
     # B9 : « shown complete … whatever its length ». Une liste tronquée
     # n'est pas une liste, c'est un mensonge — et `data-chapters` est la
     # seule preuve automatique qu'on ait.

  # ── branche 3 : le nombre correspond ──────────────────────────────────
  return BrowseSucceeded([for each row, ordinal: index])
```

**Pourquoi `ordinal = index` de la ligne et pas le numéro extrait du titre :** B10 — *« The
app never renumbers, reorders, deduplicates, or hides them »*. Un site peut numéroter
`1, 2, 3, 5` (un chapitre retiré) ou `1, 2, Extra, 3`. **L'ordre du site est l'ordre des
lignes**, et `chapters.ordinal` doit le refléter exactement ; `number` est un *affichage*, il
ne réordonne rien (`architecture.md` § 4.2).

#### 3.4.1 Le chapitre qui se poursuit — la chaîne de continuation (couvre **E3**, **B8**)

**E3 : *« Chapter split across several pages — the pages are joined in their original order
into one continuous chapter before reading (B8). »*** Sur ce site, la question n'est pas
« le code est-il écrit » mais « **le site pagine-t-il un chapitre ?** » — et la réponse se
**trouve dans la fixture gelée**, elle ne se devine pas. C'est la même discipline que le
`data-chapters` : un fait du site, lu, consigné.

```
fetchChapterContent(chapter):

  pages = [chapter.url]
 .loop:
      next = lien de CONTINUATION à l'intérieur de `div.chapter-inner.chapter-content`
      # ⚠️ PAS le lien « Next Chapter ». Voir le piège ci-dessous.
      if next == null or next dejaVu: break                  # anti-boucle
      if pages.length >= 30: fail(BrowseFailed)              # un site qui boucle
      pages.add(next)

  fragments = []
  for path in pages:
      fetched = _fetchDocument(path)
      if fetched is BrowseFailed: return fetched              # rien n'est rendu
      art = doc.querySelector(chapterBody)
      if art == null: return BrowseFailed(layoutChanged(chapterBody))
      fragments.add(art.outerHtml)

  return BrowseSucceeded(fragments.join('\n\n'))               # l'ordre du site
```

**Les trois issues, toutes explicites :**

| Issue | Ce que la source rend | Pourquoi |
|---|---|---|
| **Aucun lien de continuation dans l'article** — le cas attendu sur Royal Road, **à vérifier sur la fixture** | `BrowseSucceeded` d'**un seul** fragment | Un chapitre tient sur une page. C'est un **fait constaté**, pas une supposition : il est consigné dans `18-external-contracts.md` avec sa date |
| Une page de continuation existe, article présent | `BrowseSucceeded`, **fragments joints dans l'ordre du site** | E3, B8 : `04-html-to-markdown.md` règle 4 impose que ce soit **la source** qui assemble, avant conversion |
| Une page de continuation est **cassée** | `BrowseFailed(layoutChanged)` pour **tout** le chapitre | Aucun texte partiel rendu, rien de stocké (**B6**) |

**⚠️ LE PIÈGE SPECIFIQUE À CE SITE : « Next Chapter » n'est PAS une continuation.**
Royal Road place en bas de chaque chapitre un lien vers le **chapitre suivant**. Le suivre
produirait un `.md` contenant **deux chapitres**, et le pire : rien ne le signalerait. La
ligne serait `number: 12`, le texte irait jusqu'au chapitre 13, et le lecteur lirait le
13 **deux fois** — une fois à la fin du 12, une fois dans le 13. Le sélecteur de
continuation est donc **restrictif** : un lien de continuation doit être **à l'intérieur de
`div.chapter-inner.chapter-content`** et son `href` doit **correspondre à la même fiction et
au même numéro de chapitre**. Un lien vers un chapitre **suivant** est exclu par
construction, pas par un test « est-ce que ça change l'url ? ».

Le nombre maximal de pages suit `3-2` § 3.3 : **30**. Au-delà, ce n'est pas un chapitre long,
c'est une boucle, et une boucle est un défaut typé — pas un chapitre infini.

### 3.5 Le réseau, et les trois postures non négociables (couvre **B5**, **B23**, **B29**)

| Règle | Ce que cela interdit ici |
|---|---|
| `17-security.md` 5 — UA honnête | Aucun `User-Agent` de navigateur, aucun `WebView`, aucun `cf_clearance` (ADR-014). Le client de `core/network` est injecté et l'UA est `LumenTale/<version> (personal reader)` |
| `17-security.md` 6 — limitation de débit | Un seul client partagé, un délai entre requêtes, `Retry-After` honoré. **Une fiche = une requête**, et le catalogue n'est jamais mis en cache (`browse-catalogue.md` § 8 : une ligne en cache est une promesse qui pourrit) |
| **B5** — rien n'est demandé sans que le lecteur l'ait demandé | La source **ne déclenche aucun fetch**. Elle répond à un appel. `getPopularNovels` n'est jamais appelé au montage d'un écran ; c'est `3-1` qui décide |
| **B29** — rien ne quitte l'appareil | Aucun log ne contient le HTML brut, et `17-security.md` règle 9 interdit le HTML brut dans un `metadata.json`. Les logs portent des ids et des sélecteurs, **jamais** du texte de chapitre |
| **B23** — une panne d'un site n'affecte pas les autres | Cette source ne touche que ses propres lignes et ses propres fichiers. Un `Royal Road` cassé laisse FanMTL, la bibliothèque et tous les chapitres stockés intacts |

**Le plafond de taille.** `17-security.md` règle 3 : *« Cap the size of anything fetched or
persisted »*. Le client de `core/network` porte une limite par réponse ; cette source n'a
rien à ajouter et **ne doit pas** la contourner.

### 3.6 `B5`, `E16`, `E21` — ce que la source **ne** fait pas

| ID | Ce qui serait tentant | Ce qui est correct |
|---|---|---|
| **B5** | Ajouter un `Future.microtask` de préchargement du prochain chapitre | Non. Rien n'est demandé tant que le lecteur n'a pas demandé |
| **E16** | Notifier l'application « un nouveau chapitre existe » | Impossible, et c'est le sujet de `6-3`/`6-4`. Cette source ne voit un nouveau chapitre que le jour où on lui demande la liste |
| **E21** | Écrire `NovelFireSource` « pour plus tard », avec un `enabled: false` | Non. B1 : Novel Fire **n'existe pas** tant que Q-004 n'est pas résolu. `18-external-contracts.md` le consigne comme **absent**, pas comme désactivé |
| **B3** | Dériver l'id d'une fiction de son **titre** | Non. `novels.id` est dérivé de l'**url** + `sourceId`, jamais du titre (B40, E17 : deux romans de même titre restent deux romans) |

## 5. Gestion d'état (state management)

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| `supportsSearch` | **code** | un `bool` dans la classe | `false` | par `6-11`, **et par rien d'autre** |
| `versionId` | **code** | un `int` dans la classe | `1` | à la main, quand une URL casse |
| `id` | **code** | dérivé | à la construction | jamais |
| La réponse HTTP d'une liste | **appel** | mémoire, le temps de l'appel | — | **jamais conservée** |
| Le HTML brut d'un chapitre | **appel** | mémoire jusqu'à la conversion | — | `2-2` le convertit puis le jette |

**Ce qui n'est délibérément pas de l'état :** le catalogue. `browse-catalogue.md` § 8 :
*« no catalogue caching, and no results caching »*. Une ligne de catalogue en cache est une
promesse que l'app ouvrira quelque chose, et elle pourrit sur un roman déplacé ou retiré
(E9). La **seule** chose conservée est l'image de couverture, via `cached_network_image` —
ce que le design system nomme *« the only reason a second visit costs nothing »*.

**Le `Client` est injecté, jamais instancié.** Un `RoyalRoadSource()` qui crée son propre
dio dans son constructeur est une source qui ne peut pas être testée sans réseau — et
`10-testing.md` règle 7 l'interdit : *« No test may reach the public internet »*.

## 6. Traçabilité des règles

### 6.1 Règles métier (B*)

| ID | Règle (PRD, texte intégral) | Implémentée où | Approche |
|---|---|---|---|
| **B1** | *« v1 ships exactly two sites: FanMTL and Royal Road. A third (Novel Fire) is conditional on its terms of service being confirmed. **There is no deadline.** If unconfirmed, it is absent from v1 and v1 does not count it against its own success (E21). »* | `sourceRegistry` § 2.3 | Royal Road est enregistré **dans la v1**. Novel Fire **n'est pas** écrit : pas de classe, pas de ligne, pas d'entrée `enabled: false`. B1 dit *which* sites ship, pas comment masquer un site ; le « désactivé » serait une fonctionnalité |
| **B2** | *« A novel belongs to exactly one site. The app never merges or mixes two sites' novels, even when their titles are identical (E17). »* | § 3.6, et l'id dérivé § 2.2.1 | `sourceId` est dans l'identité du roman (§ 4.1 de l'architecture), donc deux romans de même titre sur deux sites ont deux ids. **Aucun code de cette source ne lit un titre pour retrouver un roman** — tout passe par l'url, relative |
| **B3** | *« A novel's and a chapter's identity are stable across sessions and across restarts of the app, so the library always points back at the same novel and the same chapter. »* | § 2.2.1 (`id` MD5), § 3.2 (url relatives) | `id` dérivé de `name/lang/versionId`, jamais écrit. `versionId` existe **pour** que le bumped garde la bibliothèque pointant sur les mêmes romans. Les urls stockées sont relatives : un changement d'hôte ne casse rien |
| **B5** | *« Nothing is fetched from a site unless the user asked for it. There is no bulk or speculative background fetching of chapter content. »* | § 3.5, § 3.6 | La source ne **déclenche** rien : elle répond à un appel. Aucune méthode ne s'appelle elle-même, aucun préchargement, aucun `Future.microtask`. Le catalogue n'est pas mis en cache, donc rouvrir l'écran refait une requête **que le lecteur a demandée** |
| **B22** | *« When a site cannot be read the app states that it could not read it, and never presents an empty list as an answer. **"Could not read" and "genuinely nothing" are distinguished like this:** the response parsed successfully AND carries the site's own explicit empty-result signal → genuine nothing … A successful response whose expected content elements are simply absent, a parse error, or a non-success status → the site could not be read, reported as a failure with a retry. **The discriminator is the site's own empty-result signal, never the absence of a match.** »* | § 3.1, les **quatre** branches | Le discriminant est `siteEmptyHeading` — *« There is nothing here :( »* — un texte **lu** sur la page, jamais une absence de correspondance. Trois états distincts, jamais deux. C'est la branche 3 qui empêche `BrowseSucceeded([])` |
| **B23** | *« A failure on one site never blocks the other sites, and never makes stored chapters unreadable. If a site becomes unreachable, changes, or is removed from the app entirely, the chapters already downloaded stay readable on the phone, and the other sites carry on working. »* | § 3.5 | Cette source ne lit que ses propres lignes, ne touche qu'à ses propres fichiers, et ne modifie aucun état global. `SourceManager` (`data/sources/`) résout par id : un échec ici ne change rien pour FanMTL ni pour les `.md` déjà écrits |
| **B29** | *« No user data leaves the device: no library, no reading progress, no history, no diagnostics, no analytics, no crash reports, no telemetry of any kind. »* | § 3.5 | Aucun log ne contient le HTML brut ni le texte d'un chapitre (`17-security.md` règle 9). Aucun appel autre que ceux que le lecteur a demandés. Aucune analytique, aucun rapport de crash — **un journal de crash est un appel réseau** (§ 5.3 de l'architecture) |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|

## 7. Pièges à éviter

- **⚠️ Ne pas suivre « Next Chapter » pour assembler les pages d'un chapitre.** Le
  comportement correct (**E3**, **B8**) est : le sélecteur de continuation est
  **restrictif** — un lien **à l'intérieur de** `div.chapter-inner.chapter-content`,
  et son `href` doit viser **la même fiction et le même numéro de chapitre**. Le
  lien « Next Chapter » mène au chapitre suivant ; le suivre produit un `.md`
  contenant deux chapitres, et rien ne le signale — le lecteur lirait le chapitre
  suivant deux fois.
- **⚠️ Ne pas appliquer le seuil des 100 caractères dans la source.** Le
  comportement correct (**E18**, **E22**, **B22**) est : la source refuse un
  **article absent ou vide** — une erreur de sélecteur — et **ne juge jamais la
  longueur**. Le seuil des 100 caractères sur le Markdown **nettoyé** est celui de
  `5-3` ; l'appliquer ici rejetterait un *Extra* légitime dont les balises occupent
  la moitié du HTML.
- **⚠️ Ne pas dédoublonner la liste de chapitres.** Le comportement correct
  (**E10**, **B10**) est : une ligne du site = une ligne rendue, et `ordinal` est
  l'index de la ligne. Deux titres identiques restent deux chapitres ; les fusionner
  serait décider que le site a tort.
- **⚠️ Ne pas écrire `BrowseSucceeded(NovelsPage(novels: []))` quand la page est vide.** Le
  comportement correct (**B22**, **E8**, **SC-6**) est : zéro ligne **et** signal du site →
  `BrowseEmpty` ; zéro ligne **sans** signal → `BrowseFailed(SourceLayoutChanged)`. C'est le
  bug le plus court et le plus destructeur de cette slice, parce qu'il rend `SC-6` faux en
  trois caractères.
- **⚠️ Ne pas utiliser `isEmpty` comme discriminant.** Le comportement correct est : lire
  `siteEmptyHeading` et regarder son **texte**, parce que B22 dit *« The discriminator is the
  site's own empty-result signal, never the absence of a match »*. Un `if (rows.isEmpty)`
  seul est exactement la formulation que B22 refuse.
- **⚠️ Ne pas mettre `false` dans `supportsSearch` « parce que ce n'est pas implémenté ».** Le
  comportement correct (**ADR-015**) est : la valeur est un **verdict mesuré**. Tant que
  `6-11` n'a pas écrit son verdict dans `18-external-contracts.md`, elle reste `false` —
  et elle ne changera que sur cette preuve. Le fait que le site publie `/fictions/search`
  **n'est pas** un verdict.
- **⚠️ Ne pas mettre « All genres » dans la liste des genres.** Le comportement correct est :
  15 genres, et `<option value="">ALL GENRES</option>` est une **pseudo-entrée** exclue.
  C'est le piège que `0-2` a déjà rencontré sur FanMTL et qui s'est manifesté comme un
  « neufième genre » — une étiquette qu'aucun site ne publie.
- **⚠️ Ne pas prendre « la première étiquette » comme statut.** Le comportement correct est :
  les étiquettes de statut **et** celle qui dit `Original` portent le même
  `span.label.bg-blue-hoki`. Il faut filtrer sur le **texte**. Le défaut donne un roman
  `COMPLETED` classé « Original », et `Original` dans l'énumération des statuts n'existe pas.
- **⚠️ Ne pas s'appuyer sur les classes `cn…` des paragraphes.** Le comportement correct est :
  ce sont des jetons **opaques et uniques à l'anti-scraping**, différents à chaque paragraphe
  et changent au prochain déploiement. Tout sélecteur qui les utilise casse à ce moment-là.
- **⚠️ Ne pas garder le premier `<p>` du corps du chapitre.** Le comportement correct
  (`04-html-to-markdown.md` règle 1, `0-4`) est : le premier paragraphe de
  `div.chapter-inner.chapter-content` est le **titre du chapitre répété**. Il est déclaré dans
  `removableSelectors`, sinon le lecteur voit *Chapter 001 / Good Morning Brother* en tête de
  chaque chapitre.
- **⚠️ Ne pas appliquer la conversion de page de FanMTL.** Le comportement correct est :
  Royal Road est **1-based**, comme le contrat. Le segment `-0` de FanMTL est un
  accident d'URL. Une conversion donne `?page=0` que le site traite comme la page 1 — donc
  ça marche et l'erreur est invisible.
- **⚠️ Ne pas déduire `hasNextPage` d'une page pleine.** Le comportement correct est : lire
  `ul.pagination a[data-page='<n+1>']`. Une liste tronquée par le site avec 20 lignes sur
  une page de 100 doit afficher **pas** de pied de page.
- **⚠️ Ne pas accepter une liste de chapitres plus courte que `data-chapters`.** Le
  comportement correct (**B9**, **E1**) est : `BrowseFailed(layoutChanged(selector: 'data-chapters'))`. C'est la
  seule chose qui rende l'exhaustivité vérifiable sans compter à la main.
  **Et** aucune cause `SourceFailure` nouvelle n'est inventée : la taxonomie
  de § 5.2 est fermée, et une troncature **est** un `layoutChanged`.
- **⚠️ Ne pas numéroter les chapitres par le nombre extrait du titre.** Le comportement
  correct est : `ordinal = index` de la ligne. Le site peut numéroter `1, 2, 3, 5` ou
  insérer un `Extra` au milieu ; B10 interdit de réordonner, réordonner nous-mêmes serait
  réordonner deux fois.
- **⚠️ Ne pas convertir `0` en `-1`.** Le comportement correct est l'inverse : `-1` signifie
  « illisible » et `0` est un **vrai** numéro de chapitre (`extra`, `omake`). Les deux
  doivent rester distinguables, et `app_database_test.dart` a un test là-dessus.
- **⚠️ Ne pas écrire `NovelFireSource`.** Le comportement correct (**B1**, **E21**, C10) est :
  pas de classe, pas de ligne de registre, pas de libellé. « Absent », pas « désactivé » —
  `architecture.md` § 3.1 le dit pour la même raison.
- **⚠️ Ne pas journaliser le HTML brut.** Le comportement correct (`17-security.md` règle 9,
  **B44**) est : un sélecteur qui a échoué et un nombre de lignes, **jamais** le document. Le
  HTML brut est transitoire — converti puis jeté.
- **⚠️ Ne pas mettre en cache un catalogue.** Le comportement correct
  (`browse-catalogue.md` § 8) est : rien n'est mis en cache, et la seule chose conservée est
  l'image de couverture. Une ligne en cache est une promesse que l'app ouvrira ce roman, et
  elle pourrit sur un roman déplacé ou retiré (**E9**).
- **⚠️ Ne pas écrire d'URL complète dans `Novel.url` ou `Chapter.url`.** Le comportement
  correct (`03-source-system.md` règle 3) est : relative. `link.attributes['href']` donne
  déjà `/fiction/21220/…`, et c'est ce qu'on stocke.
- **⚠️ Ne pas écrire de `User-Agent` de navigateur, ni de contournement Cloudflare.** Le
  comportement correct (**ADR-014**, `17-security.md` règle 5) est : le client injecté, UA
  honnête. Royal Road ne défie pas le client honnête ; s'il le défiait un jour, la règle
  dit *stop and ask the owner*, pas *contourner*.
