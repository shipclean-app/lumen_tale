# Internationalization (FR + EN)

The app ships **French and English** from day one. French is the primary language.

## Setup

- Flutter `gen-l10n` with ARB files: `lib/l10n/app_en.arb` + `lib/l10n/app_fr.arb` (template is `app_en.arb`).
- `flutter_localizations` wired in `main.dart` (delegates + supported locales `[en, fr]`), locale resolved at runtime.
- `intl` is enabled in `pubspec.yaml` and `l10n.yaml` is present (untranslated-messages tolerated only when the string is identical to the source locale).

## Rules

1. **No hardcoded user-visible strings** in widgets — ever. Every label, button, tooltip, empty-state, error message and aria/semantics label goes through `AppLocalizations`.
2. **Every new string** is added to both ARB files in the same commit. Keep `@@locale` metadata (`@@` keys), `placeholders`, and the plural/`plural` support consistent between the two files.
3. **Keys** are dot-namespaced and describe meaning, not layout: `library.emptyTitle`, `reader.errorBody`, `downloads.cancelAll`. Group by feature, no translation for a key twice.
4. **Dynamic text**: chapter/novel titles are source data — not localized. Format dates/numbers with `intl` `DateFormat`/`NumberFormat` for the active locale.
5. **French locale** is the fallback for unsupported locales if the user's locale is unknown; otherwise the framework's `supportedLocales` resolution applies.
6. Regenerate localizations via `flutter gen-l10n` (or the build) after editing ARB; run `flutter analyze` — analyzer flags missing keys on the code side.
